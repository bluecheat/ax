# 0.5.9 — I5 가 pre-commit hook 을 늘 미등록으로 세던 것

> 실사용 리포에서 `enforced_by: hook:.ax/hooks/pre-commit/<팀>.sh` 를 단 룰이 배선이 멀쩡한데도
> 매 doctor 호출마다 "I5 (settings.json 미등록) 1건" 으로 잡혔어요. 고칠 게 코드였다는 건
> `docs/reference/rule-enforcement.md` 가 이미 말해주고 있었고요 — I5 명세는 처음부터
> "`.claude/settings.json` **또는** `.git/hooks/pre-commit` 에 등록" 인데, 구현이 앞의 절반만 봤어요.

## 무엇이 바뀌었나

- `check-rule-enforcement.sh` 의 I5-b 판정이 `hook_wired()` 를 거쳐요. `.ax/hooks/pre-commit/*.sh` 는
  settings.json 에 **개별 등록되지 않는** 게 정상이에요 — 디스패처 둘이 디렉토리째 glob 하거든요.
  settings.json 에 PreToolUse 로 등록된 `pre-bash/grep-on-commit.sh` 가 에이전트 커밋을,
  `install-git-hooks.sh` 가 깐 `.git/hooks/pre-commit` chain wrapper 가 사람 터미널 커밋을 잡아요.
  basename 리터럴로 찾으니 어느 쪽으로 배선하든 항상 미등록이었어요.
- 오탐만 지우고 끝내지 않았어요. 디스패처가 **둘 다 없으면** 여전히 위반으로 잡아요.
  I5 의 값어치는 "선언한 hook 이 실제로 돈다" 를 보장하는 데 있으니, 조용히 통과시키면
  룰이 집행되지 않는 상태를 검사기가 정상이라고 보고하게 돼요. `pre-commit/` 밖 hook 은
  종전대로 settings.json 등록을 요구해요.
- `#goax-pre-commit-chain` 마커를 `GOAX_CHAIN_MARKER` 상수로 묶었어요. I6 트리거 판정과
  I5 배선 판정이 같은 것을 봐야 하는데 리터럴이 두 벌이면 한쪽만 조용히 틀어져요.

## 왜 한 건만 터졌나

선언된 게 그 룰 하나였을 뿐, 잠복 범위는 `pre-commit/` 전체예요. 출고 `AGENTS.md` 템플릿이
`enforced_by: hook:.ax/hooks/pre-commit/<name>.sh` 형식을 권장하니, 팀이 `check-mistake-secrets` ·
`critical-rule-grep` · `spec-completion-gate` 중 하나라도 룰에 선언하는 순간 같은 오탐이 떴어요.

## 검증

- smoke 에 I5 배선 4건 추가 — 디스패처 없음(잡힘) · grep-on-commit 등록(통과) ·
  git wrapper 만(통과) · `pre-commit/` 밖(잡힘). 패치 전 코드로 돌리면 가운데 둘이 실패하고
  가드 둘은 통과해요 (회귀를 실제로 잡는지 양방향 확인).
- 실사용 리포(모노레포 안 Kotlin 프로젝트, 룰 7개): 패치 전 I5 1건 → 패치 후 0건,
  I1·I2·I6 과 rule_count 는 그대로.
