## 1) 보안 경화 — regex / sed 입력 escape

### 1a) `triage-search.sh` — `--keywords` regex 메타문자 escape

`triage-search.sh:65` 가 `--keywords` 값을 alternation 패턴으로 만들 때 메타문자를 그대로 `grep -iE` 에 흘려보냈어요. `KEYWORDS` 는 LLM 추출이라 일반적으로 단어지만, `.` `*` `(` 같은 메타가 들어오면 의도치 않은 매칭이나 catastrophic backtracking 가능. 방어적 코딩으로 토큰 단위 escape 후 join. dry-run JSON 출력의 ALT 값도 backslash 가 들어가게 됐으므로 JSON-safe 생성 (`jq --arg` / fallback escape) 으로 동시 fix.

**Before:**
```bash
ALT=$(printf '%s' "$KEYWORDS" | tr -s ' ' '|' | sed 's/^|//; s/|$//')
```

**After:**
```bash
# 각 토큰의 regex 메타문자 escape 후 | 로 join
ALT=""
read -ra _GOAX_KW_ARR <<< "$KEYWORDS"
for _kw in "${_GOAX_KW_ARR[@]}"; do
    [ -z "$_kw" ] && continue
    _esc=$(printf '%s' "$_kw" | sed -E 's/[][\.*+?(){}|^$\\]/\\&/g')
    if [ -z "$ALT" ]; then ALT="$_esc"; else ALT="$ALT|$_esc"; fi
done
```

### 1b) `init-mistake-file.sh` — sed delimiter 사전 escape

`init-mistake-file.sh:165` 의 frontmatter 치환은 `sed -e "s|...|$VAR|g"` 패턴인데 delimiter `|` 와 replacement 메타 (`\`, `&`) 가 변수에 들어오면 sed 명령이 깨졌어요. 특히 `CONTEXT_LINK` 가 URL 쿼리 파라미터로 `|` 를 포함할 가능성. 모든 치환 변수를 사전 escape.

**Before:**
```bash
sed -e "s|{{CONTEXT_LINK}}|$CONTEXT_LINK_OUT|g" ...
```

**After:**
```bash
_sed_escape() { printf '%s' "$1" | sed 's/[\&|]/\\&/g'; }
CONTEXT_LINK_E=$(_sed_escape "$CONTEXT_LINK_OUT")
# ... 다른 변수도 동일
sed -e "s|{{CONTEXT_LINK}}|$CONTEXT_LINK_E|g" ...
```

## 2) 신규 hook — mistake 본문 시크릿 재검증

`init-mistake-file.sh` 의 `redact_secrets()` 는 `--one-line` 에만 적용됨. 본문 5섹션 (어디서·왜 발생·어떻게 막을 수 있나·영향·audit 액션) 은 LLM 이 Edit 으로 채우므로 AWS AKIA·GitHub ghp_·Slack xox·Stripe sk_live·JWT·PEM·key=value≥12자 같은 패턴이 그대로 들어갈 수 있는 gap 이 있었어요.

신규: `.ax/hooks/pre-commit/check-mistake-secrets.sh`

- staged `.ax/mistakes/*.md` (subdirectory 제외) 본문을 `redact_secrets()` 통과시켜 원본과 다르면 시크릿 추정으로 판정
- `mode=fail` → exit 2 (차단), `mode=warning` → stderr 경고 후 exit 0
- `grep-on-commit.sh` 가 `pre-commit/*.sh` 를 자동 chain 하므로 별도 등록 불필요

## 3) `common.sh:find_project_root()` — `GOAX_PROJECT_DIR` 최우선 fallback

결정론 스크립트가 Claude Code 외 환경 (직접 호출, CI, 다른 AI CLI 의 어댑터, OpenCode) 에서도 동작하도록 fallback chain 1단계 추가.

**Fallback 순서:**
1. `$GOAX_PROJECT_DIR` — CLI-agnostic override (신규)
2. `$CLAUDE_PROJECT_DIR` — Claude Code 자동 주입 (기존)
3. cwd ancestor 탐색 — `.ax/` 가진 첫 조상 (기존)

기존 Claude Code 동작은 그대로. 1단계 추가만으로 `GOAX_PROJECT_DIR=/path bash .ax/scripts/bash/triage-search.sh ...` 형태로 standalone 호출 가능.

## 4) L3 정의 일반화 — commerce 편향 → 비가역 손실 영역

`docs/reference/triage-matrix.md:19` 의 L3 정의가 "결제 / 정산 / 금액 흐름" 으로 commerce 편향이었어요. healthcare PHI·EHR, safety·제어, 회계·장부, 인증·자격증명 같은 비-commerce L3 도메인이 매트릭스에서 떠다녔던 문제. 추상화 + 예시 확장.

**Before:**
```
| L3 | 결제 / 정산 / 금액 흐름 | + 사람 architect 게이트 (강제) |
```

**After:**
```
| L3 | 비가역 손실 가능 영역 — 결제·정산, 의료 PHI·EHR, 안전·제어, 회계·장부 무결성, 인증·자격증명 등 | + 사람 architect 게이트 (강제) |
```

`.ax/config.yml` 의 `domain_risk` 예시도 다양화 — `billing` `phi-access` `safety-control` `ledger` `auth-credential` 을 주석으로 추가 (활성화는 사용자가 자기 프로젝트에 맞게).

## 5) `commands/goax-*.md` 13개 thin wrapper 폐기

기존 14개 commands 중 13개는 단순히 `Skill goax:<name>` 한 줄을 호출하는 thin wrapper 였어요. skill 의 `description:` frontmatter 가 자연어 키워드를 autoroute 하므로 동일 진입점이 이미 존재. wrapper 가 추가로 제공하던 가치는 "slash 키 입력으로 정확한 호출" 뿐인데, 이건 autorouting + claude 의 명시적 `Skill` 호출로 대체 가능.

**폐기 목록:** `goax-up`, `goax-onboarding`, `goax-doctor`, `goax-audit`, `goax-rules`, `goax-hud`, `goax-spirit`, `goax-triage`, `goax-adr`, `goax-spec`, `goax-spec-validate`, `goax-spec-tasks`, `goax-spec-implement` (13개).

**유지:** `commands/goax.md` — `/goax` 인덱스 1개만 discoverability 진입점으로. 본문도 옛 `/spec-plan` (0.1.16 retired) 참조 제거 + 자연어 트리거 primary 구조로 재작성.

`tests/smoke.sh §2.5` 도 14개 검증 loop → 단일 인덱스 + 폐기 잔재 0 확인으로 축소.

### Breaking change — 기존 `/goax-*` 사용자 마이그레이션

`/goax-spec`, `/goax-doctor` 같이 slash 키 입력으로 호출하던 사용자는 자연어 트리거로 전환 필요:
