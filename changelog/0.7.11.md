# 0.7.11 — 새 워크트리에서 바로 이어져요 · zsh 에서 JSON 이 안 깨져요 · 리뷰어가 부모 모델을 그대로 쓰지 않아요

## 무엇이 좋아졌나 — 누구에게 체감되나

> git worktree 를 자주 새로 뜨는 사람(Orca·Conductor 같은 워크트리 기반 도구), macOS 기본 셸(zsh)에서 goax 를 쓰는 사람,
> 상위 모델 세션에서 합의 리뷰·레인을 돌리는 사람에게 체감돼요. 세 가지 모두 실사용 프로젝트의 워크트리 세 곳에서 같은 날 겪었어요.

- **새 워크트리에서 `/up` 없이 바로 작업이 이어져요.** `.ax/current-task.json` · `.ax/state.json` 은 체크아웃마다 따로
  있는 런타임 상태라 gitignore 대상이에요. 그래서 워크트리를 새로 뜨면 없었고, triage 가 작업을 기록하려 하면
  "`/up` 으로 설치를 마쳐요" 로 거부됐어요. 이제 처음 쓰는 스크립트가 설치본에 같이 들어 있는 템플릿으로 만들고
  이어가요. `/up` 이 만드는 것과 같은 원본이라 내용도 같아요. 템플릿까지 없는 옛 설치본일 때만 `/up` 을 안내해요.
- **`spec-review.sh --snapshot` 결과를 zsh 에서 받아도 jq 가 깨지지 않아요.** 응답의 `header` 문자열에 든 `\n` 을
  zsh `echo` 가 진짜 줄바꿈으로 바꿔 `jq: parse error … at line 2, column 18` 이 났어요. `header` 를 줄 배열로 바꿨고,
  모델이 따라 쓰는 SKILL.md 예시 92곳의 `echo "$X" | jq` 를 `printf '%s\n' "$X" | jq` 로 바꿨어요.
- **합의 리뷰·레인 에이전트가 기본 모델을 가져요 (#44 일부).** 에이전트 정의에 `model:` 이 없어 부모 세션 모델을
  상속했어요 — 상위 모델 세션이면 리뷰 라운드마다 리뷰어 둘이 전부 그 모델로 돌았어요. architect 는 `opus`,
  evaluator · lane-scout · lane-worker · rules-auditor 는 `sonnet`, screen-designer 는 렌더 결과를 판단하는 일이라
  `inherit` 예요. 프로젝트별로 덮어쓰는 `config.yml` 설정은 다음 패치에서 와요.

## 바뀐 것

- `common.sh` `goax_runtime_template` · `goax_runtime_seed` — 런타임 상태 파일이 없으면 설치본 템플릿으로 만들어요.
  `ln` 으로 붙여 다른 세션이 먼저 만든 파일은 덮지 않아요
- `update-task.sh` · `status-note.sh` · `tier-from-state.sh --reset` — 락 안에서 seed 하고 이어가요. `--dry-run` 은 만들지
  않고 템플릿 내용으로 따져요
- `update-state.sh` — 같은 헬퍼를 써요. 예전 폴백은 설치되지 않는 템플릿 경로를 봐서 실사용에선 돌지 않았어요
- `MANIFEST` — `.ax/current-task.json.template` · `.ax/hud/state.json.template` 을 설치본에 복사해요
- `spec-review.sh --snapshot` — `result.header` 가 줄 배열이에요 (`["verdict: …", "sha: …"]`)
- skills · references — `echo "$X" | jq` → `printf '%s\n' "$X" | jq`
- `agents/*.md` — frontmatter `model:`
- `docs/state-ownership.md` · `scripts/bash/README.md` — 런타임 상태 파일의 생성 규칙
