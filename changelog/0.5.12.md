# 0.5.12 — 상태 파일을 쓰는 SKILL.md 인라인 jq 가 무락이던 것 (`update-task.sh` · `update-state.sh --skill`)

> 0.5.11 이 인계 노트를 `current-task.json` 의 `handoff` 로 옮기면서 남긴 비용 (1) — 같은 파일을
> `status-note.sh` 는 락을 잡고 쓰는데, phase 를 바꾸는 쪽(`triage` · `spec` · `spec-validate` ·
> `spec-tasks` · `spec-implement` 의 SKILL.md 인라인 jq 5곳 8군데)은 무락이었어요. 두 세션이 같은
> 리포를 쓰면 `handoff` 항목이 lost-update 로 사라지는 창이 그대로 남아 있었어요.
> 리뷰에서 같은 결함이 `state.json` 에도 있는 게 드러났어요 — `update-state.sh` 와 `tasks-gate.sh`(task_seal) 는
> 락을 잡는데 skill 마무리의 `last_skill`·`skill_calls` 인라인 jq 12곳은 무락이라 봉인값이 사라질 수 있었어요.

## 무엇이 바뀌었나

- **`update-task.sh`** (신규, 출고 스크립트 37번째) — `current-task.json` 의 task 필드를 락 안에서 in-place 갱신해요.
  `--phase <p>` · `--set task_id|description|size|risk|domain|spec_id|spec_dir|spec_tier=<v>` · `--blocked-by '<json 배열>'` ·
  `--merge-intent '<json 객체>'` · `--start`(started_at) · `--json` · `--dry-run`. `updated_at` 은 매번 찍어요.
  enum(phase · size · risk · spec_tier) 은 `case` 로 검증하고 하나라도 틀리면 아무것도 안 써요 (`[a-z]` 범위 아님 — `Medium`·`l1` 못 지나가요).
  락 문자열은 `status-note.sh` · `tier-from-state.sh --reset` 과 바이트 동일.
- SKILL.md 인라인 jq 8군데가 전부 `update-task.sh` 호출로 바뀌었어요 — `triage`(`--start --phase triaged --set …×5 --merge-intent` · 역면접 `--merge-intent`),
  `spec`(`--phase spec --set spec_id·spec_dir·spec_tier`), `spec-validate`(`--phase spec_checked --blocked-by '[]'` · `--phase spec_blocked --blocked-by "$BLOCKED"`),
  `spec-tasks`(`--phase tasks`), `spec-implement`(`--phase implementing` · `--phase review`).
- **`update-state.sh --skill <name> [--last-mistake <file>]`** — `last_skill`·`skill_calls+=1`·`last_mistake_file` 을 derived 값과 **같은 락·같은 jq 쓰기**
  안에서 찍어요. SKILL.md 12곳(`lane` · `mistake` · `spec` · `spec-validate` · `triage` · `doctor` · `audit` · `zero` · `up` · `spec-tasks` ·
  `spec-implement` · `onboarding`)의 `jq '.last_skill = …' state.json > tmp && mv` 가 전부 이 한 줄이 됐어요 — `update-state.sh` 를 먼저 부르고
  메타만 따로 쓰던 곳은 호출 두 번이 한 번으로 줄어요. 옵션 여러 개를 받게 되면서 `--help` 도 `goax_help` 로.
- **`tier-from-state.sh --reset`** — `.ax/current-task.json.template` 복사 fallback 을 뺐어요 (설치본엔 그 파일이 없어요 — MANIFEST `->` 는 템플릿을 옮기지 않아요).
  파일이 없으면 exit 1 로 거절하고 만들지 않아요 (최소 파일은 `/up` 의 seed 를 영영 막아요). jq 가 없으면 exit 2. 예전엔 둘 다 조용히 `ok` 였어요.
- **`goax_help`** (common.sh) — 출고 스크립트 32개의 `--help` 가 `sed -n '2,NNp'` 로 줄 번호를 손으로 들고 있었고, 실측 19개가 어긋나 있었어요
  (헤더가 자라면 `Exit:` 계약 줄이 잘리고, 줄면 `set -euo pipefail` 까지 찍혔어요). 헤더 주석 블록을 그대로 찍는 헬퍼 하나로 통일하고
  줄 번호 방식은 smoke 가 막아요.
- smoke 계약 `writer_contract` — 상태 파일 둘 다: skills·agents 에서 **어떤 쓰기도** 금지(리다이렉트 · `.tmp` · `mv`), 출고 스크립트 writer 는
  `current-task.json` 은 `update-task` · `status-note` · `tier-from-state`, `state.json` 은 `update-state` · `tasks-gate` 만 —
  **경로를 변수에 담아 쓰는 것**(`F=…/state.json; jq … > "$F.tmp"`)도 잡아요 (실제 writer 가 다 그렇게 써서 직접 경로만 보면 허용 목록이 한 번도 안 걸려요).
  `update-task.sh` 호출 엣지 8곳 · `update-state.sh --skill` 12곳을 이름으로 고정.
- `update-task.sh` 인자 검증 — `--phase`·`--set`·`--blocked-by`·`--merge-intent` 의 값이 비었거나 다음 토큰이 옵션이면 exit 1 (예전 초안은
  빈 값을 "안 준 것" 으로 접어 `updated_at` 만 조용히 쓰고 ok — `spec-validate` 가 `BLOCKED` 를 비워 보내면 phase 만 `spec_blocked` 로 넘어갔어요).
  옵션 토큰은 값으로 삼키지 않아 `--set --json` 도 봉투로 답해요. `--phase idle` 은 거절 (task 필드까지 비우는 건 `reset-task.sh`).
  `--merge-intent '{}'` 는 `changed` 에 `intent_notes` 를 안 올려요.

## 행동 변화

- `reset-task.sh` 는 `current-task.json` 이 없으면 exit 1 (`/up` 먼저). 호출부(`spec-implement` §8.2)는 이미 `|| true` 예요.
- `triage` §3.5 의 `NOW=` 변수가 사라졌어요 — `started_at`·`updated_at` 은 스크립트가 찍어요.
