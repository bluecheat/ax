# 0.7.12 — 에이전트 모델을 config 로 정해요 · 모든 --json 이 한 줄이에요 · 테스트가 실제 설치본과 zsh 를 봐요

## 무엇이 좋아졌나 — 누구에게 체감되나

> 합의 리뷰·레인을 자주 돌리는 팀, 모델이 스크립트 출력을 읽다 가끔 깨지는 걸 본 사람, goax 에 기여하는 사람에게 체감돼요.

- **에이전트 모델을 프로젝트에서 정해요 (#44).** `.ax/config.yml` 의 `agent_models` 에 `evaluator: haiku` 처럼 적으면
  skill 이 그 에이전트를 띄울 때 그 모델로 띄워요. 적지 않은 에이전트는 정의의 기본값(architect `opus`, 나머지 `sonnet`,
  screen-designer 는 부모 모델)을 그대로 써요. 값은 `opus` · `sonnet` · `haiku` · `fable` 이에요. 오타 난 이름, 모를 값
  (`inherit` 포함 — Agent 도구엔 "부모 모델" 값이 없어요), 한 줄 `{…}` 형식은 경고하고 기본값으로 띄워요 — 설정이
  조용히 안 먹히지 않아요.
- **어떤 스크립트든 `--json` 이면 stdout 은 JSON 한 줄이에요.** `update-state.sh --json` 은 여러 줄짜리 state.json 을
  그대로 찍었고, `--dry-run` 을 주면 아무것도 안 찍고 끝났어요. 10개 스크립트는 `--dry-run` 을 모르는 옵션으로 거부했고,
  `--json` 앞의 인자에서 오류가 나면 어느 스크립트든 오류를 stderr 로만 냈어요.
  이제 전부 같은 envelope 한 줄이고, 쓰는 스크립트(`reset-task` · `tier-from-state --reset` · `promote-mistake --apply/--archive`
  · `update-state`)의 `--dry-run` 은 무엇을 바꿀지만 보여줘요.
- **기여자 — smoke 가 약 3분의 1 시간에 끝나요(188초 → 약 1분).** 검사를 조각 19개로 나눠 병렬로 돌려요.
  `bash tests/smoke.sh locks` 처럼 조각 하나만 돌릴 수도 있어요. 진입점은 그대로 `bash tests/smoke.sh` 예요.

## 바뀐 것

- `agent-model.sh` (신규) — `agent_models` 를 읽어 에이전트별 `model` 을 내요 (null 이면 넘기지 않음). `config.yml`
  템플릿에 `agent_models` 블록(주석 예시)을 넣었고, 에이전트를 띄우는 `spec-validate` · `spec-implement`(evaluator ·
  rules-auditor · 레인) · `screen` 이 띄우기 전에 이 스크립트를 불러요
- `update-state.sh` — `--json` 은 `{"status":"ok","result":{"state":{…},"written":false}}` 한 줄. 파일이 없어도 템플릿으로
  계산만 하고 만들지 않아요. `--dry-run` 을 받아요 (`--dry` 와 같아요). 잘못된 옵션도 `--json` 이면 envelope 으로
- `tier-from-state.sh --reset --dry-run` · `reset-task.sh --dry-run` — 끝낼 작업과 지울 파일만 알려줘요
- `promote-mistake.sh --dry-run` — `--apply` 가 표시할 mistake, `--archive` 가 옮길 파일만 알려줘요
- `common.sh` — 인자에 `--json` 이 있으면 파서가 거기 닿기 전의 오류도 `goax_error` 가 envelope 으로 내요
- `check-*` 5종 · `slug-from-text.sh` — `--dry-run` 을 받아요 (읽기 전용이라 그대로 실행). `zero-probe.sh --dry-run` 은
  프로브를 돌리지 않고 목록만(`--list`)
- `scripts/bash/README.md` — `--json` 은 오류여도 envelope 한 줄, 라벨엔 줄바꿈 없음 (`zero-verify.sh` 의 `evidence` 만
  보고에 붙이는 내용이라 예외)
- `tests/smoke.sh` — 조각 `tests/smoke/NN-*.sh` 를 병렬로 돌리는 진입점이 됐어요. 조각이 끝 표식 전에 죽거나 시간 상한
  (`GOAX_SMOKE_PART_TIMEOUT`, 기본 600초)을 넘기면 실패로 세요
- `tests/lib/harness.sh` (신규) — 출력·실패 집계와 fixture: `fx_install`(provision.sh 실제 설치본) ·
  `fx_fresh_worktree`(`git worktree add` 로 뜬 진짜 새 워크트리) · `fx_tree_sum` · `fx_timeout`
- `tests/lib/zsh-traps.awk` (신규) — zsh 에서 뜻이 바뀌는 모양 검출
- CI — ubuntu 러너에 zsh 를 깔아요

## 검증

- §67 (신규) — 손으로 고른 `.ax/` fixture 는 115곳을 상한으로 막아요(늘면 실패, 줄면 상한을 내리라고 실패). `fx_install` ·
  `fx_fresh_worktree` 자체 점검. §12 update-state 와 §66 새 워크트리 테스트를 실제 설치본으로 옮겼어요 — §12 는 손 fixture 가
  룰을 `CLAUDE.md` 에 넣어 셌는데, 설치본의 룰 파일은 `AGENTS.md` 라 설치본에선 그 파일을 읽지도 않았어요
- §68 (신규) — 설치본의 스크립트 46개를 `--json --dry-run` 으로, 또 모르는 옵션을 앞에 붙여 한 번 더 돌려 한 줄 · envelope ·
  라벨 줄바꿈 0 · 설치본 파일 불변(gitignore 대상 포함). 쓰는 스크립트 11종은 실제 인자를 줘서 진행 중 작업이 있는
  설치본에서 `--dry-run` — ok 이고 파일 불변. 0.7.11 코드에선 `update-state.sh` 가 0줄, 10개가 `--dry-run` 거부였어요
- §69 (신규) — skills · agents · commands · docs 의 bash 블록 121개(들여쓴 펜스 포함)를 `zsh -n` 으로, `==`/`===` 로 시작하는 단어와
  `echo "$X" | jq` 를 검출기로 봐요 (zsh 에서 `[ "$a" == b ]` 는 `= not found`)
- §70 (신규) — `agent-model.sh` 의 에이전트 목록 = `agents/*.md`, 갓 설치는 전부 null, 값 · `inherit` · 모를 값 · 두 단어 값 ·
  오타 이름 · 한 줄 `{…}` 형식 해석, 에이전트를 띄우는 skill 문서가 모두 이 스크립트를 거침
- 분할 전후 통과 검사 수 비교 — 기존 853개가 분할 뒤에도 그대로 통과해요. macOS bash 3.2 로 연속 통과
- 새 조각(§67–§70)을 새 컨텍스트 리뷰어가 따로 봤어요 — `inherit` 이 조용히 안 먹히던 것, 인자 없는 dry-run 일괄 검사가
  쓰기 경로를 안 보던 것, 두 단어 모델 값, 한 줄 `{…}` 형식, 들여쓴 펜스 누락, 조각 시간 상한을 반영했어요
