# 0.1.5 — hook `set -e` 일관 제거 + 신규 hook 가드 #5 #6

> 동작 변경 없는 hardening + 가이드 보강.

## 1) `set -e` 일관 제거 (모든 plugin shipped hook)

이전엔 chain orchestrator (`grep-on-commit.sh`) 만 `set -uo pipefail` 였고 개별 hook 들은 `set -euo pipefail` 였음. `set -e` 는 `grep -qE` 가 no-match (exit 1) 리턴할 때 hook 본체를 silent abort 시킴 — 정상 흐름인데 hook 이 도중에 죽어 후속 검사 안 돔.

수정 — plugin shipped 6 hook 모두 `set -uo pipefail` 로 통일:
- `lint-changed.sh` (post-edit)
- `block-destructive.sh` (pre-bash)
- `critical-rule-grep.sh` (pre-commit)
- `check-protected-paths.sh` (pre-edit)
- `spirit-check.sh` (pre-edit)
- `triage-nudge.sh` (user-prompt)

(`grep-on-commit.sh` 는 0.1.3 에서 이미 처리됨)

## 2) 신규 project hook 가드 4 → 6 가지

SKILL.md "절대 금지" 섹션의 가드 목록 확장:

기존 4 가지 (0.1.4):
1. 헤더 마커 `# [project-specific]`
2. annotation class 화이트리스트
3. `import static` modifier 처리
4. `capture-mistake.sh` 호출

추가 2 가지 (0.1.5):
5. **`set -uo pipefail` (no `-e`)**: hook 은 -e 없이 작성. plugin shipped 도 동일 컨벤션.
6. **plugin shipped 파일 append 금지**: 프로젝트별 spirit rule 도 `.ax/spirit/rules/ops.md` 같은 plugin shipped 파일에 append 하지 말 것 — plugin upgrade 시 silently clobber. 별도 파일 (`.ax/spirit/rules/<project>-<category>.md`) 로 만들고 root CLAUDE.md 의 CONVENTION 섹션에 `@.ax/spirit/rules/<project>-<category>.md` 한 줄.
