# 0.7.16 — 리뷰가 놓치던 축을 채워요

## 무엇이 좋아졌나 — 누구에게 체감되나

> L/XL spec 을 합의 리뷰로 돌리고, 구현 뒤 evaluator 리뷰를 받는 사람에게 체감돼요.

- **계획 단계에서 룰과 선례를 대조해요.** tasks 단계 리뷰의 evaluator 가 task 가 만들 파일에 걸리는 룰 목록을 받아 읽어요.
  "기존 패턴대로" 라고만 적힌 task 는 선례 파일 경로를 요구해요. 구현이 끝난 뒤 G7 에서야 나오던 위반을 계획에서 잡아요.
- **잘못된 입력 테스트가 빠진 task 를 알려줘요.** 파서, upsert, 조건부 갱신, 검증 로직 task 의 `검증:` 에 거부 경로가 없으면
  `tasks-plan.sh --lint` 가 짚고, evaluator 가 차단으로 적어요.
- **대안 비교에 기준이 생겼어요.** spec §2.3 에 원칙, 결정 동인, 대안 2개 이상을 적어요. 위험도 L2 이상이면 사전 부검과 검증 매트릭스도요.
  architect 가 이걸 점검해요.
- **Phase 마다 리뷰를 받을 수 있어요 (선택).** 입력을 거르는 task 가 있던 Phase 는 다음 Phase 로 가기 전에 evaluator 가 그 범위만 봐요.
- **리뷰 보고가 "직접 확인함" 과 "리뷰어 주장" 으로 나뉘어요.** 설정값 권고에는 호출처(온라인, 배치 …)가 붙어요.
- **리뷰 파일에 쓴 모델이 남아요.** `model:` 줄로 어떤 모델이 그 리뷰를 썼는지 알 수 있어요.

## 바뀐 것

- `tasks-plan.sh --lint` — 입력을 거르는 미완료 task 의 `검증:` 에 거부 경로가 없거나 `검증:` 이 없으면 `result.lint[]`, status warning
- `rules-audit-scope.sh --from-tasks` — 미완료 task 의 `files:` 로 룰을 매칭해요. 출력 파일은 `review-spec.evaluator.md`
- `spec-review.sh` — 리뷰 파일 셋째 줄 `model:` 을 읽어 `--status` 의 `architect.model` · `evaluator.model` 로 내요. 스냅샷 헤더도 세 줄
- `agents/evaluator.md` — Phase 모드, 거부 경로 테스트, 책임을 넘기는 문장, tasks 단계 룰·선례 대조. 구현 리뷰 둘째 줄 `model:`
- `agents/architect.md` — §2.3 점검. `agents/rules-auditor.md` — 둘째 줄 `model:`
- `_templates/spec/spec.md` §2.3 — 원칙, 결정 동인, 대안 ≥2, (L2+) 사전 부검과 검증 매트릭스
- `spec-validate` — tasks 단계 evaluator 브리프에 `--from-tasks` 룰 목록과 `--lint` 결과, 브리프에 모델, 보고 구분
- `spec-implement` — §4 에서 Phase 리뷰 선택 (`references/phase-review.md`), §8 브리프에 모델, 보고 구분
- `spec-tasks` — "기존 패턴" 지시에는 선례 경로, 입력을 거르는 task 는 `검증:` 에 거부 경로
- smoke §80–§83 (`tests/smoke/22-review-axes.sh`)

## 올릴 때

- 이미 있는 spec 은 그대로 돌아가요. `model:` 줄이 없는 리뷰 파일은 `model: null` 로 읽혀요. 판정에는 영향이 없어요.
- 새 spec 템플릿의 §2.3 은 `/spec` 으로 새로 만드는 spec 부터 적용돼요.
