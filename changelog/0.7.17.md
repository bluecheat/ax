# 0.7.17 — 모노레포·단일 저장소 어디서나 동봉 위치가 하나로 정해지고, 새 설정 키가 기존 config.yml 에 들어가요

## 무엇이 좋아졌나 — 누구에게 체감되나

> 모노레포에 goax 를 동봉해 쓰는 팀, 그리고 goax 를 올릴 때 새 설정을 받아야 하는 모든 설치본에 체감돼요.

- **동봉본과 훅이 같은 곳에 놓여요.** `/vendor` 와 루트 settings 훅 생성(`ade-settings.sh`)이 같은 규칙으로 ADE 루트(세션을 여는 곳)를 정해요.
  하위 프로젝트에도 `.claude/` 가 있는 모노레포에서 `/vendor` 가 저장소 루트가 아닌 하위 폴더에 동봉하던 문제가 사라져요.
  팀 전용 동기화 스크립트 없이 표준 `/vendor` 로 루트를 맞출 수 있어요.
- **세션을 여는 곳을 팀이 정해요.** 기본은 git 최상위예요(단일 저장소, 저장소 루트에서 여는 모노레포).
  하위 프로젝트에서 세션을 여는 팀은 `ade_root: "."` 한 줄로 정해요. 모노레포에서 처음 `/vendor` 할 때 한 번 물어요.
- **goax 를 올리면 새 설정 키가 config.yml 에 들어가요.** `/up` 재실행이 템플릿에만 있는 키를 기본값과 설명 주석까지 더해요.
  팀이 바꾼 값과 도메인 위험도는 그대로예요. 지금까지는 `foreign_executors`, `rule_lint_allow` 같은 새 키가 기존 설치본에 들어갈 길이 없었어요.

## 바뀐 것

- `lib/paths.sh` `goax_ade_root <project-root> [override]` — `--ade-root` → `.ax/config.yml` `ade_root:` → git 최상위 → (git 이 아니면) 가장 가까운 `.claude/` → 프로젝트 루트. `common.sh` 에서 옮겼어요
- `vendor-skills.sh --ade-root <경로>` — ADE 루트가 프로젝트 위가 아니면 오류로 알려요 (조용히 프로젝트로 바꾸지 않아요)
- `ade-settings.sh` — 자체 git 판정을 지우고 `goax_ade_root` 를 써요
- 새 스크립트 `config-merge.sh --template <템플릿>` — 빠진 최상위 키는 파일 끝에, 섹션 아래 키는 그 섹션 끝에 주석과 함께 더해요. `<config.yml>.lock` 안에서, 백업 없이
- `provision.sh` — 기존 config.yml 에 `config-merge.sh` 를 돌리고 `result.config_added` 로 알려요
- `config-set.sh` — 최상위 스칼라 키(`ade_root`)도 바꿔요. 값 없는 섹션 키는 거부해요
- `config.yml` 템플릿 — `ade_root: ""`
- `vendor` skill — ADE 루트 결정 순서, 모노레포에서 한 번 묻기. `up` skill — 더한 키 보고
- smoke §84–§85 (`tests/smoke/23-ade-config.sh`)

## 올릴 때

- `/up` 을 다시 돌리면 config.yml 에 빠진 키가 들어가요. 결과의 `config_added` 를 보고 바꿀 값이 있으면 `config-set.sh` 로 바꿔요.
- 모노레포에서 팀 전용 동기화 스크립트로 루트에 동봉하고 있었다면, `vendor-skills.sh --check` 가 이제 루트를 보고 `vendored: true` 로 나와요. 그 스크립트 대신 `/vendor` 를 써요.
- 하위 프로젝트 폴더에서 세션을 여는 모노레포 팀은 `config-set.sh ade_root "."` 로 정한 뒤 `/vendor` 를 다시 돌려요.
