# 0.5.3 — 산문이던 진단을 스크립트로, 세션 사이에 남는 인계 노트

> 0.5.x 계획(https://claude.ai/code/artifact/69145dba-4bac-4386-b17e-397058570ec2)의 둘째 판이에요.
> 스킬·에이전트 감사에서 "스크립트 없이 grep 해서 찍어라" 로 남아 있던 것들을 스크립트로 옮기고,
> 큰 스킬은 500줄 안으로 접고, 대화가 압축되면 사라지던 것(막힌 것 · 열린 질문 · 바뀐 이름 · 다음 할 일)에
> 파일을 줬어요. skill 17 → **15**, script 32 → **36**.

## 폐기 — `rules` · `spirit` skill (사용자 결정 Q1·Q2)

둘 다 하는 일이 산문이었어요. `rules` 는 "CLAUDE.md 와 spirit 과 module 을 grep 해서 인덱스를 찍어라",
`spirit` 은 "frontmatter 와 헤더 형식을 눈으로 검사해라". 스크립트가 없으니 세션마다 조금씩 다르게 했고,
doctor 3.7 이 같은 lint 를 SKILL.md 안 bash 로 또 했어요.

- **`rules-index.sh`** (신규) — Constitution 시그널 라인 + `.ax/spirit/rules/` + `.ax/modules/*/rules.md` 세 소스를
  한 목록으로. `--level` · `--source` · `--category` · `--find`. 룰 본문은 요약하지 않아요 — 원문이 정본.
  `build-memory.sh` 를 재사용하지 못한 이유: Constitution 토큰만 뽑고 `SP-*` 는 안 봐요 (critic 지적).
- **`spirit-lint.sh`** (신규) — 필수 파일 · `category:` frontmatter · `## SP-CAT-NNN:` 헤더 형식 · spirit ↔ modules
  **교차** 중복 · placeholder. 자동 수정 없음, `--strict` 면 exit 1.
- 트리거("rules 보여줘" · "spirit 점검")는 **`doctor` 가 받아요** — description 에 들어갔고, 그 절만 보고하고 끝내요.
  `/goax` 인덱스도 스크립트를 가리켜요. smoke 가 "누가 받는지" 를 grep 해요 — 폐기하면서 자연어 라우팅이
  끊기는 걸 이전에 겪었어요.

## `doctor` — 인라인 진단 셋을 `doctor-scan.sh` 로 (680 → 313줄)

3.6 마이그레이션 잔재 · 3.7 hook 등록 · 3.8 문서↔실제 는 SKILL.md 안에 사는 bash 라 `shellcheck` 도 `bash -n`
도 못 봤어요 (smoke §30 이 문법만). 셋을 스크립트로 뽑고, 하나를 더했어요.

- **도달 지도** — 룰 소스마다 "어떤 배관으로 세션에 닿는가, 그 배관이 살아 있는가". `AGENTS.md` 만 있고
  `CLAUDE.md` 가 없으면 Claude Code 는 AGENTS.md 를 읽지 않아서 **Constitution 이 어디에도 안 가요** —
  라벨이 완벽해도 룰은 0개예요. `paths:` 있는 spirit 룰은 `spirit-rules-inject.sh` 가, 모듈 룰은
  `module-rules-inject.sh` 가 등록돼야 닿고, universal 룰은 Constitution 의 `@import` 로만 닿아요.
  이 표가 doctor 에서 가장 먼저 봐야 할 줄이라 다음 단계 우선순위 맨 위예요.
- hook 등록 검사는 `settings.json.template` 이 SSOT — 이름을 hardcode 하지 않아요. `.gitignore` 기대값도
  `.gitignore.template` 에서 읽어요.
- doctor 원칙 하나가 생겼어요: **스크립트가 세는 것을 산문 bash 로 다시 세지 않아요.** 둘이 갈리면 어느
  쪽도 못 믿어요. `SubagentStart`·`Stop` hook 등록 검사는 그 hook 이 생기는 다음 판에 — 먼저 넣으면 자기
  출고본에 결손을 보고해요.

## 세션 간 인계 — `.ax/docs/STATUS.md` + `status-note.sh`

결정은 ADR, 진행은 tasks.md, 단계는 current-task.json 에 있는데 **"막힌 것 · 열린 질문 · 이번에 바뀐
공유 이름 · 다음 세션이 처음 할 것"** 은 어디에도 없었어요. 대화가 압축되면 사라져요. `zero` 가 이미
만들던 `STATUS.md` 를 공용 인계 노트로 승격했어요.

- 4절 고정: `지금 상태` · `다음` · `열린 질문` · `이번에 바뀐 이름`. 쓰는 쪽은 스크립트(`--add/--done/--set`),
  무엇을 적을지는 skill. 40줄 상한, 끝난 항목은 지워요 — 완료의 SSOT 는 git log · ADR.
- **`triage` §1.0 이 MEMORY.md 보다 먼저 읽어요.** `next` 가 지금 요청과 같으면 재분류 없이 이어가고,
  `open` 에 걸리면 그 질문부터 묻고, `renamed` 는 검색 키워드에 넣어요 (옛 이름으로 찾으면 못 찾아요).
- `spec-implement` 가 halt(§6)·완료(§8.2)·레인 보고(바뀐 이름) 시점에 적고, `zero` §13 이 첫날 개설하고,
  `onboarding` 이 끝에 "첫 spec" 을 넣어요. `build-memory.sh` 는 STATUS 가 있으면 맨 위에 포인터 한 줄.
- **MEMORY.md 는 기억이 아니라 룰 토큰 인덱스**로 자리를 정했어요. lean 모드에서도 🔴/🟡 포인터는 항상
  남고(빠지면 triage 의 CRITICAL/MANDATORY 도달이 끊겨요 — critic 정정), 접히는 건 열거뿐.
- **`build-index.sh` 제거** (Q3). BM25 역색인이 231줄 + smoke 항목 + README 행으로 "언젠가" 를 위해 살아
  있었는데, 임계(120 파일)를 넘는 코퍼스가 한 번도 없었고 그 규모도 `rg` 가 ms 로 끝나요.
  `triage-search.sh` 의 Phase 4 union 분기도 같이. 되살릴 조건: `.ax/docs` 가 2,000 파일을 넘는 실측.
