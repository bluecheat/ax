# 0.4.1 — 하네스 테제의 빈 절반 채우기 + 실사용에서 드러난 결함 정리

> 실사용 프로젝트(3개월, spec 21 · ADR 22 · mistake 49)와 공개 직후 리뷰에서
> 나온 발견을 반영해요. 관통하는 패턴이 하나 있었어요 — **사용자가 필요해서
> 직접 만들어 쓰던 것을 출고본이 안 담고 있었어요.** `[P]` 병렬 마커, `/adr`
> 슬래시 트리거, spirit 룰의 `paths:` 셋 다 손으로 추가돼 있었어요.

## 수정 — 조용히 깨져 있던 것들

**spec/ADR 번호 충돌.** 실사용 ADR 22개 중 7쌍, spec 21개 중 2쌍이 같은 번호로
겹쳐 있었어요. `next-spec-num.sh` 가 max+1 을 *계산만* 하고 생성은 호출자에게
맡겨서, 두 세션이 같은 값을 받는 창이 열려 있었어요.
→ `--reserve --slug <slug>`: 번호 원장(`.numbers/`)에 noclobber 로 원자적 선점 후
실물까지 생성. 마커는 영구 — ADR 템플릿의 "폐기된 ADR 도 ID 재사용 안 함" 규약과
같은 의미예요. 기존 프로젝트는 실물에서 원장을 자동 백필해요.
`--check-duplicates` 로 과거 충돌은 진단만 해요 (재번호는 링크를 깨뜨려 사람이 결정).
20개 동시 예약에서 충돌 0 확인.

**`up` 재실행이 사용자 자산을 파괴.** `up` 은 스스로 "destructive 하면 안 된다" 고
선언하는데 재실행마다 둘을 날렸어요.
① 런타임 상태 — `phase=implementing` / `spec_dir` 가 idle/null 로 리셋. triage-nudge
가 phase 로 작업 사이클을 추적하므로, 작업 중 `/up` 을 돌리면 그 spec 이 추적에서
조용히 빠져요. MANIFEST 의 `->` 를 seed-only 로 확정 (`check-manifest-install.sh` 는
이미 `->` 를 stateful 로 해석하고 있었는데 `up` 만 몰랐어요).
② `_templates` 사용자 수정본 — 덮어쓴 *뒤에* `.origin` 을 재계산해서 손실이 drift
감지에조차 안 잡혔어요. 이제 수정본을 보존하고 plugin 최신본은 `.suggested` 로.

**완료 마킹이 출고 템플릿과 형식 불일치.** 템플릿은 `- [ ] **T001**`(볼드)인데
마킹 sed 는 `- [ ] [T020]`(대괄호)를 기대했어요. **출고된 마킹 명령이 실제로는
아무것도 체크하지 못했어요.** 게다가 예시 ID `T020` 이 실행 위치에 하드코딩돼
있었고요. TASK_ID 변수화 + 볼드/대괄호/`[P]` 3형식 커버.

**bash 5.x bad substitution.** `${#CANDIDATES[@]:-0}` 는 bash 3.2(macOS) 가 조용히
`0` 을 반환하고 5.x(CI) 는 죽어요. 개발 환경에선 영영 안 보이는 부류라 CI 를
ubuntu + macos 매트릭스로 바꿨어요.

## 추가 — Layer 2·3 자동 주입 (하네스 테제의 절반)

goax 는 "출력 일관성은 모델이 아니라 *환경* 문제" 라고 주장하는데, 4계층 중
절반이 환경이 아니라 모델의 선의에 기대고 있었어요.

| 계층 | 이전 | 지금 |
|---|---|---|
| Layer 0 Triage | ✓ triage-nudge | ✓ |
| Layer 1 Constitution | ✓ `@AGENTS.md` import | ✓ |
| Spirit rules | ✓ 코드는 있으나 **데이터가 없었음** | ✓ |
| Layer 2 module rules | ✗ 훅 0개 | ✓ `module-rules-inject.sh` |
| Layer 3 spec/ADR | ✗ 훅 0개 | ✓ 활성 spec + 인용 ADR |

Spirit 쪽은 코드-데이터 불일치였어요 — `spirit-rules-inject.sh` 가 `paths:` 를
읽는데 출고 preset 7개와 템플릿에 그 필드가 아예 없어서, 기본 설치 상태의 Spirit
주입은 아무것도 매칭하지 않았어요. 템플릿 2종 + preset 7개에 `paths:` 를 채웠어요.

본문이 아니라 **경로만** 주입해요 (B-pointer). 룰 전문을 밀어 넣으면 편집 한 번에
수천 토큰이 들어가고 필요 없는 것까지 따라와요.

## 추가 — 완료 게이트

실사용 spec 21개 중 14개가 미완료 task 를 남긴 채 끝나 있었는데, 알려준 곳이
없었어요. 완료 판정이 "빈 체크박스 0개" 뿐이라 (a) 수용 기준 미충족 (b) 미완료를
지워서 통과 를 구분하지 못했어요.

`tasks-gate.sh` 4종 검사:
- G1 미완료 (`- [~]` 보류는 제외 — 의도적 보류를 표현할 수단이 없으면 게이트가
  그냥 성가신 게 되고 결국 우회 대상이 돼요)
- G2 대응 task 가 없는 수용 기준 (spec.md §3 에 `AC<n>` ID 도입)
- G3 어떤 AC 도 참조 안 하는 orphan task
- G4 task 총 수 감소 — "미완료를 지워서 통과" 방어

`pre-commit/spec-completion-gate.sh` 로 커밋 시점에도 걸어요. 게이트가 SKILL.md
안에만 있으면 그 skill 을 안 돌리고 끝내는 순간 아무도 확인하지 않으니까요.
기본은 경고(`sensors.mode=warning`), `fail` 로 올리면 차단.

## 추가 — vendor skill (plugin 없이 배포)

동봉은 이미 실사용 중인데 공식 경로가 없었어요 — 14개 skill 이 손으로 복사돼
3개월 전 버전으로 굳어 있었어요.

핵심은 루트가 둘이라는 것이에요. **ADE 루트**(에이전트가 스킬을 찾는 `.claude/`)와
**프로젝트 루트**(하네스가 있는 `.ax/`). 단일 저장소면 같지만 모노레포면 갈라져요.
이때 조상 탐색으로는 하네스를 영영 못 찾아요 — `.ax/` 가 *하위* 에 있으니까요.
`.goax-root` 포인터를 도입하고 `find_project_root` 에 단계를 추가했어요.

`/vendor` 는 두 루트를 감지해 ADE 루트의 `.claude/` 로 동봉하고, 갈라져 있으면
포인터를 남겨요. 사용자가 만든 skill 은 건드리지 않아요. `--check` 로 동봉본이
낡았는지 doctor 가 알려줘요.

## 추가 — 기타

- **mistake 에 `model` / `session_ref`.** env 에는 모델 정보가 없지만 transcript 에
  있어요. `detect-model.sh` 가 결정론으로 뽑아요 (LLM 자가보고 X). 감지 실패는
  `unknown` — 캡처 자체를 막으면 안 되니까요. `session_ref` 는 파일명만 담아요
  (mistake 는 커밋되므로 개인 절대경로 금지). audit 에 model 분포 절 추가.
- **죽은 스키마 살리기.** `applies_to` 를 주입 필터로, `# adr:` 주석을 실제 필드로
  승격해 Layer 2 주입 때 근거 ADR 도 같이 가리켜요. 실사용 리포가 두 필드를
  성실히 채워뒀는데 효과가 0이었어요.
- **`tasks-plan.sh`.** ready 집합 + `[P]` 주장 검증(파일 충돌). **wave 를 만들지
  않아요** — "1차 전원 완료 → 2차" 는 배리어라 가장 느린 하나가 나머지를 붙잡아요.
  **자동 실행도 하지 않아요** — 도구가 판단 없이 N개를 뿌리면 쓰기 충돌 위험을
  도구가 스스로 만들게 돼요.
- **분해 기준을 크기 → 필요 컨텍스트로.** "무슨 일을 하나" 가 아니라 "무엇을 알아야
  하나" 로 묶어요. 작업 종류(플래너/코더/테스터)로 쪼개는 건 핸드오프마다 새는
  전화 놀이라 안티패턴으로 명시.
- **evaluator 성립 조건.** fresh context 요구 + "발견 0건이 정상 결과" + 재현
  시나리오 없는 지적은 발견이 아님. 문제 이름(self-praise bias)만 부르고 조건은
  어디에도 없었어요.
- **모든 skill 에 `/<name>` 슬래시 트리거.** 자연어만으로 안 잡히는 경우가 실제로
  있었어요 (사용자가 손으로 `/adr`·`/spec-implement` 추가).

smoke 에 §19~§29 11개 섹션 신설. macOS bash 3.2 / Ubuntu 24.04 bash 5.2 양쪽 통과.

문서에 박힌 개수(skill·script)와 실제를 대조하는 검사도 넣었어요 — 이미 19→21 로

## 마이그레이션

`/plugin marketplace update goax` → `/plugin install goax` → 프로젝트에서 `up` 재실행.

**동작이 달라지는 지점**
- 새 spec/ADR 은 번호를 원자적으로 예약해요. 과거 충돌은 자동 수정하지 않아요
  (`doctor` 가 보고만 — 재번호는 기존 링크를 깨뜨려요).
- Layer 2·3 주입이 켜져요. `.ax/modules/*/rules.md` 와 spirit 룰에 `paths:` 가
  없으면 아무것도 주입되지 않아요 — `_templates` 를 참고해 채우세요.
- tasks.md 새 형식(`[P]`·`[AC<n>]`·`- [~]`)은 **기존 형식과 함께 읽혀요.**
  마이그레이션을 강제하지 않아요.
- 완료 게이트는 경고로 시작해요. 차단이 필요하면 `sensors.mode: fail`.
