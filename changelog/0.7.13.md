# 0.7.13 — 합의 리뷰가 상한에서 멈춰요 · 구현은 lane-worker 가 맡아요 · 전체 검증 없이는 완료가 아니에요

## 무엇이 좋아졌나 — 누구에게 체감되나

> spec 합의 리뷰·레인 모드를 쓰는 팀, 특히 다른 플러그인(OMC 등)과 goax 를 같이 쓰는 사람에게 체감돼요.
> 근거는 commerce 워크트리 세 곳의 실수 29건이에요 — 10-09 이후 13건 중 8건이 하네스가 막았어야 할 일이었어요.

- **리뷰가 상한을 넘어 계속 돌지 않아요.** 예전엔 상한(spec 3 · tasks 2)을 넘어도 경고만 나와서, 실제 tasks 단계가
  라운드 18 까지 갔어요. 이제 상한을 넘는 `--snapshot` 은 아무것도 쓰지 않고 멈춰요. 그 뒤는 사용자가 정해요 —
  지금 본문으로 진행(`--override`)이거나, 리뷰 한 번 더(`--extend-round`, 라운드 **하나만** 열려요).
- **구현은 lane-worker 가 맡아요.** spec 구현 중에 다른 실행 에이전트(`executor` 등)로 일을 넘기려 하면 새 훅
  `delegate-gate` 가 한 번 물어요. 다른 플러그인 훅이 자기 executor 를 권해서 lane-worker 의 소유 파일·커밋 금지
  규율이 통째로 빠진 일이 있었어요.
- **필터 테스트만 돌리고 "완료" 가 되지 않아요 (G8).** 완료 전에 `zero-verify.sh --record <spec>` 이 config 의 명령
  전부를 돌린 기록이 있어야 해요. 기록 뒤에 코드를 고치면 다시 요구하고, 커밋만 한 건 그대로 인정해요.
  `commands.test` 가 비어 있으면 요구하지 않아요.
- **정리·스윕 레인에 레거시 파일이 안 섞여요.** `lanes-dispatch.sh --stack-files` 가 이번 스택에서 바뀐 파일만 뽑고,
  `--dispatch` 는 스택 밖 기존 파일을 보내면 알려줘요.
- **룰 파일은 끝까지 읽어야 읽은 거예요.** `offset`·`limit` 로 앞부분만 읽어도 rule-read-gate 를 통과하던 구멍을 막았어요.

## 바뀐 것

- `spec-review.sh` — `--snapshot` 은 새 라운드가 상한을 넘으면 쓰기 전에 exit 1. `--extend-round [--stage spec] --reason`
  (신규)은 `review-extend.md` 에 `after_sha`(마지막 리뷰된 스냅샷)·`grant: <단계> <라운드>` 를 남겨 그 라운드 하나만 열어요.
  `--max-rounds` 는 낮추기만 돼요. tasks → spec 단계 되돌리기도 상한을 1 로 되돌리는 길이라 연장 기록이 있어야 해요.
  결과에 `extended` 가 붙어요
- `spec-validate` — 상한에 닿으면 `AskUserQuestion` 으로 진행 · 한 번 더 · spec 재정의를 물어요. 상한은 "품질 수렴"
  이 아니라 비용·과잉설계를 막는 선이라고 적었어요
- `hooks/pre-agent/delegate-gate.sh` (신규, PreToolUse `Agent|Task`) — phase `implementing`·`review` 에서
  `sensors.foreign_executors`(기본 `executor` · `deep-executor` · `general-purpose`, `플러그인:` 접두사 무시)로의 위임을
  에이전트 이름마다 한 번 막아요. `config.yml` 에 `foreign_executors` 키
- `spec-implement` §3.3 — 단일 레인 위임 대상을 `goax:lane-worker` 로 고정, 모델은 `agent-model.sh`
- `zero-verify.sh --record <spec>` (신규) — `<spec>/verify.json`(`fingerprint` · `checks` · `ok`). `--cmd`·`--only` 와
  같이 쓰면 거부해요
- `tasks-gate.sh` G8 (신규) — `verify_state`: `ok` · `missing` · `fail` · `stale` · `mismatch` · `unconfigured` · `none`.
  필수 여부는 G6 과 같아요. 실패 기록은 필수가 아니어도 막아요
- `common.sh` — `goax_tree_fingerprint`(`.ax/` 를 뺀 작업 트리 내용 지문 — HEAD 트리 위에 바뀐·새 파일을 덮어 계산,
  읽기만 해요), `goax_config_cmd`(zero-verify 의 `commands.*` 파서를 옮김), `goax_stack_base` · `goax_stack_files`
  (rules-audit-scope 에서 옮김)
- `lanes-dispatch.sh` — `--stack-files [--path] [--base]` (신규), `--dispatch` 결과에 `outside_stack`
- `rule-read-gate.sh` — 파일 끝까지 덮지 않는 Read 는 기록하지 않아요. 입력 필드 구분자를 `\x1f` 로 (탭은 빈 필드가
  이어지면 뒤 필드가 당겨져요)
- `docs/reference/writing-for-agents.md` (신규) — 모델이 읽는 글의 기준이에요. 조건, 주어와 행동, 이유 한 줄로 써요.
  이번 버전에서 바꾼 SKILL 문단, 훅 문구, 스크립트 메시지를 이 기준으로 다시 썼어요
- smoke — §51b delegate-gate, §71 G8, §72 스택 판정, §33·§65 상한 차단으로 갱신
