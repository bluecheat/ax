# 0.1.16 — SDD 슬림화 (plan.md 폐기 + tier 2 단계 + spec-validate 강화)

## 핵심 변경

도그푸딩 중 발견한 spec/plan/tasks **3 산출물 사이 중복** 과 spec close 시점에 *alpha 환경 e2e* 같은 운영 활동이 혼입되는 문제를 해결해요. 3 검토자 (architect / critic / planner) 합의로 plan.md 와 basic tier 를 폐기하고, "다음 단계" 자유 입력란을 정형화했어요.

### 폐기 (3 항목)

- **`/spec-plan` skill + command** 통째 삭제 — 설계 결정의 *근거* 는 ADR 이 단독 담당
- **`plan.md` 템플릿** 삭제 — spec.md §7.5 Technical Context 가 *기술 컨텍스트* 자리, ADR 이 *결정 근거*
- **basic tier** 폐기 — `S/M × L0~L1` 도 standard 흡수. tier 는 standard / full 2 단계

### 신규 (2 항목)

- **`check-spec-clarity.sh`** 신규 스크립트 — NEEDS CLARIFICATION + placeholder `<...>` 본문 잔존 + 필수 섹션 (§1.1 / §3 / §4) 비어있음 3 가지를 한 번에 검사. spec-validate 가 grep 한 줄 → 결정론 스크립트 위임으로 강화
- **spec.md §7.5 Technical Context** 신규 섹션 — 스택·언어 / 영향 모듈 / 적용 룰 토큰 / 진입 ADR 4 항목 표 (3~5 라인). plan.md 의 Tech Context 자리를 spec 안에 흡수

### "다음 단계" 자유 입력란 폐지

`spec.md` / `tasks.md` / `quickstart.md` 끝의 자유 텍스트 `## 다음 단계` 섹션 모두 제거. 워크플로우 안내는 skill 출력의 `📍 다음` 으로만 제공해요. 환경 검증·배포·모니터링 같은 운영 활동은 이 문서 *범위 밖* 명시.

## tier matrix (0.1.16)

| Tier | 산출물 | 적용 size×risk |
|---|---|---|
| **standard** | `spec.md` + `tasks.md` (2) | S/M/L × L0~L2 |
| **full** | + `research.md` + `data-model.md` + `quickstart.md` + `contracts/` + ADR | L × L3 / XL × * |

## Why

도그푸딩 결과:

- spec / plan / tasks 사이 **5 항목 중복** (거부된 대안, 의존성, 데이터 마이그레이션, Phase 구조, "다음 단계")
- plan.md 108 라인 중 **약 60 라인이 다른 문서와 겹침**
- "다음 단계" 자유 입력란이 SSOT 위반 + scope creep 통로 (4 파일에 분산)
- spec-validate 의 grep 게이트가 placeholder 잔존·빈 섹션을 검사하지 않아 거짓 안전
- basic tier 가 사실상 의례 — standard 가 80~90% 흡수해서 실질 binary

→ spec (WHAT/WHY) / tasks (HOW) / ADR (WHY-DECISION) 3 자 *책임 분리* 로 정렬. 다음 사이클부터 중복·혼입이 사라져요.
