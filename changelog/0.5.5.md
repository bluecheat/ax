> (보고서: https://claude.ai/code/artifact/c7821f87-9d39-4243-903b-b681526937b4). changelog 가 약속한 장치들은

## 원장 · 완료 게이트 · 합의 리뷰

- **쓰기 락.** `common.sh` 에 `goax_lock`/`goax_unlock` (mkdir 락 · PID · stale 회수 60s · 타임아웃 10s). `lanes-dispatch.sh`
  의 원장 read→transform→mv 와 `tasks-gate.sh`·`update-state.sh` 의 `task_seal`/state.json 갱신을 감싸요. 실측: `--report A` ‖
  `--report B` 30회 → 유실 30/30 에서 **0**, 16 레인 동시 보고 → 16 기록, state.json 동시 6회 → 온전.
- **코드펜스는 task 가 아니에요.** `tasks.md` 를 줄 단위로 읽는 파서 6곳(lanes-dispatch · tasks-gate · tasks-plan · lanes-hotfiles ·
  check-spec-clarity · HUD)이 ``` 안을 건너뛰어요. 출고 템플릿의 형식 설명 예시 `T001` 이 실 task 로 세지던 것 —
  갓 만든 spec 에서 ready·blocked 양쪽에 T001, total 5(실제 4), `--assign` 이 두 줄에 stamp — 이 사라져요.
- `--assign` 은 트랜잭션이에요 — 하나라도 거부되면 파일 무변경, `result.applied`/`rejected[{task,reason}]`.
- `files:` 경로는 비교 전에 정규화해요(`./`·중복 `/`·끝 `/`). `src/a.ts` 와 `./src/a.ts` 는 같은 파일이에요.
- `--dispatch <lane>` 은 **보고를 못 받은** task 만 보내요. 이미 보고받은 task 를 재전송하려면 `--force`(그때만 `보고:` 삭제).
  성공하면 `status: ok` 예요 — 방금 보낸 task 는 "보고 안 받은 디스패치" 경보에서 빼요.
- `spec-review.sh` — `.tier` 는 3줄 YAML 이라 `tier:` 키를 읽어요(예전엔 `full` 이 영원히 안 걸려 비활성 spec 이 전부 optional).
  SSOT(`tier-from-state.sh`) 조회 실패·`phase=idle` 이면 optional 로 열지 않고 `.tier` 기준으로 닫아요. sha 는 spec.md + tasks.md
  합산 — tasks.md 만 바꿔도 `--status` 가 `changed_files` 로 지목해요. 라운드 상한(3) 초과는 JSON `warning` + 텍스트 `⚠`.
- **exit 계약.** `tasks-gate.sh --strict` 위반 = **1**, 대상 spec 없음 = `status: skipped` + **2** (README 표준과 같아요).
  `--spec 001` 축약은 `goax_resolve_spec`(정확 일치 → prefix 1개 → 실패) 로 5개 스크립트가 같은 답을 내요.
- `--dry-run` 이 파일을 쓰던 자리 셋(tasks-gate 봉인 · spec-review `--merge`·`--snapshot`) 가드. `--all --json` 은 `specs[]`.
  G6 verdict 는 review.md **첫 줄**만. `--help` 가 `Exit:` 계약까지 보여줘요(7개 게이트 스크립트).

## 템플릿 ↔ 게이트 · 룰 집행

- **spec.md 템플릿을 채우면 `check-spec-clarity.sh` 가 통과해요.** 마커 정규식을 `**NEEDS CLARIFICATION**` 로 좁히고
  안내문의 리터럴을 "미해결 마커" 로, `AC<n>` 안내를 `AC1, AC2 …` 로, §4 시나리오를 펜스 밖 불릿으로, §5/§6 에
  "안 쓰면 섹션째 지우세요". 예전엔 성실히 채운 spec 도 `needs_clarification 3 · placeholders 1 · §4 빈 섹션` 으로 영원히 exit 1 이었어요.
- **`severity:` 를 읽어요.** `check-rule-enforcement.sh` 가 spirit/module 룰 frontmatter 의 `severity` 를 critical/mandatory/convention
  으로 매핑해요 — 예전엔 "convention" 고정이라 I1 이 frontmatter 룰 전면에서 죽은 코드였어요. 배열형 `enforced_by` 가 한 번도
  안 읽히던 것(키 리셋 순서)과 YAML 인라인 주석이 값으로 들어가던 것도 같이 고쳤어요.
- **CI `--strict` 를 첫날부터 켤 수 있어요.** `enforced_by` 가 `<…>`·`YYYY-MM-DD` 자리표시자면 위반이 아니라
  `result.placeholder_rules` + warning 이에요. 출고 `AGENTS.md.template` 의 예시 룰이 갓 설치한 프로젝트를 I2·I5 위반으로
  만들던 게 사라지고, `templates/zero/ci/github-actions.yml.example` 의 harness job 이 `--strict` 로 돌아요.
- `_templates/spirit/{rule,ops}.md` 에 `severity`·`enforced_by`·`enforced_kind` 필드. `checks/README.md` 가 인용하던
  `version-bump.sh` 프로브를 실제로 추가했어요(`probe/examples/`).
- `zero-guard-bash.sh` 는 **명령 위치**의 `git add -A|.` 만 막아요. 커밋 메시지·echo·grep 인자·`#` 주석·heredoc 속 언급은 통과.

## 설치기 · 훅

- `provision.sh` 는 심볼릭 링크를 따라가지 않아요 — 대상 경로 조각 어디에 링크가 끼어 있든(댕글링 포함) 건너뛰고
  `warnings` 에 남겨요(`status: warning`). 예전엔 `.ax/hooks` 를 프로젝트 밖으로 걸어 두면 훅 14개가 밖에 생기고 `status: ok` 였어요.
- **시크릿 검출 두 갈래.** `critical-rule-grep.sh` 가 토큰 형태 12종(AKIA · gh[posru]_ · github_pat_ · xox · sk/pk/rk_live_ · sk- ·
  AIza · npm_ · whsec_ · PEM · JWT)은 대소문자 그대로, `key[:=]value` 는 대소문자 무시로 봐요. 값 첫 글자 `$<{%(` 와 6자 미만은
  제외해서 `${GITHUB_TOKEN}`·`secret: null`·`token_count = 0` 은 안 잡아요. 실검체 9/9 검출, 오탐 0/4. 매칭 줄은 안 찍어요.
- `block-destructive.sh` 가 `rm -rf ../..`·`../../etc` 도 경고해요(예전엔 `..` 하나만). jq 가 없으면 `[goax] jq 없음 — 이 안전망이
  비활성 상태예요` 한 줄을 남기고 통과해요(무성 fail-open 아님).
- **인계 노트는 24시간만 게이트 통과증이에요.** `status-note.sh --set now` 가 줄 끝에 `(YYYY-MM-DDTHH:MMZ)` 를 붙이고,
  `stop/spec-gate.sh` 는 그 시각이 24h 이내일 때만 "멈추는 게 의도" 로 봐요. 시각 없는 옛 노트는 인정하지 않아요.
  `--clear <절>` 로 지울 수 있어요. Stop 훅이 `.ax/.session/` 의 하루 넘은 디렉토리도 지워요.
- `doctor-scan.sh` 훅 등록 검사가 (이벤트 키, 경로) 쌍이에요 — Stop 훅이 PreToolUse 아래 있으면 `missing` 이에요.
- `zero-init.sh` 가 settings.json 머지 실패 시 `.tmp` 를 지우고, `.bak` 은 최신 3개만 남겨요.

## zero · onboarding 스크립트

- `zero-domain-risk.sh` — 검증·재작성이 같은 전체 매치(`^[[:lower:]][[:lower:][:digit:]-]*=L[0-3]$`, `LC_ALL=C`)를 봐요.
  변환 안 된 줄이 있으면 파일을 쓰지 않고 exit 1. 예전엔 `Payment=L2` 가 `[a-z]`×en_US 로케일로 검증만 통과해 `domain_risk`
  4개를 0개로 지우고 `status: ok` 였고, `new=oops=L3` 는 깨진 YAML 을 만들었어요. `common.sh` 가 `LC_COLLATE=C` 를 export 해요.
- `constitution-apply.sh` — 중복 0건(가장 흔한 경우)에 빈 출력 exit 1 로 죽던 경로 제거. "이미 적용됨" 판정은 첫 헤더가 아니라
  블록의 **룰 토큰**(`AX:MANDATORY:002` · `SP-OPS-001`)이 대상에 전부 있을 때만.
- `zero-ablation.sh --on` 은 목적지에 파일이 있으면 덮지 않고 `.ablated` 를 유지 + warning. `zero-verify.sh` 는 값을 감싼 바깥
  따옴표만 벗겨요(`test "a b" = "a b"` 가 돼요). `init-mistake-file.sh` 는 `${arg,,}`(bash 4) 를 `tr` 로 — bash 3.2 에서 필수 인자
  검증이 조용히 꺼지고 빈 category 파일을 ok 로 만들던 것.

## 스킬 · 에이전트 · 문서

- `spec-tasks` §3 이 가르치는 task 줄 형식이 템플릿과 같아요 — `files:` 필수 · `의존:`·`검증:` continuation. 예전 형식으로 쓰면
  같은 파일 `[P]` 겹침이 `violations: []` 였어요. §5 다음 단계에 `lane`.
- `spec-validate` 는 JSON 을 `printf '%s\n'` 로 넘겨요(zsh 내장 echo 가 `header` 의 `\n` 을 펴서 첫 라운드부터 깨졌어요).
  절차에 "round ≥ 3 이면 사용자 결정" 명시. triage 의 M×L2 메뉴에 "합의 리뷰 켜기".
- `lane-worker`·`lane-scout` 는 최종 메시지로 보고해요(`Agent` 스폰에 `SendMessage` 가 없어요). lane-mode 는 라운드 단위 배리어를
  인정하고, 빈 레인 `--dispatch` exit 1 을 정상 종료로 봐요.
- triage 매트릭스 3문서(triage SKILL · triage-matrix · skill-routing)가 `tier-from-state.sh` 와 같은 셀 값을 가져요 — L·XL 전 행 evaluator.
- `up` 은 `.ax/` 존재로 install/update 를 먼저 가르고, update 경로에선 goax 가 깐 CLAUDE.md 를 brownfield 근거로 삼지 않아요.
  `doctor` §2 는 스크립트 출력으로 세요. AskUserQuestion 은 4문·4옵션.
- 설치되는 `spirit/README.md`·`tone.md` 에서 폐기된 `goax spirit/rules/find` 명령과 없는 `up --force` 를 걷어냈어요.
  README 트리에 훅 7종 13개, `scripts/bash/README.md` 에 쓰기 규약(락 · `LC_COLLATE=C` · 펜스 skip)·exit 계약·`warning` 상태·
  누락 카탈로그 2개. 리포 `CLAUDE.md` 에 같은 규약 3줄.
