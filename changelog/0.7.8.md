# 0.7.8 — 화면을 만들고 재고 고친 뒤에만 보여주는 `screen` skill · `screen-designer`

## 무엇이 좋아졌나 — 누구에게 체감되나

> 웹·앱 화면을 Claude 에게 맡기는 사람 모두에게 체감돼요. 디자인 도구나 MCP 가 없어도 끝까지 돌아요.

- **"화면 만들어줘" · "이 화면 어때" · "문구 고쳐줘" 가 한 흐름으로 끝나요.** 스펙 표를 먼저 채우고, 새 컨텍스트의
  `screen-designer` 가 구현 → 렌더링 → 실측 → 수정(최대 3회)까지 마친 뒤에만 결과를 보여줘요.
- **"괜찮아 보여요" 대신 숫자로 판정해요.** 게이트 20개(글자 비율 · 간격 스케일 · 버튼 높이 · 터치 44 · 금지어 0건 ·
  대비 4.5:1 …)를 칸마다 측정 출처와 함께 적고, 리포트 첫 줄은 `verdict: 통과 | 보강 필요 | 실측 아님` 이에요.
  - 스크린샷이 실제로 없거나, 측정값이 비었거나, 코드 상수만 보고 적었으면 `통과` 가 되지 않아요.
  - 브라우저 · 시뮬레이터가 없으면 정직하게 `실측 아님` 이라고 말하고, 직접 캡처하는 방법을 알려줘요.
- **외부에 기대지 않아요.** 기본 팔레트 · 타입 램프 · 간격 · 부품 16종 · 화면 19종 · UX 문구 규칙 · 한국어 화면 관례가
  skill 안에 다 있어요. 프로젝트의 토큰 · 테마 · 컴포넌트가 있으면 그게 먼저고, Figma · 레퍼런스 MCP · 브라우저 ·
  시뮬레이터는 있으면 빨라질 뿐이에요.
- **절제가 기본이에요.** 포인트 컬러 하나, 장식보다 정보 순서. 랜딩 · 캠페인처럼 화면 종류가 정할 때만 파격을 허용하고,
  그때도 게이트는 그대로예요.
- **기존 흐름과 이어져요.** triage 가 화면 작업이면 `screen` 으로 넘기고, `zero` 의 첫 시안과 `spec-implement` 의
  화면 task 가 이 절차로 돌아요 (task 의 `검증:` 은 리포트 판정으로 대신해요).
