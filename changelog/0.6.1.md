# 0.6.1 — doctor 의 external 룰 경고가 실제로 뜨고, 잠긴 환경에서 진단·설치가 틀리게 통과하지 않아요

## 달라지는 것

> 체감 범위를 먼저 적어요. 첫 항목(I6)은 `enforced_by: external:*` 룰을 쓰는 모든 git 프로젝트에 해당해요.
> 나머지 셋은 임시 파일이나 git 명령이 막힌 환경(샌드박스 · 잠긴 CI 컨테이너)에서만 발동하는 보강이라
> 일반 개발 머신에선 동작 변화가 없어요.

- **`external:*` 룰의 "자동 실행 안 됨" 경고가 실제로 떠요.** `enforced_by: external:vitest` 처럼 외부 도구에
  맡긴 🔴 룰은 CI 나 프로젝트 전용 훅이 있어야 자동으로 도는데, 갓 설치한 프로젝트에서 이 검사(I6)가 항상 통과해
  경고가 한 번도 안 떴어요. 이제 트리거가 없으면 doctor 가 짚어요.
- **`doctor` 가 틀린 초록불을 안 켜요.** 임시 파일을 못 만드는 환경(샌드박스·잠긴 `$TMPDIR`)에서 룰 검사가
  "전부 통과" 로, git 명령이 안 도는 환경에서 "pre-commit 훅 없음" 으로 잘못 나오던 걸 고쳤어요. 이제 프로젝트 안
  임시 폴더로 대신 돌고, 그것도 안 되면 통과 대신 **에러로 멈춰요**.
- **`up` 설치가 사용자 템플릿을 조용히 덮어쓰지 않아요.** 임시 폴더를 못 만드는 환경에서 백업 없이
  `.ax/_templates/spec/` 의 사용자 수정본을 덮어쓸 수 있었고, `AGENTS.md` 가 매번 "수정됨" 으로 잘못 표시될 수
  있었어요. 둘 다 백업을 못 만들면 설치를 멈춰요.
- **git worktree · husky 프로젝트에서 훅 경로를 제대로 찾아요.** `git worktree add` 로 만든 작업 트리와
  `core.hooksPath` 설정(husky v9 등)을 git 없이도 해석해요.

## 메인테이너용

- **eval 스위트가 hook·스크립트가 실제로 도는 상황을 재요.** `claude plugin eval` 샌드박스는 프로젝트
  `.claude/settings.json` 을 안 읽어서 지금까지는 모델 프로즈만 재고 있었어요. `tests/eval-hook-shim/` 이 hook
  등록을 미러하고, 세 케이스 전부 `provision.sh` 로 실제 설치한 트리에서 돌아요 — 룰 주입(`critical-canary`),
  doctor 의 스크립트 진단(`doctor-i6`), triage 선행(`triage-first`). 실행 명령과 측정 표는 `evals/README.md`.
- 위 doctor·설치 버그 세 개는 전부 이 eval 이 잡았어요.
