# 0.1.10 — mistake skill 본문 작성 강제 + template 청소

> 0.1.9 출시 직후 첫 사용에서 발견된 두 결함 패치. mistake skill 의 핵심 동작(본문 5섹션 작성)이 실제로 일어나지 않던 문제 + 템플릿이 생성 파일에 가이드 텍스트를 흘리던 문제.

## 1) Mistake skill 본문 작성 단계 강제

증상: 5건 캡처 호출 시 `init-mistake-file.sh` 만 실행되고 본문 5섹션 (어디서 / 왜 발생 5 Whys / 어떻게 막을 수 있나 / 영향 Cost / audit 액션) 이 placeholder 그대로 남음. audit 시 의미 0.

원인: skill 의 본문 작성 단계가 advisory 톤이라 LLM 이 script 호출을 skill 종착점으로 해석.

수정:
- `init-mistake-file.sh` JSON `next_step` — `"edit ... — fill"` 같은 soft 표현을 `"MANDATORY next: Edit ..."` 로 강제. 5섹션 명시 + placeholder 마커 enumeration (`파일/모듈/도메인.`, `1. 왜 X? → A`, `<예:` 등) + "보고 직전까지 잔재 0 까지" 명령.
- `skills/mistake/SKILL.md §3` — 5섹션 표에 *교체 대상 placeholder* 컬럼 추가. "완료 검증 (보고 직전 필수)" 블록 신설 — Grep 으로 마커 잔재 0 검증, 1건이라도 남으면 추가 Edit, "캡처 완료" 보고 금지.
- `SKILL.md §6 (절대 금지)` — "본문 placeholder 그대로 두지 X (검증 필수)" 로 강화.

## 2) Template 청소 — 생성 파일 오염 2건

`_templates/mistakes/mistake.md` 가 cp 될 때 생성 파일에 노이즈 전파:

- 상단 HTML 주석 (`<!-- enum 가이드 -->`) — `skills/mistake/SKILL.md:37-39` 가 이미 SSOT 라 중복 + 매 mistake 파일 헤더 오염
- `## 이력` 섹션의 `- 최초 작성 <HH:MM:SS>` placeholder — sed 치환 대상이 아닌데 `init-mistake-file.sh` 가 별도로 `- 최초 캡처 HH:MM:SS` append → 두 줄 겹침

수정: 두 라인 모두 template 에서 삭제. script append 가 단일 SSOT.

## 호환성

- 0.1.9 사용자가 0.1.10 으로 update — 새 캡처는 즉시 강제된 본문 작성으로 진행, 기존 placeholder 잔재 mistake 는 사용자가 수동 정리 (또는 audit skill 이 다음 회고 시 안내).
- template 변경은 plugin reinstall 후 사용자 프로젝트 `.ax/_templates/mistakes/mistake.md` 에 자동 반영.
- 기존 mistake 파일에 남은 `- 최초 작성 <HH:MM:SS>` 라인은 무해 — 그대로 두거나 수동 삭제.
