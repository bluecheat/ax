# 0.2.0 — OpenCode Hybrid 호환 + AGENTS.md Constitution SSOT

> Claude Code 외 [OpenCode](https://opencode.ai/) 환경에서도 goax 가 plug-and-play 동작하도록 Hybrid 호환 레이어를 추가했어요. 3축 (보안·이식성·범용성) 팀모드 분석 → critic 검토 → 사용자 인터뷰 (Hybrid + AGENTS.md 우선 + hook 미지원 명시) 답을 기반.

## Breaking change — Constitution SSOT 위치 이동

### 변경 요약

| 항목 | 0.1.x | 0.2.0+ |
|---|---|---|
| Constitution SSOT | `CLAUDE.md` | `AGENTS.md` (multi-CLI) |
| `CLAUDE.md` 본문 | 1차 SSOT | `@AGENTS.md` import alias (Claude Code 전용 진입점) |
| 마크다운 자산 인식 | Claude Code 자동 | Claude Code + OpenCode 둘 다 |

### 왜 AGENTS.md 우선?
- [OpenCode 공식 문서](https://opencode.ai/docs/rules/) 가 AGENTS.md 우선 인식, CLAUDE.md 는 fallback
- Claude Code 는 `@AGENTS.md` import 문법을 이미 지원 — alias 가 자연스러움
- 사용자 customize 영역이 두 곳으로 분산되는 걸 막음 (SSOT 단일화)

### 자동 마이그레이션 (`up` 재실행 시)

1. **기존 CLAUDE.md 가 이미 `@AGENTS.md` alias 형태** (1줄 + 20줄 미만): 자동으로 출고본 갱신 (drift 방지)
2. **기존 CLAUDE.md 가 customize 본문**: 손대지 않음 + `.ax/CLAUDE.md.suggested` 로 새 alias 본문 보존. `up` 이 §7 마이그레이션 가이드 출력 — 권장 수동 절차:
   - 기존 CLAUDE.md 본문 → AGENTS.md 로 mv
   - CLAUDE.md → suggested 의 alias 본문으로 교체
   - 양쪽 CLI 동시 인식
3. **AGENTS.md 가 이미 있음**: `.ax/AGENTS.md.suggested` 만 보존, diff 후 사용자 머지

기존 사용자가 CLAUDE.md 본문을 그대로 두면 Claude Code 는 그대로 동작. OpenCode 도 CLAUDE.md fallback 으로 동작. 즉 **breaking 이지만 마이그레이션 없이도 양쪽 CLI 모두 안전**.

## 신규 자산

### `templates/default/AGENTS.md.template` (Constitution SSOT)

기존 `CLAUDE.md.template` 본문을 그대로 이동 + 헤더 multi-CLI 명시:
```markdown
# [PROJECT_NAME] — Constitution (AGENTS.md, Multi-CLI SSOT)

> AI 에이전트의 비협상 룰. README 가 아니라 system-level governance 문서.
> **이 파일이 SSOT** — Claude Code 는 `CLAUDE.md` 의 `@AGENTS.md` import 로, OpenCode 는 직접 인식.
```

META 가드레일 5원칙 + 시그널 의미 + CRITICAL/MANDATORY/CONVENTION 섹션 + 4계층 인덱스 — 0.1.x CLAUDE.md.template 본문 동일.

### `templates/default/opencode.json.template` (OpenCode config)

OpenCode 환경 감지 시만 설치. `instructions:` 가 AGENTS.md + 핵심 reference 문서를 system prompt 로 병합:
```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "AGENTS.md",
    ".ax/docs/reference/rules-tokens.md",
    ".ax/docs/reference/rule-enforcement.md",
    ".ax/docs/reference/triage-matrix.md",
    ".ax/docs/reference/critical-rules.md",
    ".ax/docs/reference/opencode-compat.md"
  ],
  "plugins": []
}
```

`plugins: []` 자리는 0.2.x 후속에서 bash hook 의 TypeScript 포팅 도입 시 채움.

### `.ax/scripts/bash/install-git-hooks.sh` (OpenCode mode hook 보전)

OpenCode 는 PreToolUse subprocess hook 미지원이라 `.git/hooks/pre-commit` 으로 chain 보전:
```bash
bash .ax/scripts/bash/install-git-hooks.sh
# → .git/hooks/pre-commit wrapper 설치 (#goax-pre-commit-chain marker)
# → 재실행 시 skipped (idempotent)
# → 기존 hook 있으면 --force 로 .bak 백업 후 교체
```

설치된 wrapper 가 `.ax/hooks/pre-commit/*.sh` 를 사전순 chain 실행 (CATASTROPHIC 차단 + secrets 재검증). 첫 exit 2 에서 commit 차단.

### `docs/reference/opencode-compat.md` (호환 매트릭스 SSOT)

호환 매트릭스 + git pre-commit 가이드 + OpenCode 환경변수 (`OPENCODE_DISABLE_CLAUDE_CODE` 등) + 알려진 OpenCode 버그 ([Issue #6177](https://github.com/sst/opencode/issues/6177) plural/singular 미스매치) + 트러블슈팅. CLAUDE.md.template 도 이 문서를 가리킴.

## 0.2.x 로 의도적으로 보류

사용자 인터뷰에서 "Hybrid 권장" + "TypeScript plugin 보류" 결정. 다음 항목은 별도 트리거 기준:

| 항목 | 보류 이유 | 트리거 |
|---|---|---|
| `.opencode/plugins/goax-hooks/plugin.ts` (Full 옵션) — bash hook 의 TS 포팅 | npm 의존 + 유지보수 표면 2배 비용 정당화 부족 | 실제 OpenCode 사용자가 PreToolUse hook 동등성 요청 |
| `experimental.hook` 기반 bash 호출 | OpenCode 공식 스펙 미공개, 깨질 위험 | OpenCode 의 hook event API 안정화 |
| OpenCode HUD statusline 어댑터 | OpenCode statusline schema 가 Claude Code 와 다름 | 어댑터 작업 단위 별도 |
| Spirit rules path-scoped 자동 inject (OpenCode) | bash hook 미지원이라 path-based context injection 불가 | TypeScript plugin 도입 시 동시 |
| `.opencode/agents/` sub-agent 포팅 | `agents/architect.md` + `evaluator.md` 의 OpenCode 형식 매핑 — 별도 작업 | TypeScript plugin 과 같은 트리거 |
| i18n (영문 AGENTS.md) | 글로벌 채택 데이터 0 — 0.1.20 changelog 와 동일 이유 | 영문 사용자 트래픽 가시화 |
