# 0.5.10 — dry-run 이 spec 번호를 태우던 것

> `init-spec-dir.sh --dry-run` 이 "would create" 라고 보고해놓고 **번호를 실제로 예약**했어요.
> 원장 규약이 "한 번 쓰인 번호는 재사용 안 함" 이라 결번이 영구로 남아요. 실사용 리포에서
> dry-run 두 번에 023·024 가 타고 다음 spec 이 025 부터 시작할 뻔했어요.

## 무엇이 바뀌었나

- `init-spec-dir.sh` 가 dry-run 일 때 `next-spec-num.sh` 에 `--dry-run` 을 넘겨요.
  `--reserve` 는 번호 원장 선점 + 디렉토리 생성까지 하는 **쓰기** 라, 안 넘기면 dry-run 이 씁니다.
  jq 없을 때의 계산 fallback 도 같이 넘겨요 — `--reserve` 없이도 `sync_ledger` 가 `.numbers/` 를 만들거든요.
- `RESERVED_BY_US` 는 dry-run 에서 false 로 남겨요. `--dry-run` 만 넘기고 두면 아래 "이미 존재"
  가드가 `[ -e "$DEST" ] && [ "$RESERVED_BY_US" != true ]` 라 통째로 꺼져서, 실재하는 spec 을
  두고 만들 수 있다고 보고해요. 예약을 안 했으면 소유권도 없어요.

예약이 디렉토리를 만드는 설계 자체는 그대로예요 — 동시 세션 번호 경합 방어라서요
(실사용에서 spec 2 쌍·ADR 7 쌍이 겹친 뒤 들어온 장치).

## 행동 변화

연속 dry-run 이 `023`·`024` 대신 `023`·`023` 을 줘요. 예약을 안 하니 당연한 결과이고,
"dry-run 이 약속한 번호 = 실제로 받는 번호" 가 맞는 semantics 예요.

## 왜 못 잡았나

`next-spec-num.sh` 는 `--reserve` 경로와 `sync_ledger` 양쪽에 가드가 이미 있었어요.
§39 도 "`--dry-run` 이 파일을 쓰면 그건 dry-run 이 아니에요" 를 `next-spec-num`·`spec-review`·
`tasks-gate` 세 곳에 대해 검사하고요. **원시 함수는 지켜졌는데 그걸 부르는 합성 지점이
목록에서 빠져 있었어요.**
