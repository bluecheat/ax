# 0.7.4 — 레인의 일부만 맡겨도 원장이 그대로 적어요

## 무엇이 좋아졌나 — 누구에게 체감되나

- **라운드마다 실제로 맡긴 task 만 디스패치로 적혀요.** 예전엔 `--dispatch` 가 레인 이름만 받아서, 그 레인의 미완료
  task 전부에 시각을 찍었어요. 한 실사용 프로젝트(레인 5개 · 워커 4개 동시)에서 한 레인의 8 task 가 실제 기동보다 77분
  먼저 디스패치로 적혔고, 아무도 안 맡은 4 task 가 `dispatched_unreported` 와 완료 게이트의 "보고 안 받은 디스패치" 에
  섞여 경보가 흐려졌어요. 이제 `--dispatch T010,T011` 로 그 task 들만 적어요. `--report` 와 같은 모양이에요.
- **여러 task 를 한 번에 완료 표시해요.** 레인 보고 하나로 여러 task 의 검증이 통과했을 때 `mark-task.sh --task T010,T011`.

## 바뀐 것

- `lanes-dispatch.sh --dispatch <레인 | T010,T011>`
  - 레인 이름이면 기존 동작 그대로예요.
  - task 목록이면 전부 미완료 · 같은 레인에 배정돼 있어야 해요. 아니면(없는 ID · 완료/보류 · 레인 없음 · 여러 레인)
    exit 1 이고 원장은 그대로예요 (`--assign` 과 같은 트랜잭션).
  - 이미 디스패치된 task 를 다시 적으면 시각을 갱신하고 `보고:` 를 지운 뒤 `warnings` 에 적어요. 중복 ID 는 한 번만.
  - 파일 소유 충돌 검사는 그 task 들이 속한 레인 기준이에요.
- `mark-task.sh --task T010,T011` — 트랜잭션(하나라도 없거나 중복이면 무변경), 이미 켜진 것은 `unchanged_tasks`.
  result 에 `tasks` · `lines` · `changed_tasks` · `unchanged_tasks` 를 더했어요. 단일 ID 의 기존 필드는 그대로예요.
- 문서: `spec-implement/references/lane-mode.md` §2 가 task 목록 디스패치를 기본으로 안내해요. `lane` §6 · `spec-implement` §5 ·
  스크립트 README 도 같이 고쳤어요.
