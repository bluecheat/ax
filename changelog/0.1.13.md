# 0.1.13 — MANIFEST install 검증 + rules-tokens 재작성

## 1) `check-manifest-install.sh` 추가 — install 완전성 파일 단위 검증

issue #6 (commerce 프로젝트에서 `.ax/_templates/adr/` 누락) 처럼 plugin 갱신 후 사용자가 install 재실행을 안 해서 출고분이 silently 빠진 채 누적되는 케이스가 doctor 에서 사전 detect 안 되던 결함 보완.

```bash
bash .ax/scripts/bash/check-manifest-install.sh --json [--plugin-dir <path>]
```

- plugin `templates/default/MANIFEST` 의 디렉토리 entry 를 모두 walk
- plugin tpl side 의 각 파일을 사용자 프로젝트와 비교:
  - `missing` — plugin 에 있는데 사용자 프로젝트에 없음 (install gap)
  - `drift` — 양쪽 다 있는데 내용 다름 (수정 또는 plugin 갱신 후 미동기)
- rename entry (`src -> dst` — current-task.json/state.json 등 stateful target) 는 skip
- PLUGIN_ROOT 미해결 시 `status:skipped` 로 graceful degradation

JSON 스키마:

```json
{
  "status": "ok|warning|skipped|error",
  "result": {
    "manifest_path": "<abs>",
    "files_checked": 44,
    "missing": ["rel/path", ...],
    "drift": ["rel/path", ...]
  },
  "next_step": "...",
  "warnings": [],
  "errors": []
}
```

## 5) `docs/reference/rules-tokens.md` 재작성 — 두 scheme 모두 명시 + 미구현 CLI 제거

기존 결함 (commerce 개밥먹기에서 발견):
- Layer 1 (CLAUDE.md) `<scope>:<TIER>:<NNN>` scheme 만 다루고 Cross-cut Spirit 의 `SP-<CAT>-<NNN>` scheme 은 한 줄도 언급 X
- 두 scheme 의 cross-reference 관계 미설명
- `LEVEL` vs `TIER` 단어 혼용 (rules-tokens=LEVEL, CLAUDE.md.template=TIER)
- 미구현 CLI 광고 (`goax rules --json`, `goax find <token>`, `--untokenized`, `--renumber` — `skills/rules/SKILL.md` 본문엔 `--level/--source/--category/find` 만 구현)
- HTML 주석 ADR 링크 권장 — `rule-enforcement.md` 의 `enforced_by:` schema 와 모순, 실제 사용 0건

수정:
- "두 layer, 두 scheme" 섹션 신설 — Layer 1 / Cross-cut Spirit 각각 형식·예시·작성법
- 두 scheme 의 cross-reference 패턴 명시 (CLAUDE.md 본문에 `자세한 룰: .ax/spirit/rules/...`)
- `LEVEL` → `TIER` 통일 (전 plugin 통일)
- `goax rules` skill 의 실 구현 옵션만 기재
- HTML 주석 추천 제거 → `rule-enforcement.md` 위임 명시
