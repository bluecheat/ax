# 0.5.4 — hook 도달 범위: 서브에이전트까지, 턴 끝까지, 그리고 같은 말은 한 번만

> 0.5.x 계획(https://claude.ai/code/artifact/69145dba-4bac-4386-b17e-397058570ec2)의 마지막 판이에요.
> 하네스가 **메인 세션 안에서만** 돌고 있었어요 — 서브에이전트는 Constitution 도 Spirit 도 모른 채 떴고,
> 턴이 커밋 없이 끝나면 완료 게이트는 아무도 안 봤고, 편집마다 같은 룰 포인터가 다시 들어갔어요.
> 이번 판은 그 세 경계를 넘겨요. 스크립트 수는 그대로(36), hook 이 두 종류(`subagent-start/` · `stop/`) 늘었어요.

## `SubagentStart` — 하네스가 서브에이전트에 닿아요

Explore · Plan · general-purpose 같은 내장 서브에이전트와 다른 플러그인의 에이전트는 **새 컨텍스트**로 떠요.
메인 세션은 `@AGENTS.md` 와 훅으로 룰을 받지만 그쪽은 아무것도 몰라요. `harness-pointer.sh` 가 뜨는 순간
`hookSpecificOutput.additionalContext` 로 **경로만** 줘요 — Constitution(시그널 라인을 실제로 가진 쪽) ·
`spirit/values.md`·`tone.md` · 진행 중인 spec/tasks · 인계 노트 · 규율 한 줄(커밋 금지 · 소유 파일 밖 금지 · 정량 주장엔 명령).
goax 자기 에이전트(evaluator·architect·lane-*)는 "시작 전 필수" 로 이미 읽으니 건너뛰어요.
공식 문서로 `agent_type` 입력과 `hookEventName: "SubagentStart"` 중첩을 확인했어요.

## `Stop` — 턴이 끝나기 전에 한 번

완료 게이트 G1~G6 는 파일 게이트라 커밋 시점(`spec-completion-gate.sh`)엔 걸리지만, **커밋 없이 턴이 끝나면**
아무도 안 봐요. `stop/spec-gate.sh` 는 phase 가 `implementing`·`review` 이고 `tasks-gate.sh` 가 위반을 보고할 때
`{"decision":"block","reason":…}` 로 **한 턴만** 더 줘요. 시키는 건 셋 중 하나 — 마저 하기 · `- [~]` 보류 표기 ·
인계 노트에 적고 멈추기. 인계 노트의 "지금 상태" 에 그 spec 이 적혀 있으면 멈추는 게 의도라고 보고 잡지 않아요.

안전장치: `stop_hook_active=true`(재시도)면 무조건 통과(공식 계약이라 무한 루프가 없어요) · 세션당
`GOAX_STOP_GATE_MAX`(기본 8)회 · `sensors.mode=off` 면 침묵 · 계획 단계(spec/tasks)엔 안 잡아요.

## 주입 중복 제거 — 실측 뒤에 만들었어요

계획대로 **먼저 쟀어요.** 이 맥의 트랜스크립트에서 goax 가 설치된 프로젝트를 찾아 `spirit-rules-inject.sh` 의
주입 문자열을 셌어요:

| 세션 | 주입 횟수 | 편집한 파일 | 주입 본문 |
|---|---|---|---|
| 가장 큰 세션 (100MB) | **1,200회** | 196개 | **529KB** |
| 보통 세션 | 121 ~ 246회 | 19 ~ 54개 | 43 ~ 72KB |
| 레인 서브에이전트 하나 | spirit 168 + module 168 | 39개 | 96 + 55KB |

같은 룰 파일 경로가 편집마다 다시 들어간 거예요. 그래서 `common.sh` 에 `goax_inject_fresh` 가 생겼어요 —
`session_id` 마다 `.ax/.session/<sid>/injected/<key>` 마커를 두고 같은 포인터는 4시간(`GOAX_INJECT_TTL`) 안엔
다시 안 줘요. compaction 뒤엔 4시간 TTL 이 다시 줄 여지를 남기고, 세션 id 가 stdin 에 없으면(수동 실행) 예전처럼
매번 줘요. `spirit-rules-inject.sh`(룰 파일 단위) · `module-rules-inject.sh`(모듈 · 활성 spec 단위) 둘 다.
하루 넘은 세션 디렉토리는 지나가며 지워요.

## doctor — 이벤트 키와 인계 노트 기한

- **hook 이벤트 키 검사.** 파일은 `/up` 이 깔았는데 `settings.json` 에 `Stop`·`SubagentStart` 키가 없으면 안 돌아요.
  `doctor-scan.sh hooks.events` 가 template 의 이벤트 키를 SSOT 로 대조해요 — 이름을 hardcode 하지 않아요.
  계획대로 hook 이 생기는 판에 같이 넣었어요 (먼저 넣으면 자기 출고본에 결손을 보고해요).
- **인계 노트 기한.** `STATUS.md` 의 `- [ ] YYYY-MM-DD …` 를 I3 와 같은 규칙(≤7일 임박 · 초과)으로 봐요.
  zero 의 "1순위 가정 검증" 과 "룰 ablation 재검토" 가 여기 살아요 — 날짜가 문서 안에만 있으면 아무도 안 봐요.
- **ablation 주기.** `zero-ablation.sh --on` 이 한 회차의 끝 — `.ax/.ablation-last` 를 적고 다음 기한(+180일)을
  `status-note.sh` 로 STATUS.md 에 체크박스로 넣어요. `--status` 가 마지막 회차·다음 기한을 보여줘요.

## `.omc/` 잔재

plugin 디렉토리 안에서 세션을 연 적이 있으면 OMC 가 `templates/default/.ax/hooks/.omc/` 같은 상태 디렉토리를
만들어요. git 은 `.omc/` 를 무시해서 저장소엔 안 들어가지만, **로컬 plugin 에서 `cp -R` 로 설치하면 사용자
프로젝트의 `.ax/` 안에 남의 상태가 들어갔어요.** `provision.sh` 가 복사 뒤 `.omc` 를 지우고,
`check-manifest-install.sh` 가 열거에서 빼요. smoke 가 tracked 파일에 `.omc` 가 없는지 봐요.
