# 0.7.2 — task 하나를 끝냈는데 본문에 이름만 나온 다른 task 까지 완료로 바뀌던 것

## 무엇이 좋아졌나 — 누구에게 체감되나

- **spec-implement 가 끝낸 task 만 체크해요.** 예전엔 `T009` 를 끝내면 "T009 가 셋 다 해소" 처럼 본문에 `T009` 를 언급한
  다른 task 줄까지 `[x]` 로 바뀌었어요. 한 실사용 프로젝트에서 시작도 안 한 task 3개가 검증 없이 완료가 됐고, 완료 게이트는 그걸
  정상으로 읽었어요. 이제 줄 **앞**의 ID 만 봐요(`- [ ] T013 ` · `**T013**` · `[T013]`).
- **"다음 task" 가 템플릿 예시를 집지 않아요.** tasks.md 의 형식 설명 코드 블록 안 예시(`- [ ] T001 [P] [AC2] <한 줄 설명>`)를
  다음 할 일로 잡던 것을 고쳤어요.
- **레인 작업과 동시에 tasks.md 를 써도 변경이 사라지지 않아요.** 체크 표시가 `lanes-dispatch.sh` 와 같은 락을 잡아요.

## 바뀐 것

- 스크립트: `mark-task.sh` 신설 — `--task T013 [--state x|~]` · `--next`. 줄 앞 ID 만 매칭, 코드 펜스 건너뜀, `tasks.md.lock`,
  쓰기 전후 `[x]` 개수가 정확히 하나 늘었는지 확인(아니면 exit 1). 없는 ID 는 조용히 성공하지 않고 exit 1.
- 스킬: `spec-implement` §1(다음 task) · §5(완료 표시)의 인라인 `grep`·`sed` 를 `mark-task.sh` 로 바꿨어요.
- `spec-review.sh --merge --json` 결과에 `merged_file`.
