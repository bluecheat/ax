# 0.2.4 — triage 4단계 역면접(Reverse Interview) + intent_notes 스키마 실체화

> 구현 시작 전에 놓친 요구사항(규모·실패 모드·경계·성공 기준)을 발굴하는 게이트를 triage 에 추가했어요. Anthropic 엔지니어의 "매일 쓰는 6개 프롬프트" 중 역면접·blind pass 갭을 채우는 개선 (internal tracker ref (removed) upstream 반영). 0단계 인터뷰가 "어느 상자에 넣을지"(분류) 를 물었다면, 4단계는 "만들기 전에 뭘 모르는지" 를 캐요.

## 추가 — `skills/triage/SKILL.md` 4단계 역면접

- **발동 조건** — 3단계 확정 경로가 spec 경로인 셀 (M×L2 이상, L×*, XL×*) 에서만, spec/spec-implement 진입 직전 1회. S×* 와 M×L0~L1 (즉시·inline) 은 스킵해 과잉질문 방지. **L3 는 스킵 금지** — 스킵하면 `.ax/mistakes/` 캡처 대상.
- **질문 축 분리** — [`skills/triage/references/reverse-interview.md`](../skills/triage/references/reverse-interview.md) 신설. 범용 5축 (`scale`/`failure`/`boundary`/`done`/`constraints`) + multiple choice 예시. 프로젝트에 `.ax/docs/reference/reverse-interview.md` 가 있으면 그쪽이 우선 (도메인 특화 축 오버라이드 — 예: 커머스의 동시성·멱등성).
- **blind-pass 흡수** — 낯선 코드베이스/도메인이면 첫 라운드를 질문이 아닌 정찰로 시작. 자주 깨지는 지점·엣지케이스·기존 유사 구현을 먼저 스캔하고, 거기서 나온 구체적 불확실성만 질문으로 변환. 정찰 요약은 `intent_notes.blind_pass` 에 기록.
- **질문 룰 경계 명시** — 0단계 "한 라운드 1문" 은 0단계 한정 (의도 좁히기, 순차) / 4단계는 한 라운드 최대 5문 multiple choice (체크리스트 성격). 두 룰이 문면상 충돌하지 않게 각자 적용 범위를 명시.

## 변경 — `intent_notes` 유령 필드 → 실제 스키마 승격

기존 0단계가 "인터뷰 결과는 `intent_notes` 에 기록" 이라 서술했지만 어느 스크립트·스키마도 이 필드를 기록/관리하지 않던 갭을 해소:

- `current-task.json.template` 에 `"intent_notes": {}` 추가
- 3.5단계 jq 에 `--argjson intent` 병합 추가 — 0단계 답변을 축별 key (`why`/`constraints`/`done`) 로 기록
- `tier-from-state.sh --reset` (= `reset-task.sh`) 이 `intent_notes = {}` 로 초기화
- 4단계 중복 방지가 이 객체의 key 존재를 결정론으로 체크 (`jq keys[]`) — 이미 답한 축 재질문 금지
