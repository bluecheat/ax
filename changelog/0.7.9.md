# 0.7.9 — 레인이 보고·검증 뒤 스스로 정리돼요 · 레인은 시키지 않은 외부 변경을 하지 않아요

## 무엇이 좋아졌나 — 누구에게 체감되나

> 작업을 레인(팀원 에이전트)으로 나눠 돌리는 사람에게 체감돼요.

- **다 끝난 레인이 쌓이지 않아요.** 보고를 받고 검증 명령을 다시 돌려 통과하면 코디네이터가 그 레인을 바로
  종료해요. 전엔 보고 뒤에도 idle 로 남아, 하루에 수십 개가 쌓여 어느 레인이 살아 있는지 헷갈렸어요.
  - 완료 게이트 전에 살아 있는 레인 목록(`ListAgents`)을 한 번 더 보고, 남은 걸 정리해요. 원장 밖에서
    띄운 레인도 이름 접두사(`lane-` · `scout-`)로 잡혀요.
  - 종료가 두 번 실패하면 더 붙잡지 않고 인계 노트에 이름을 남겨요.
  - 종료한 레인도 이름으로 메시지를 보내면 이어서 일해요.
- **레인이 시키지 않은 외부 변경을 하지 않아요.** push · 배포 · 원격 API 쓰기 · 스토어 콘솔 같은 외부 서비스 변경은
  브리프의 "외부 쓰기 허용" 에 적힌 것만 해요 (기본 "없음"). 필요하면 하지 않고 보고에 적어요.
- **종료 응답이 거부되지 않아요.** 레인이 종료 요청에 답할 때 정확한 형식(문자열이 아닌 객체)을 예시로 받아요.

  §5 종료 조건에 살아 있는 레인 0개 · 레인 이름 규칙

- `agents/lane-worker.md` · `lane-scout.md` — 외부 쓰기 금지, 종료 요청에는 응답만(객체 형식)
- `lane/references/incidents.md` 사고 6
