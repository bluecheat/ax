## `.ax/mistakes/` 자기충돌 누적 차단

onboarding 의 합법적 쓰기가 `.ax/` blanket protected_paths 와 unconditional capture 호출 두 결함의 합작으로 mistake 파일을 누적시키던 문제. 두 fix 합:

- `templates/default/.ax/config.yml` — `protected_paths` 를 `.ax/` 통째 → 12 개 구체 경로 (`CLAUDE.md`, `.ax/config.yml`, `.ax/version`, `.ax/state.json`, `.ax/current-task.json`, `.ax/hooks/`, `.ax/scripts/`, `.ax/spirit/values.md`, `.ax/spirit/tone.md`, `.ax/docs/_templates/`, `.claude/settings.json`, `.github/workflows/`)
- `templates/default/.ax/hooks/pre-edit/check-protected-paths.sh` — `capture-mistake.sh` 호출을 `if [ "$SENSOR_MODE" = "fail" ]` 분기 안으로 이동. warning 모드는 stderr 경고만, mistake 파일 X

검증: warning=0 capture / fail=1 capture / 합법 경로 4개 통과 / 진짜 보호 대상 6개 경고 발화

## SSOT 안내 정정

onboarding 마무리 메시지가 `.ax/docs/_templates/spec/` 를 "프로젝트 SSOT" 라고 표기. 잘못된 표현 — 작업 spec 의 SSOT 는 `.ax/docs/spec/NNN-<slug>/spec.md`, `_templates/` 는 *템플릿*. 두 개념을 합치면 사용자가 spec 을 templates 디렉토리에 직접 쓰는 워크플로 misroute 가능.

수정 (`skills/onboarding/SKILL.md` § 5): 섹션 헤딩 변경 + 두 디렉토리 역할 분리 명시 + 명시적 경고 추가.

## @import 동작 — 공식 문서 정합성

`@import` 옵션 안내에 documented 안 된 클레임 정정 (docs.claude.com 대조):

- ❌ 제거: `enabledImports` settings.json 키 — **존재하지 않는 키**
- ❌ 제거: "거절 후 `permissions.allow` 로 복구 가능" — 권한 시스템과 import 시스템은 별개. 공식 문서에 documented 된 자동 복구 path 없음
- ✅ 추가: external import 정의 (`@~/.claude/foo.md` 같은 외부 경로) 명시
- ✅ 추가: 우리가 prepend 하는 4개 라인은 모두 프로젝트 *내부 상대경로* 라 dialog 대상 아님
- ✅ 추가: 5 hop 재귀 한도, `permissions.deny` 정확 문법 (`"deny": ["Edit(./.ax/config.yml)"]`)

## Hook 패턴 modernization

Claude Code 공식 modern hook patterns 적용:

- `check-protected-paths.sh` 의 fail 모드 차단을 `exit 2 + stderr` → `exit 0 + stdout JSON` 으로 전환. JSON shape: `{hookSpecificOutput: {hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason: "..."}}`. Claude 가 error 가 아닌 정책적 거부로 인식, reason 깔끔하게 surfacing. jq 없는 환경 fallback 은 `exit 2` 유지
- `tool_input.file_path` jq 추출에 `.tool_input.notebook_path` fallback 추가 → NotebookEdit 도구도 동일하게 보호 경로 검사

## 카운트 검증 메서드 명시

`SKILL.md` § 4 에 검증 메서드 추가 — 사용자에게 보고하는 정량 클레임이 raw grep 노이즈를 포함하지 않도록:

- 시그널 카운트: legend 제외, `<scope>:(CRITICAL|MANDATORY|CONVENTION):[0-9]+ | sort -u | wc -l` 같은 unique 룰 토큰 기준
- `domain_risk` key 카운트: 인덴트 `-` prefix 라인이 아닌 실제 키 라인 (`awk` 범위 추출 후 `^[[:space:]]+[a-z][...]:` 매칭)
- 룰 토큰 카운트: 출현 횟수와 unique ID 개수 구분 — "토큰 N개" 는 unique 가 정상 의미

## Critical-rule grep — Kotlin domain dead code 수정

`templates/default/.ax/hooks/pre-commit/critical-rule-grep.sh` 의 Kotlin `var`-in-domain 검출이 `grep -n` 출력 stream 에 다시 `grep -qE 'domain/(model|entity)'` 를 거는 형태였음 — 영원히 안 켜지던 dead code.

수정: `echo "$f" | grep -qE 'domain/(model|entity)' && grep -qE '...' "$f"` — 파일 경로 먼저 검사 후 본문 var 검출.

검증: domain/model/User.kt 의 var 검출 ✓ / util/Helper.kt 의 var 통과 ✓
