# 0.4.2 — 검색이 슬러그를 넘어서고, 설치가 파일이 됐어요

> 공개 후 첫 점검에서 나온 것들이에요. 관통하는 게 하나 있어요 —
> **선언한 규칙을 정작 코드가 안 지키고 있었어요.** 결정론은 스크립트로 간다더니
> 제일 큰 코드가 마크다운 안에 있었고, 6군데를 검색한다더니 spec 은 이름만 봤어요.

## 수정 — 관련 문서를 못 찾고 있었어요

**specs 를 디렉토리 *이름* 으로만 매칭했어요.** `triage-search.sh` 는 adrs·mistakes·
rules·imported 를 전부 본문 랭킹하는데 specs 만 `find -type d | grep` 이었어요.
슬러그에 도메인 단어가 없고 본문에만 있는 spec 은 영영 안 나왔어요.

한국어 프로젝트에선 이게 더 심했어요. 슬러그는 영문 kebab-case 규약이라
`009-settlement` 의 본문이 "정산" 이어도 **"정산" 으로 검색하면 0건**이었어요.
"동일 도메인이면 같이 검토" 라는 설계가 여기서 통째로 샜어요.

→ 본문 랭킹 + 스니펫으로 전환. 디렉토리명 매칭은 강한 신호라 boost 로 남겨서
기존 결과 순위는 그대로예요. BM25 인덱스가 이미 `spec.md` 를 `spec` 카테고리로
색인하고 있었는데 읽는 데가 없었어요 — 대형 코퍼스에선 그 후보도 union 해요.

**후보는 대소문자 무시로 뽑고 점수는 대소문자 구분으로 매겼어요.** `grep -ril` 로
listing 한 뒤 `grep -cE` 로 재채점해서, 키워드가 **대문자로만** 등장하는 문서는
후보에 올랐다가 점수 0으로 조용히 탈락했어요. adrs·mistakes·rules·imported
**전부** 해당됐어요. `Payment`·`Refund` 처럼 영문 고유명사가 문장 앞이나 제목에
오는 흔한 경우가 그대로 누락이었어요. → 재채점도 `-i`.

**`spec`·`adr` skill 이 스크립트를 안 부르고 자기가 grep 했어요.** 그런데 그
인라인 grep 은 본문을 봤어요 — 좋은 스크립트가 못 하던 걸 하고 있었던 거예요.
배선이 빠진 게 아니라 배선할 수가 없었어요. 스크립트를 고친 뒤 둘 다
`triage-search.sh --json` 호출로 교체했어요. 동의어 확장·랭킹·스니펫·6카테고리가
따라와요.

## 이동 — 설치 로직이 파일이 됐어요 (`scripts/provision.sh`)

`skills/up/SKILL.md` §4 는 **266줄짜리 설치 프로그램**이었어요. MANIFEST 파싱,
sha 비교, 사용자 수정본 백업·복원, seed-only 분기가 전부 ```` ```bash ```` 블록
안에요. 이 리포 자신의 규칙과 정면으로 부딪혀요.

설계 위반보다 실질적인 문제가 있었어요 — **마크다운 안의 bash 는 파일이 아니라서
어떤 검사도 안 닿아요.** smoke §7 의 `bash -n` 은 `templates/**/*.sh` 만, §19 의
bash 호환 lint 는 `templates|tests|.claude` 만 봤어요. `skills/` 는 둘 다 대상
밖이었어요. 이틀 전 CI 를 깨뜨린 `${#ARR[@]:-0}` 를 `up/SKILL.md` 에 썼다면
그대로 통과했을 거예요. 하필 사용자가 제일 먼저 돌리는 코드고요.

→ `scripts/provision.sh` (`--json --dry-run --help`). `up` §4 는 273줄 → 44줄.
`up/SKILL.md` 전체가 460 → 231줄.

plugin 루트에 두는 이유는 이 스크립트가 `.ax/` 를 *만드는* 쪽이라서예요. 실행
시점엔 `.ax/scripts/bash/` 가 아직 없어요.

**부수 개선 — `.suggested` 소음.** 예전엔 재실행마다 내용이 같아도 조건부 자산
9개에 전부 `.suggested` 를 붙였어요. 사용자는 곧 전부 무시하게 되고, 그러면 정말
봐야 할 diff 도 같이 묻혀요. 이제 실제로 다를 때만 만들어요 (customize 0건이면
0개). `AGENTS.md` 는 `[PROJECT_NAME]` 치환본과 비교해요 — 원본 템플릿과 비교하면
신규 설치 직후에도 늘 "다름" 이 떠요.

## 검증 — 문자열 매칭을 행동 검증으로

**smoke §30 신설.** `skills/`·`commands/` 의 ```` ```bash ```` 블록을 뽑아 `bash -n`.
현재 62블록 전부 통과하고, 앞으로 SKILL.md 에 문법 오류가 들어가면 CI 가 잡아요.
§19 의 bash 호환 lint 범위에도 `skills/`·`commands/` 를 넣었어요.

**§20 을 실제 실행으로 바꿨어요.** 0.4.1 이 고친 "재실행이 진행 중 상태를 파괴"
회귀 테스트가 `up/SKILL.md` 를 grep 하는 문자열 매칭이었어요. 그건 "그 문장이
있다" 만 보증하지 "그렇게 동작한다" 는 보증 못 해요. 이제 `provision.sh` 를 임시
프로젝트에 **두 번 돌려서** phase 보존과 `_templates` 수정본 보존을 직접 확인해요.

**§7 `bash -n` 범위에 plugin 루트 `scripts/` 추가.**

**smoke §20 제목의 백틱이 명령 치환으로 실행되고 있었어요** — 매 실행마다 stderr 에
syntax error 를 뱉고 제목의 `` `->` `` 가 사라졌어요. 테스트는 통과해서 안 보였고요.
