# 0.1.8 — capture 안전성 + install upgrade-safe (mistake loop 기반 다지기)

> v0.1.7 다음 큰 그림: weekly Routines로 mistake → 룰 승격 자동화. 0.1.8은 그 전제가 되는 *capture 측 신뢰성*과 *plugin re-install upgrade safety*에 집중. Routine 표면(자동 commit, audit PR 자동 생성)은 의도적으로 0.1.9+로 연기 — 검증 후 단계적 도입.

## 1) capture-mistake.sh — race-free ID

기존: `${DATE}-${NUM_PAD}-...` 포맷. NUM은 `find ... | wc -l`로 산정 → 동시 캡처 시 같은 NUM 부여 가능 (race).

수정: `${DATE}-${EPOCH_MS}-${PID}-${RANDOM}-...`. ms 정밀도 + PID + bash $RANDOM. 5병렬 호출 → 5개 고유 파일 (smoke section 10.1 검증).

호환: idempotent glob `${DATE}-*-${CATEGORY}-${SLUG}.md`는 옛 포맷·새 포맷 모두 매치. 0.1.7 누적분 그대로 유지.

```bash
# old
NUM=$(find "$MISTAKES" -maxdepth 1 -type f -name "${DATE}-*.md" | wc -l)

# new — race-safe
EPOCH_MS=$(python3 -c 'import time; print(int(time.time()*1000))')
TS="${EPOCH_MS}-$$-${RANDOM}"
FILE="$MISTAKES/${DATE}-${TS}-${CATEGORY}-${SLUG}.md"
```

## 2) common.sh — `redact_secrets()` (write-time secret sanitizer)

mistake 파일에 secret이 평문으로 박히면 git-tracked policy(아래 §4)와 충돌. capture-mistake.sh가 write 직전 DETAILS만 sanitize.

전략: known-prefix 토큰(고신뢰) + key=value(≥12자 entropy).

| 카테고리 | 패턴 | 치환 |
|---|---|---|
| AWS access key | `AKIA[A-Z0-9]{16,}` | `[REDACTED:aws]` |
| GitHub PAT | `gh[poshru]_[A-Za-z0-9]{20,}` | `[REDACTED:github]` |
| Slack | `xox[baprs]-[A-Za-z0-9-]{10,}` | `[REDACTED:slack]` |
| Stripe | `(sk\|pk\|rk)_live_[...]{20,}`, `whsec_` | `[REDACTED:stripe]` |
| JWT | `eyJ...\....\....` | `[REDACTED:jwt]` |
| PEM begin | `-----BEGIN[^-]*PRIVATE KEY-----` | `[REDACTED:pem-begin]` |
| key=value | `(api_key\|secret\|password\|token\|bearer\|pg_key)\s*[:=]\s*[A-Za-z0-9+/=_-]{12,}` | `\1\2[REDACTED]` |

핵심 design choice — **`$ONE_LINE`(타이틀)은 redact 미적용**. "PG 키 평문 누출 의심" 같은 시그널을 "[REDACTED] 누출 의심"으로 만들면 audit 시 분류 불가. `$DETAILS`만 sanitize.

False positive 방어: 식별자(`password_field`, `tokenizer`) 보존, 값 길이 <12자(`pw=ok`)는 미치환. smoke section 10.5 검증.

## 12) **Path-scoped rule injection** — hook 기반, `.ax/`-only (Design B)

기존: 모든 spirit/rules/*.md 를 CLAUDE.md `@import` → 작업 무관하게 매 turn 컨텍스트에 주입. 9 파일 합산 ~12K tokens, 공식 권장 "200 lines/file" 5.8x 초과로 adherence 손상.

수정: spirit/rules/*.md frontmatter에 `paths:` 선언 + `pre-edit/spirit-rules-inject.sh` hook이 편집 대상 파일과 glob 매칭 → 매칭된 룰 파일 경로를 `additionalContext`로 LLM에 안내 → Claude가 lazy Read.

```yaml
# spirit/rules/commerce-domain.md
---
category: domain
paths:                          # ← 신규
  - "**/domain/**"
  - "**/*Entity*.kt"
applies_to: [code]
---
# Commerce Domain Rules
## SP-DOM-001: ...
```

```bash
# .ax/hooks/pre-edit/spirit-rules-inject.sh — PreToolUse(Edit|Write|MultiEdit)
# stdin: {tool_input.file_path}
# stdout: {hookSpecificOutput:{hookEventName:"PreToolUse",additionalContext:"📋 Path-scoped...\n- .ax/spirit/rules/commerce-domain.md\n"}}
```

**핵심 설계**:
- spirit/rules는 SSOT, hook이 path-scoped 매칭 + additionalContext 주입
- **`.claude/rules/` 의존성 0** — `.claude/`를 gitignore하는 팀에서도 100% 동작
- 모든 자산 `.ax/` 거주 (`spirit/rules/` + `hooks/pre-edit/`), 등록은 이미 tracked인 `.claude/settings.json`
- B-pointer 모드: hook은 룰 파일 path만 알림 → Claude가 필요 시 Read (lazy, token 효율)
- glob 매칭은 python으로 `**` 처리 정확 (jq 부재 시 fallback도 minimal)

**효과**: presenter 작업 시 domain 룰 안 옴, 반대도 마찬가지. token cost ~30~40% 감소 + adherence 개선. 매 Edit/Write/MultiEdit마다 hook 실행 (수ms 오버헤드 — 무시 가능).

**왜 shim 메커니즘이 폐기됐나** (Design A → B): `.claude/rules/`는 `.claude/`를 gitignore하는 팀(흔함)에서 per-machine 일관성 보장 X. 한 dev은 shim 가지고 다른 dev은 없으면 path-scoped 룰이 일부에게만 주입되는 silent inconsistency. hook은 `.claude/settings.json` (이미 tracked) 한 곳만 의존 → 일관 동작.

연관 파일:
- `templates/.../hooks/pre-edit/spirit-rules-inject.sh` — 매칭·additionalContext 출력
- `templates/.../.claude/settings.json.template` — PreToolUse(Edit|Write|MultiEdit)에 hook 등록

## 28) Plugin ↔ commerce 분기 통일 (보강)

commerce 측 코드 비교 결과 두 영역에서 commerce 디자인이 더 견고. plugin이 commerce 패턴 채택:

### `common.sh` JSON helper 명명 통일
- `_json_array_helper` (stdin) → `_goax_json_array` (arg-based, `_goax_*` prefix 일관)
- caller 코드도 깔끔: `errs=$(_goax_json_array "$msg")` vs 이전의 `printf | helper` 파이프

### `block-destructive.sh` rm 패턴 broader catch
- 기존 `-[rRfF]*[rR][rRfF]*` (r/R 필수) → `(-[rRfFvV]+[[:space:]]+)*-[rRfFvV]+` (multi-chunk + v)
- 신규 catch:
  - `rm -rfv /` (verbose 추가)
  - `rm -r -f /` (분리된 flag chunk)
  - `rm -v -rf /` (chunk 순서 변경)
  - `rm -fvR /` (대소문자·v 혼합)
- 검증 8개 변종: 6개 차단 + 비-recurse (`rm /tmp/x`, `rm -v /tmp/x`) 통과

## 27) PR review 종합 fix — 8개 (commerce PR #1085 review 반영)

PR review (chatgpt-codex P1/P2 + coderabbit Critical/Major/Minor) 반영. 진짜 보안·correctness 버그 + commerce에 이미 fix됐던 내용을 plugin으로 backport.

### 보안 fix (P1)
- **block-destructive.sh**: `rm -rf?` regex가 `rm -fr /` 미차단 → `rm[[:space:]]+-[rRfF]*[rR][rRfF]*[[:space:]]+/` (flag 안에 r/R 필수). `-fr`/`-rf`/`-Rf`/`-fRr` 모두 catch

### Cross-platform fix (P1)
- **update-state.sh**: `date -u -r EPOCH` BSD 전용 → BSD 우선 + `date -u -d @EPOCH` GNU fallback. Linux/Routine에서 실패하던 ISO 변환 정상

### JSON escape fix (P2)
- **common.sh**: `json_error` / `json_skip` 가 `"[\"$msg\"]"` 직조립으로 따옴표/역슬래시 미escape → `_json_array_helper()` 헬퍼 신설 (jq 우선, sed fallback). 메시지에 quote/backslash 있어도 JSON 안전

### Validation 강화
- **next-spec-num.sh**: 999개 spec 초과 시 silent overflow → `NEXT_NUM > 999` 명시 에러. NNN-* 3자리 규약 위반 차단

### Code reuse
- **common.sh**: `goax_error` JSON_MODE-aware. JSON_MODE=true 면 stdout JSON 한 줄 emit, 아니면 stderr — caller가 `--json` flag 처리 일관
