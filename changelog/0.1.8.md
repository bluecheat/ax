# 0.1.8 — capture 안전성 + install upgrade-safe (mistake loop 기반 다지기)

> v0.1.7 다음 큰 그림: weekly Routines로 mistake → 룰 승격 자동화. 0.1.8은 그 전제가 되는 *capture 측 신뢰성*과 *plugin re-install upgrade safety*에 집중. Routine 표면(자동 commit, audit PR 자동 생성)은 의도적으로 0.1.9+로 연기 — 검증 후 단계적 도입.

## 1) capture-mistake.sh — race-free ID

기존: `${DATE}-${NUM_PAD}-...` 포맷. NUM은 `find ... | wc -l`로 산정 → 동시 캡처 시 같은 NUM 부여 가능 (race).

수정: `${DATE}-${EPOCH_MS}-${PID}-${RANDOM}-...`. ms 정밀도 + PID + bash $RANDOM. 5병렬 호출 → 5개 고유 파일 (smoke section 10.1 검증).

호환: idempotent glob `${DATE}-*-${CATEGORY}-${SLUG}.md`는 옛 포맷·새 포맷 모두 매치. 0.1.7 누적분 그대로 유지.

```bash
# old
NUM=$(find "$MISTAKES" -maxdepth 1 -type f -name "${DATE}-*.md" | wc -l)

# new — race-safe
EPOCH_MS=$(python3 -c 'import time; print(int(time.time()*1000))')
TS="${EPOCH_MS}-$$-${RANDOM}"
FILE="$MISTAKES/${DATE}-${TS}-${CATEGORY}-${SLUG}.md"
```

## 2) common.sh — `redact_secrets()` (write-time secret sanitizer)

mistake 파일에 secret이 평문으로 박히면 git-tracked policy(아래 §4)와 충돌. capture-mistake.sh가 write 직전 DETAILS만 sanitize.

전략: known-prefix 토큰(고신뢰) + key=value(≥12자 entropy).

| 카테고리 | 패턴 | 치환 |
|---|---|---|
| AWS access key | `AKIA[A-Z0-9]{16,}` | `[REDACTED:aws]` |
| GitHub PAT | `gh[poshru]_[A-Za-z0-9]{20,}` | `[REDACTED:github]` |
| Slack | `xox[baprs]-[A-Za-z0-9-]{10,}` | `[REDACTED:slack]` |
| Stripe | `(sk\|pk\|rk)_live_[...]{20,}`, `whsec_` | `[REDACTED:stripe]` |
| JWT | `eyJ...\....\....` | `[REDACTED:jwt]` |
| PEM begin | `-----BEGIN[^-]*PRIVATE KEY-----` | `[REDACTED:pem-begin]` |
| key=value | `(api_key\|secret\|password\|token\|bearer\|pg_key)\s*[:=]\s*[A-Za-z0-9+/=_-]{12,}` | `\1\2[REDACTED]` |

핵심 design choice — **`$ONE_LINE`(타이틀)은 redact 미적용**. "PG 키 평문 누출 의심" 같은 시그널을 "[REDACTED] 누출 의심"으로 만들면 audit 시 분류 불가. `$DETAILS`만 sanitize.

False positive 방어: 식별자(`password_field`, `tokenizer`) 보존, 값 길이 <12자(`pw=ok`)는 미치환. smoke section 10.5 검증.

## 3) install — `.ax/config.yml` 조건부 복사 (upgrade-safe)

기존: MANIFEST에 `.ax/config.yml`을 무조건 cp 항목으로 등재 → plugin re-install 시 사용자의 `domain_risk`·`commands`·`sensors` customization을 clobber.

수정:
- MANIFEST에서 `.ax/config.yml` 제거
- `install` SKILL §6.5 신설 — `[ -f .ax/config.yml ]`이면 `.ax/config.yml.suggested`로, 아니면 그대로 cp. CLAUDE.md/.claude/settings.json과 동일한 conditional 패턴.

영향: 새 install은 동작 동일. 기존 v0.1.7 사용자가 0.1.8로 re-install해도 자기 config 보존.

## 4) `.ax/mistakes/` git-tracked 정책 명시

mistake loop는 **팀 단위 패턴 누적이 가치의 핵심** — gitignore하면 audit이 사실상 1인 회고로 전락 (threshold 영영 미달, scheduled audit이 빈 디렉토리 봄). 0.1.8부터 `mistakes/README.md`에 정책을 명시:

- `.ax/mistakes/*.md` 는 **git-tracked**.
- 보호 4겹: §1 race-free ID + §2 redactor + 익명화 컨벤션(`goax-bot` author 권장) + 별도 commit 분리.
- `_local/` 슬롯은 **도입하지 않음** — 시그널 분산 회피.

## 5) common.sh — `goax_hook_report()` 헬퍼 추가

`goax_hook_exit`은 단발성(즉시 exit) hook용. 배치 hook(여러 위반 누적 후 한 번에 결정)이 필요한 케이스를 위해 비차단 변형 추가. caller가 종료 결정. 기존 hook은 0.1.8에선 미적용 — 신규 hook이 활용.

## 6) tests/smoke.sh

- §2.5 헤더 백틱 노이즈 fix (`'goax-' prefix`로 quote)

## 8) `spirit/rules/output-style.md` 출고 제거 (B2)

## 11) doctor — 0.1.8 마이그레이션 잔재 점검 (A11)

기존 v0.1.7 install이 0.1.8 신규 항목(.gitignore 4 entries, output-style.md 제거, .suggested 처리)을 갖추도록 안내. doctor SKILL §3.6 신설:

```bash
# .gitignore 누락 엔트리 검출
NEED_GITIGNORE=()
for line in ".ax/state.json" ".ax/current-task.json" ".ax/*.suggested" ".ax/.onboarding-pending"; do
    grep -qxF "$line" .gitignore 2>/dev/null || NEED_GITIGNORE+=("$line")
done

# output-style.md 잔재
[ -f .ax/spirit/rules/output-style.md ] && HAS_STALE=true

# 미처리 .suggested 잔재
SUGGESTED=$(find .ax -maxdepth 2 -name "*.suggested" 2>/dev/null)
```

자동 수정 X — 사용자가 `[m] 0.1.8 마이그레이션 처리` 옵션 선택 시에만 실행. output-style.md 제거는 git commit 영향이라 사용자 컨텍스트에서만.

## 12) **Path-scoped rule shim** — Claude Code 네이티브 활용 (Design A)

기존: 모든 spirit/rules/*.md 를 CLAUDE.md `@import` → 작업 무관하게 매 turn 컨텍스트에 주입. 9 파일 합산 ~12K tokens, 공식 권장 "200 lines/file" 5.8x 초과로 adherence 손상.

수정: spirit/rules/*.md frontmatter에 `paths:` 선언 → `generate-rule-shims.sh` 가 `.claude/rules/<name>.md` shim 자동 생성 → Claude Code 네이티브 path-scoped loading. paths 매칭 작업 시에만 룰 컨텍스트 주입.

```yaml
# spirit/rules/commerce-domain.md
---
category: domain
paths:                          # ← 신규
  - "**/domain/**"
  - "**/*Entity*.kt"
applies_to: [code]
---
# Commerce Domain Rules
## SP-DOM-001: ...
```

```bash
# install §6.9 자동 호출
bash .ax/scripts/bash/generate-rule-shims.sh
# → .claude/rules/commerce-domain.md 생성 (shim, spirit이 SSOT)
```

**핵심 설계**:
- spirit/rules는 SSOT, `.claude/rules`는 generated artifact
- paths 없으면 shim 생성 안 함 — universal 룰은 CLAUDE.md @import 그대로
- paths 추가만으로 룰을 path-scoped로 전환 가능 (gradual)
- shim 형식: `@../../.ax/spirit/rules/<name>.md` 로 spirit 본문 참조 — 룰 본문 중복 X

**효과**: presenter 작업 시 domain 룰 안 옴, 반대도 마찬가지. token cost ~30~40% 감소 + adherence 개선.

스크립트 옵션:
- `--dry-run` : 변경 미리보기
- `--clean` : paths가 제거된 룰의 stale shim 정리
- `--json` : skill 위임용 구조화 출력

## 13) `update-state.sh` CONVENTION 카운트 패턴 보강

기존: `^🔵 \*\*\`` 인라인 형식만 grep — heading 형식(`^## SP-CAT-NNN: text`, plugin 컨벤션) 미카운트. spirit/rules에 88 룰 있어도 HUD/state.json `convention=0`.

수정: 두 패턴 합산.
```bash
CONV_SPIRIT_HEAD=$(grep -hE '^## SP-[A-Z]+-[0-9]{3}:' .ax/spirit/rules/*.md | wc -l)
CONV_SPIRIT_INLINE=$(grep -hE '^🔵 \*\*`' .ax/spirit/rules/*.md | wc -l)
CONV_SPIRIT=$((CONV_SPIRIT_HEAD + CONV_SPIRIT_INLINE))
```

영향: 0.1.7 inline-only 호환 유지 + 0.1.8+ heading 형식 정확 카운트.

## 14) `doctor` §3.7 — spirit lint + shim drift

신설 점검 항목:

## 15) `find_project_root` — `CLAUDE_PROJECT_DIR` 우선 honor

`common.sh::find_project_root` 가 pwd ancestor만 탐색 → 다른 cwd에서 호출 시 (smoke fixture, hooks from subdirectory) `.ax/` 못 찾음. 이제 `$CLAUDE_PROJECT_DIR` env 가 있고 거기 `.ax/` 있으면 우선 사용. 비파괴적 (없으면 기존 ancestor 탐색 fallback).

## 16) install §6.9 — shim 자동 생성

install이 끝나기 전에 `generate-rule-shims.sh` 호출. 첫 install/재설치 모두 spirit frontmatter 기반 shim 최신화. 사용자가 paths를 spirit/rules에 채워두면 다음 install 또는 doctor 호출 시 자동 반영.

## 17) onboarding — paths frontmatter 가이드 추가

새 spirit/rules/*.md 작성 시 `paths:` 선언 패턴 인지. universal vs path-scoped 결정을 onboarding 단계에서 명시.

## 0.1.9+로 연기된 항목 (의도적)

| 항목 | 이유 |
|---|---|
| auto-commit on capture | rebase/merge/sign/recursion · core.hooksPath 충돌. Routine 워크플로 YAML에서 `git add && commit && PR` 처리하는 게 분리 명확. |
| `GOAX_AUDIT_BOT` env bypass | env는 subshell로 leak. HMAC 토큰 또는 path-only allowlist로 재설계 후. |
| `lint-changed.sh`를 fail-routing | 모든 ESLint warning이 mistake가 되면 noise floor 폭발 → threshold 의미 손실. severity tier 도입 후. |
| `goax doctor --upgrade` | 기존 install의 누락 키 진단·갱신 흐름. 별도 PR. |
| `state.json` flock | 동시성 보호. 현재 `mv` atomic으로 last-writer-wins. 수치 카운트라 자연 회복. |
| Routine smoke (실 발화 검증) | docs는 "full Claude Code session"이라고만 명시 — `.claude/settings.json` hooks가 ephemeral sandbox에서 실제 발화하는지 첫 Routine 한 번 굴려서 확인 필요. |

## 호환성

- 동작 변경 없음. 새 install·재설치 모두 안전.
- v0.1.7 누적된 mistake 파일은 그대로 동작 (idempotent glob 호환).
- `.ax/config.yml` · `.ax/mistakes/README.md` clobber 위험 제거 — 0.1.7 사용자가 0.1.8로 re-install해도 customization 유지.
- 기존 0.1.7 install — `.gitignore` 4 entries 누락 / `spirit/rules/output-style.md` 잔재 / 미처리 `.suggested` 는 `goax doctor` 실행 시 [m] 옵션으로 일괄 정리 가능 (자동 X).
