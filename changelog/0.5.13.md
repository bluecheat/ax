# 0.5.13 — `spec-completion-gate.sh` 가 spec 없는 triage 직후 매 커밋마다 jq 에러를 찍던 것

> `phase != idle` 인데 `spec_id`·`spec_dir` 이 아직 없는 구간(`triage` 직후, `/spec` 이전)에서
> `tasks-gate.sh --json` 은 `{"status":"skipped","result":{},...}` 를 돌려줘요 — "검사할 spec 이
> 없다" 는 정상 신호예요. 그런데 hook 의 가드 `jq -e '.result'` 는 `{}` 도 참으로 봐서 통과시키고,
> 그 다음 `.result.ac_uncovered` 를 읽는 줄이 `null` 을 배열처럼 돌려고 해서 `jq: error … Cannot
> iterate over null` 을 매 `git commit` 마다 stderr 에 찍었어요. exit code 는 0 이라 커밋 자체는
> 안 막았지만, triage 만 하고 아직 spec 을 안 쪼갠 동안은 커밋할 때마다 이 에러가 보였어요.

## 무엇이 바뀌었나

- **`spec-completion-gate.sh`** — `OUT` 을 받은 직후 `.status` 를 봐요. `ok`·`warning` (실제 검사
  결과가 있는 상태) 이 아니면 (`skipped`·`error`, `result` 가 항상 `{}`) 그대로 조용히 통과해요 —
  `tasks-gate.sh` 가 이미 자기 `next_step` 으로 사유를 말하니 hook 이 또 말할 게 없어요.
- 같은 줄의 `ac_uncovered` 읽기도 `(.result.ac_uncovered // []) | join(", ")` 로 굳혔어요 —
  바로 아래 `dispatched_unreported`·`done_without_report` 와 같은 스타일. `status` 가드로 이미
  걸러지지만, 이중 방어예요.

## 검증

- 재현: `echo '{"status":"skipped","result":{}}' | jq -r '.result.ac_uncovered | join(", ")'` →
  `jq: error … Cannot iterate over null (null)`.
- `main`(0.5.12) 의 원본 hook 을 fixture 에 그대로 올려 `current-task.json` 을
  `{"phase":"triaged"}` 로 두고 실행 → stderr 에 위 jq 에러, exit 0 (재현 확인). 같은 fixture 에
  수정본을 올리면 stdout+stderr 모두 빈 문자열, exit 0.
- `status:"warning"` (실제 위반이 있는 정상 케이스) 은 fixture 로 별도 확인 — AC 커버리지 누락 +
  미완료 task 가 있는 spec 에서 여전히 경고 메시지가 그대로 출력됨 (이 변경이 본래 목적인 위반
  가시화를 죽이지 않았음을 확인).
- smoke — 새 픽스처 1개 추가: `spec-completion-gate — phase=triaged·spec 없음이면 jq 에러 없이
  조용히 통과` (기존 `phase=idle` 픽스처 옆). 수정 전 hook 으로는 이 픽스처가 실패함을 먼저 확인.
  591 → 592 통과 / 0 실패 (환경마다 조건부로 실행되는 검사가 있어 0.5.12 changelog 의 592 와는
  기준선이 다를 수 있어요 — 이번 실행 기준 +1).
