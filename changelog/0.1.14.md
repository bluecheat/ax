# 0.1.14 — Confirmation Friction Policy

## 핵심 변경

per-task `[y/n]` 무차별 적용을 **데이터 기반 결정 정책**으로 대체. `tier × risk × mistake-recurrence × enforced_by-coverage × Spirit 카테고리` 의 5변수 조합으로 게이트 강도가 자동 결정.

## 왜 (Why)

기존 `spec-implement` 가 task 18개 spec 에 대해 매 task 시작 전·후 `[y/n]` → **확인 36회**. 사용자 피로감 누적. 더 본질적으로:

- spec-validate / spec-tasks 가 이미 **1회 게이트**로 계약을 닫는데, implement 만 **N회 재개봉** → SSOT 원칙(`CONCEPTS.md` §5.4) 위반
- triage 의 size × risk **5단계 차등**이 implement 단계에서 평탄화됨 → Layer 0 무력화
- Spirit + hooks + Mistake Loop 의 **3중 안전망** 위에 task 게이트를 더하는 건 defense-in-depth 가 아니라 paranoid duplication

## 무엇 (What)

### 신규 — `docs/reference/confirmation-policy.md`

5개 Decision Rules SSOT:
- C1 tier 기반 게이트 빈도 (basic 0회 / standard Phase 경계 / full Phase + ADR-touching)
- C2 sensors.mode 와 autopilot 매핑
- C3 Mistake 재발 escalation (≥3 카테고리 강제)
- C4 enforced_by coverage (≥0.8 autopilot, <0.5+L2 강제)
- C5 Spirit 카테고리 severity (SP-SEC/DATA + L3 = mode 불문 강제)

### 신규 — `.ax/config.yml` `confirmation:` 섹션

```yaml
confirmation:
  mode: phase_gate              # phase_gate | per_task | autopilot
  l3_override: per_task         # L3 도메인은 mode 불문 task 게이트
  mistake_threshold: 3
  spirit_severity_gate: true
```

### 갱신 — `skills/spec-implement/SKILL.md`

- §2 task 시작 전 `[y/n]` 제거 → Phase 경계 게이트 + L3/SP-SEC 강제 게이트
- §6 task 완료 후 `[y/n]` 제거 → silent `[x]` 마킹 + Phase 경계에서만 정보 밀도 출력
- §122 절대 금지 갱신 — "한 task 씩 사용자 확인" → "Phase 경계·실패·L3 SP-SEC 매칭 task 만 게이트"

### 갱신 — `skills/triage/SKILL.md` §3

- 매트릭스 코너 케이스 (S×L0, L×L3 등 결정 명확) → 메뉴 출력 X, 권장 1줄
- 모호 영역 (M×L2 등) → 기존 `[a]/[b]/[c]/[d]` 메뉴 유지

### 갱신 — `docs/reference/triage-matrix.md`

각 매트릭스 셀에 friction 모드 (`autopilot` / `phase_gate` / `per_task`) 표시.

### 갱신 — `CONCEPTS.md` §5

Engineering Principle 6 추가: "Confirmation Friction Policy". 4계층 권한 위임 모델에서 반복 게이트가 왜 책임 충돌인지의 design rationale.

## 보호 장치 (외부 도구는 안 한 부분)

critic 입장의 우려를 흡수:

1. **Default = `phase_gate`** (supervised) — autopilot 은 사용자가 의식적으로 선언해야 발동
2. **L3 도메인은 mode 불문 게이트** — `l3_override: per_task` 가 기본값. critic 의 "L3 위험 무감각" 우려 차단
3. **Mistake recurrence 동적 강화** — 같은 카테고리 ≥3 누적 시 자동으로 그 카테고리 task 게이트
4. **Phase 경계 게이트는 정보 밀도 풍부** — 형식적 [y/n] 이 아니라 *이전 Phase 결과 + 다음 Phase 파일 + 적용 룰 delta* 출력

## 마이그레이션

기존 사용자는 자동 호환. `.ax/config.yml` 에 `confirmation:` 섹션이 없으면 `mode: phase_gate` 가 기본값. 구버전 동작을 유지하려면 `mode: per_task` 명시.

```yaml
# 기존 동작 유지하려면
confirmation:
  mode: per_task
```
