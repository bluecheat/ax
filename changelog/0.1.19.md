# 0.1.19 — audit §4.2 압축·탈맥락 원칙 박스

> 작은 패치. audit 이 spirit/rules 룰 본문을 작성할 때 verbose 누적 + 이전 세션 흔적 (시간 부사·일회성 ref·발견 경위) 박히는 패턴 차단. 룰은 매 turn hook 으로 inject 되고 매번 새 세션에서 읽히는 evergreen 문서 — verbose 면 토큰 낭비, 세션 흔적이 본문에 박히면 6개월 뒤 노이즈.

## 1) audit §4.2 — 압축·탈맥락 원칙 박스 추가

기존: audit `§4.2 룰 본문 — LLM 이 spirit/rules 에 직접 Edit` 단계는 frontmatter 스키마 + 예시 1개만 제시. LLM 이 자유 서술하면 verbose / 시간 부사 / `PR #1234`·날짜·"이번 audit 에서 발견" 같은 일회성 컨텍스트가 룰 본문에 그대로 박힐 위험.

수정: `skills/audit/SKILL.md §4.2` 안에 **압축·탈맥락 원칙 (룰 본문·CLAUDE.md 공통)** 박스 추가.

**압축 (7 규칙)**
- 3줄 골격 권장 — 위반 예 / 대안 / 검증
- 한 줄 한 사실
- 의례적 표현 제거 ("다음과 같이", "~할 수 있어요", "참고로", "필요시", "일반적으로")
- 단정·명령형 — 완곡 어법 X
- 표준 약어 OK (PR, DB, API, CI, regex)
- 보존 필수 — 코드블록(백틱), URL, SP 토큰, 파일경로, 정규식, frontmatter
- 목표 길이 — CRITICAL/MANDATORY 5~8줄, CONVENTION 3~5줄

**탈맥락 (4 규칙 — 세션·시간 흔적 금지)**
- 시간 부사 X — "이번 세션", "방금 전", "최근", "어제", "지난 주" 삭제. 룰은 시간 불변.
- 일회성 ref X — `PR #1234`, 이슈 ID, 절대 날짜 (`2026-05-17`), 커밋 SHA 박지 말기. 식별자는 SP 토큰 하나.
- 발견 경위 X — "이번 audit 에서 발견", "OO 가 제보" 같은 출처는 mistake 파일 (archive 후 보존) 의 책임.
- 세션 자아 X — "내가 분석한 결과", "조사해보니" 1인칭/조사 표현 삭제.

before / after diff 예시 포함 — 시간·세션 흔적 (날짜·PR 번호·"최근"·"조사해보니") 박힌 verbose 4줄을 evergreen 4줄로 정리하는 비교.

영향: audit 으로 룰 승격 시 LLM 이 박스 따라 짧고 evergreen 한 본문을 씀. CLAUDE.md 직접 수정은 audit 책임 아님 (§4.2 기존 가이드 유지) 이지만 동일 원칙 적용 — 헤더에 "룰 본문·CLAUDE.md 공통" 명시.
