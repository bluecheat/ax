# 0.5.2 — 계획 시점의 합의 리뷰, 그리고 움직이는 HUD

> 0.5.1 을 오케스트레이션 스택 여섯 층에 대조한 계획(critic 13건 반영)의 첫 판이에요. 둘을 담아요 —
> **spec 을 diff 시점이 아니라 계획 시점에 리뷰**하는 합의 루프, 그리고 **하네스 위치만** 보여주되
> 실제로 움직이는 HUD. 전문 계획: https://claude.ai/code/artifact/69145dba-4bac-4386-b17e-397058570ec2

## 합의 리뷰 — `spec-validate` §2.5 · `spec-review.sh`

OMC ralplan 의 구조를 가져왔어요. 고정 스냅샷 하나를 Architect 와 Critic 이 **독립·순차**로 보고,
서로의 출력을 받지 않고, 종합은 Planner(메인 세션)만 해요. goax 가 얹은 건 둘이에요.

- **결정적 게이트가 먼저.** `check-spec-clarity.sh` 를 통과한 spec 만 리뷰어가 봐요. placeholder
  지적에 리뷰어 컨텍스트를 쓰지 않아요.
- **verdict 는 파일로.** 리뷰어가 `review-spec.architect.md` · `review-spec.evaluator.md` 에 직접 쓰고,
  첫 줄 `verdict:` 둘째 줄 `sha:` 가 계약이에요. `spec-review.sh --status` 가 둘을 집계해요.

**왜 파일을 둘로 가르나** — critic 이 잡은 구멍이에요. 한 파일에 둘이 쓰면 첫 줄 verdict 하나로
"둘 다 진행" 을 표현할 수 없고, 뒤에 쓰는 쪽이 앞 절을 읽게 돼 독립성이 깨져요. 리뷰어는 자기
파일 경로만 받아요. `tasks-gate.sh` G6 이 `review.md` 첫 줄 하나만 읽는 것과 같은 계약이에요.

**발동은 옷 사이즈로** (사용자 결정). Size 축만 봐요 — L·XL 필수, M 은 `--consensus` 로 선택, S 는
없음. risk 는 안 봐요: 구현 리뷰(evaluator, G6)가 이미 반영해서 두 축을 다 걸면 이중 반영이에요.
`tier-from-state.sh` 에 `spec_review` 필드가 생겼어요 (0.5.1 의 `evaluator` 필드와 같은 자리).

**sha 고정.** 리뷰 뒤에 spec 이 바뀌면 그 리뷰는 다른 문서에 대한 리뷰예요. 어느 쪽 sha 가
어긋났는지 스크립트가 말해주고, 그쪽만 다시 받아요. 라운드 상한은 3 — 넘으면 리뷰가 아니라 spec
정의가 문제예요.

`architect.md` 에 spec 리뷰 브리프(가장 강한 반대안 하나 · 실제 트레이드오프 하나 · ADR 후보),
`evaluator.md` 에 spec 모드(AC 검증 가능성 · 누락 엣지 · 같은 개념 다른 이름 · tasks.md 가 있으면
분해 기준·`files:` 실재·`[P]` 근거)가 들어갔어요. `architect` 는 0.5.1 까지 triage 매트릭스가
"L3 → architect 게이트" 라고만 적고 아무 skill 도 안 부르던 에이전트였어요 — 이제 엣지가 있어요.

## HUD — 하네스 위치만, OMC 의 문법으로

이전 HUD 의 세 조각(행성 이모지 · S×R · 혜성)은 **작업 중에 안 변했어요.** 상태 표시줄인데 상태가
안 움직였어요. 새 HUD 는 한 줄이에요:

```
[goax#0.5.1] | M×L2 · payment | spec ✓ › tasks ✓ › impl ● [######----]7/12 › review ○ | mistakes:3
```

- 설치 버전 (plugin 이 새로우면 `-> 0.5.2 goax up`) · triage 의 Size×Risk · M 이상의 워크플로
  체인(`✓` 완료 `●` 진행 `○` 남음, full tier 는 `adr`, `review` 는 evaluator 필수일 때만) · 실수 누적 수.
- **안 보여주는 것**: 모델·ctx%·에이전트·todo 는 OMC 몫, 레인·게이트·경보는 skill 출력과 doctor 몫
  (사용자 결정 — 상태 표시줄엔 하네스 위치만).
- **구조는 OMC HUD 소스를 그대로 옮겼어요** — 요소를 독립 렌더해 레이아웃 순서로 조립, 프리셋
  `minimal`/`focused`(기본)/`full` 이 줄 수를 정하고, `COLUMNS` 를 넘으면 ` | ` 경계에서 잘라요.
  버전 태그와 업데이트 힌트도 OMC 문구예요. 시안 라벨·초록 완료·노랑 대기·dim 남음.
- **체인이 움직이려면 phase 가 있어야 해요.** critic 이 잡은 것 — `spec-implement` 는 0.5.1 까지 실행 중
  phase 를 안 쓰고 끝에 idle 로 리셋만 했어요. 이제 진입 시 `implementing`, evaluator 대기 시 `review`
  를 써요. `docs/skill-routing.md` 의 phase 표가 그 목록이에요.
- **파일만 읽어요.** statusline 은 300ms 디바운스에 새 이벤트가 오면 취소돼요. 스크립트 호출은 0 이고
  jq 3회 + awk 1패스 + find 1회예요. 이 맥 실측 90–130ms — 계획의 50ms 목표엔 못 미쳤지만(요소마다
  서브셸이 하나씩) 300ms 예산 안이에요. 무거운 값(plugin 버전·evaluator 필수 여부)은 `update-state.sh` 가
  `state.json.hud` 에 캐시하고, 30분이 지나면 `(stale)` 을 붙여요 — 거짓 초록을 안 만들려고요.
- **합치기가 고쳐졌어요.** 이전 [c] 는 두 명령을 이어 붙였는데, 앞 스크립트가 stdin 을 다 먹어 뒤의
  OMC 가 JSON 을 못 받고 출력도 같은 줄에 붙었어요 (critic 실측). 이제 합성 스크립트가 stdin 을 변수로
  받아 양쪽에 각각 먹이고, goax 출력은 개행으로 끝나요.
- `config.yml` 에 `hud: { preset, bars }` 가 생겼어요. 조건부 복사라 기존 설치엔 안 내려가요 — 키가
  없으면 focused · ascii 예요.
