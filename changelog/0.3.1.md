# 0.3.1 — 집행 실체 검증 (I6·sensor liveness) + git hook 전 환경 기본

> 실사용 프로젝트(statusface) 외부 평가에서 나온 발견을 반영해요: 설치 무결성은 완벽해도
> **실제로 '차단'까지 가는 집행이 0개**일 수 있어요 — 라벨(`enforced_by`)은 schema 를
> 통과하는데 그걸 자동으로 돌리는 트리거가 리포에 없는 상태. 0.3.1 은 "라벨과 실제의
> 일치"를 장치 레벨까지 밀어붙여요.

## 변경 — Rule Enforcement I6 신설

- **`check-rule-enforcement.sh`**: I6 invariant 추가 — `enforced_by: external:*` 룰은
  자동 트리거 표면(CI workflow[GitHub/GitLab/Circle/Jenkins/Azure/Buildkite] /
  git pre-commit / husky / pre-commit-framework / lefthook)이 리포에 1개 이상 실재해야
  함. JSON 에 `i6_no_trigger`·`trigger_surfaces` 추가.
- **자기 무력화 방지**: goax wrapper 만 있는 pre-commit 은 트리거로 안 쳐요 — up 이 전
  환경 기본 설치라 인정하면 I6 가 항상 통과해요. 출고 훅 이외의 프로젝트 전용 chain
  훅이 있을 때만 `git:pre-commit-chain` 인정. hooksPath(husky v9)·실행권한까지 확인.
- **`--strict` 계약 변화**: I6 위반도 `TOTAL_VIOLATIONS` 에 포함돼요 — `--strict` 로
  쓰던 CI 에서 새 위반이 잡히면 그게 의도예요 (거짓 약속을 fail 로).
- 근거: I1 은 `external:vitest` 라벨을 통과시키지만, CI 도 git hook 도 없으면 그 테스트는
  "누군가 손으로 돌릴 때만" 집행돼요 — 사람 게이트(🟡)와 순환하는 거짓 약속. 도구 **내용**
  검증은 여전히 비목표(rule-enforcement.md 시나리오 11 유지), **트리거 실재**만 검증.
- `docs/reference/rule-enforcement.md`: I6 본문 + 시나리오 11/11b/11c 분리.
- doctor §3.9: I6 보고 라인 + 다음 단계 옵션 `[t] 트리거 설치` 추가.

## 변경 — Sensors liveness 검사 신설 (doctor §3.10)

- **`check-sensor-liveness.sh` 신규** (script-backed, `--json`): 룰 라벨이 아니라 Sensors
  장치의 생사를 검사.
  - **C1** grep 훅이 미작성 스캐폴드(`#goax-grep-scaffold`)거나 구버전 데모 내용 잔존
  - **C2** git pre-commit wrapper 미설치 (사람 터미널 커밋 완전 우회 상태)
  - **C3** 차단 능력 0 — `sensors.mode` warning/off + C2 조합 (off 는 검사 자체 생략).
    기본 설치가 이 상태라 명시적 finding 으로 보고해야 사용자가 인지
  - **C4** 세션 루트 이탈 — `CLAUDE_PROJECT_DIR ≠ .ax 루트` (gitignore 된 서브디렉토리에서
    세션 시작 시 훅·spirit 주입이 조용히 빠지는 실관찰 사례)

## 변경 — critical-rule-grep.sh 데모 제거

- 템플릿 출고본의 데모 검사(Next.js hydration·Kotlin domain var·entity-migration)를
  **미작성 스캐폴드**로 교체 — 설치 프로젝트가 "커밋 grep 센서가 있다"고 믿는데 실제론
  남의 룰을 검사하던 상태 차단. secrets 검출은 범용이라 유지.
- `#goax-grep-scaffold` 마커: 프로젝트 패턴을 채우면 지우는 신호 — liveness C1 이 감지.

## 변경 — git pre-commit wrapper 전 환경 기본 설치

- up §5.7: `install-git-hooks.sh` 를 OpenCode 안내에서 **전 환경 기본 설치**로 승격
  (idempotent, 기존 non-goax hook 은 `--force` 없인 불변 — 보존 원칙 동일).
- 근거: Claude Code `PreToolUse:Bash` 는 **에이전트가 실행하는** `git commit` 만 잡아요.
  사람이 터미널에서 하는 커밋은 git hook 이 없으면 CRITICAL 센서를 완전 우회해요.

## 변경 — triage state.json 갱신 명시

- triage SKILL 말미에 doctor 와 동일한 state 갱신 블록 추가 (`update-state.sh` +
  `last_skill`/`skill_calls`). 실사용에서 triage 가 state 를 안 찍어 `goax_version: null`
  `skill_calls: 0` 인 죽은 state 로 남고, doctor 3-way 버전 비교가 stale 오진하던 문제.

## 변경 — evals/ 스위트 신설

- 플러그인 행동 평가 3케이스: `triage-first`(META 1번 룰이 실제로 발동하나) ·
  `critical-canary`(🔴 룰을 긴급성 압박으로 유혹) · `doctor-i6`(집행 공백 오진 여부).
- 레이아웃은 `claude plugin eval` (early access — 공개 문서 없음, 실행 전
  `--help` 로 포맷 확인) 기준. 케이스가 자기 완결이라 `claude -p` 수동 채점도 가능.
- 운영 원칙: 케이스는 실패 관찰에서만 추가 (mistake loop 와 같은 방향).
