# 0.7.3 — audit 이 경고만 있는 룰을 만들던 것 (가이드 먼저) · "사다리" 를 풀어 쓴 이름으로

## 무엇이 좋아졌나 — 누구에게 체감되나

- **audit 이 승격하는 룰이 "어떻게 해야 하나" 로 시작해요.** 예전엔 grep 으로 잡히는 룰이면 `<!-- 검출 패턴: -->`
  경고를 붙이는 게 곧 승격이었어요. 그런데 이름·위치 규약은 경고가 틀렸다는 것만 알리고 무엇을 쓸지는 알려주지 못해요.
  한 실사용 프로젝트에서 "구현체를 `Default*Api` 로 짓지 않는다" 를 경고로 승격했다가, 정작 필요한 건 "`application/service`
  에 행위 기반 `*Service` 로, 동사 1개면 `Get*`·여럿이면 `Modify*`" 라는 가이드였어요. 모델은 금지만 보면 가장 가까운
  선례(대개 잔재)를 따라 써요.
- **잔재가 많은 패턴에 경고를 걸기 전에 잔재 수를 재요.** pre-commit grep 은 staged 파일 전체를 봐서, 같은 프로젝트에서
  105개 중 35개 파일이 이미 걸리는 import 패턴은 무관한 수정마다 경고를 냈을 거예요.
- **"집행 사다리" 가 "막는 방법 우선순위" 가 됐어요.** 새 세션이 설명 없이 "사다리 ③" 을 읽으면 무엇인지 알 수 없었어요.
  이제 처음 나오는 곳마다 "위에서부터 보고 처음 해당하는 하나를 고른다" 를 같이 적고, 항목은 "③ grep 검사" 처럼 수단 이름으로 불러요.

## 바뀐 것

- 스킬 `audit` §3: "가이드 먼저" 원칙 — 막는 방법 우선순위는 가이드를 무엇으로 지킬지 고르는 것. ③ grep 검사는 "걸리면
  커밋을 멈춰야 하는" 룰로 좁히고, 경고로 끝나는 규약·잔재가 많은 패턴은 가이드 + ② CI 테스트(ArchUnit 같은 + 잔재 허용목록)
  또는 ④ 리뷰로. 후보 [d] 예시를 가이드 + ② 로.
- `audit` §4.2: 3줄 골격에서 `대안` 을 빠지면 안 되는 줄로. 이름·위치 규약은 위치·이름·예시로 풀어도 돼요.
- `audit` 절대 금지: "가이드 없이 금지·경고만 있는 룰로 승격 X" 추가, grep 패턴 필수 조건을 "커밋을 멈춰야 하는 룰" 로.
- 용어: `audit`·`mistake` 스킬, `_templates/mistakes/mistake.md` 의 "집행 사다리" → "막는 방법 우선순위".
- `CONCEPTS.md` §4.2.1 승격 설명을 같은 원칙으로 (산업안전의 통제 위계와 같은 원칙이라는 출처 한 줄).
