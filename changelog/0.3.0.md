# 0.3.0 — 재베이스라인: 행동 스캐폴딩 lean 전환 + model_tier 분기

> 행동 지시(가치 의례·인터뷰 대본·절대 금지 목록)를 상시 주입에서 걷어내고, 결정론(Sensors·스크립트·게이팅)과 프로젝트 지식만 남기는 재베이스라인이에요. frontier 모델은 lean 하네스가 기본이 되고, 경량·타사 모델은 `model_tier: standard` 로 기존 행동 가이드를 opt-in 복원해요.

## 변경 — Spirit lean 전환

- **`values.md` 슬리밍**: 상시 주입은 팀 고유 가치(작은 단위·안전 우선 + 사용자 추가 슬롯)만. frontier 모델 기본 행동과 중복되던 항목 — 긍정 편향 금지 · 추측 대신 질문 · 결과→근거→다음 구조 · 자가 점검 · 자기 합리화 신호 명시 의례 · 이모지 prefix — 는 상시 주입에서 제거.
- **`_templates/spirit/behavioral-baseline.md` 신설**: 제거된 행동 가이드 전문을 opt-in 템플릿으로 보존. 경량 모델 사용 시 또는 특정 항목의 실패가 **실제로 재발 관찰**될 때 그 항목만 복원해요 (ablation 원칙 — 전부 되살리지 않음).
- **`tone.md`**: `~해요` 체는 유지 (충돌 없는 정체성 가치). 삭제된 values 항목 번호 참조만 정리.

## 변경 — `model_tier` 분기 신설

- `config.yml` 에 `model_tier: frontier | standard` 추가 (기본 frontier).
  - `frontier`: lean 하네스 — 행동 가이드 최소, 결정론 중심.
  - `standard`: 경량·구세대·타사 모델 — behavioral-baseline 복원 절차를 주석으로 안내.
- `AGENTS.md.template` META: 5원칙 → **Triage First 단독** (하네스 고유 지시만 잔류). 일반 행동 원칙(추측 금지·단순성·요청 범위·검증 후 종료)은 frontier 기본 행동이라 상시 주입 제외, standard tier 는 baseline 참조.

## 변경 — triage 슬리밍 (403 → 약 230줄)

- **유지 (결정론·프로젝트 지식)**: MEMORY 인덱스 → triage-search → snippet-first 읽기, Size×Risk 기준표, 게이팅 매트릭스, current-task.json 기록, 역면접 발동 조건 + intent_notes 중복 방지, L3 게이팅 불변.
- **제거·압축 (행동 대본)**: 0단계 인터뷰 진행 룰 4종·출력 예시 박스 2개, 3단계 출력 예시 박스 3개 중 2개, "절대 금지" 3블록. 인터뷰·메뉴의 문장 구성은 모델 판단에 위임 (`AskUserQuestion` 도구 활용 안내). 핵심 불변 3줄(검색 결과 반영·L3 우회 금지·결정 공간 비례 질문)로 통합.

## 변경 — 문서 명제 정련

- CONCEPTS §1.3: "더 큰 모델은 잘못된 진단" → **"절반의 진실"** 로 정련. frontier 모델이 Guides(행동 지시)를 흡수했음을 인정하고, 환경의 지속 가치를 Sensors(검증)·프로젝트 고유 지식·Loop(축적)로 재정의. 정련 명제: *환경 엔지니어링의 무게중심은 모델 세대에 따라 Guides → Sensors + Loop 로 이동한다.*
- CONCEPTS §7.3: "행동 스캐폴딩의 감가상각" 한계 명시 — 감가상각은 Sensors·Loop 에는 적용되지 않음.
- README(en/ko) Core Principles 에 "축적 대신 재베이스라인" 원칙 추가.

## Design decisions — 왜 지금 재베이스라인인가 (외부 근거)

- **Claude Code 시스템 프롬프트 ~80% 삭제**: Anthropic 이 신형 frontier 모델(Opus 5 계열) 출시에 맞춰 Claude Code 시스템 프롬프트를 약 800 → 164 토큰으로 줄였고 성능은 유지·개선. Boris Cherny(Claude Code 창시자): *"시스템 프롬프트의 많은 부분이 모델이 당연히 알아야 했지만 몰랐던 행동을 교정하는 내용이었다 — 새 모델은 그냥 안다."*
- **주기적 ablation 권고**: Cherny 는 모델 릴리즈마다 프롬프트를 지우고 한 줄씩 되살리는 ablation 을 권고 — *"석 달 전 모델을 위해 한 것이 다음 모델에는 전혀 통하지 않을 수 있다"*, *"모델은 그 지시를 매 호출마다 읽는다 — 정말 필요한지 확인하라."*
- **삭제 대상과 잔존 대상의 구분**: 공개된 사례에서 삭제된 것은 상세 단계별 절차·부정 제약·검증 지시·선주입 예시. 남긴 것은 안전·권한·정적 분석(결정론), 도구 인터페이스, progressive disclosure, 저장소에서 유추 불가능한 도메인 지식 — goax 의 Sensors·enforced_by·Mistake Loop·Layer 2/3 가 정확히 잔존 카테고리예요.
- **상충 지시가 최대 해악**: 여러 파일에 흩어진 상충 지시는 frontier 모델 성능 저하 요인 1순위로 보고됨. Spirit 의 응답 형식 의례는 호스트 CLI 자체 출력 가이드와 직접 충돌하던 유일 지점이라 우선 제거.
- **실측 근거**: 본 저장소 운영 중 frontier 모델의 Spirit 형식 의례 미준수가 실제 관찰됨 — 지켜지지 않는 룰은 goax 자신의 원칙(라벨과 실제의 일치)에 따라 제거가 정직해요.

## 기존 사용자 마이그레이션

lean 전환은 **자동 적용되지 않아요** — 팀이 커스터마이즈한 spirit·Constitution 을 덮어쓰지 않는 보존 설계(`.suggested` 패턴) 때문이에요. 갱신 경로:

1. `/plugin marketplace update goax` → `/plugin install goax` — 스킬(기능 프롬프팅)은 이 시점에 즉시 신판 적용.
2. `"goax up"` 재실행 — `_templates/spirit/behavioral-baseline.md` 자동 백필 + lean 신판이 `.ax/spirit/values.md.suggested` · `.ax/AGENTS.md.suggested` 로 제안돼요.
3. `.suggested` 를 기존 파일과 diff 해서 lean 전환 여부를 결정해요 — 팀 고유 가치는 새 values.md §3 슬롯으로 옮기고, 행동 가이드가 필요한 경량 모델 프로젝트만 `config.yml` 에 `model_tier: standard` 를 적고 baseline 을 복원해요.

갱신 전 혼합 상태(신형 스킬 + 구형 values)에서도 참조가 끊기는 곳은 없어요 — 구 values 는 자기 완결적이고, 누락 파일은 doctor 가 감지해 `/up` 을 안내해요.
