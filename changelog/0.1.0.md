# 0.1.0 — Initial release

> goax — AX 4-Layer 하네스 Claude Code Plugin. AI 결과 일관성을 *환경*으로 통제해요.

## 골격

### 4계층 + 2 Cross-cut

- **Layer 0 — Triage** — 작업 진입 시 Size×Risk 자동 분류, spirit·룰·페르소나 자동 주입
- **Layer 1 — Constitution** — `CLAUDE.md` (root) 비협상 룰 3~5개 (🔴 CRITICAL / 🟡 MANDATORY / 🔵 CONVENTION 시그널)
- **Layer 2 — Module Rules** — 모노레포 모듈별 sub-CLAUDE.md
- **Layer 3 — Spec / ADR** — `.ax/docs/{adr, spec}/` SSOT, NEEDS CLARIFICATION 게이팅
- **Cross-cut Spirit** — `.ax/spirit/{values, tone, rules}` 모든 sub-agent 공통 인격
- **Cross-cut Mistake Loop** — `.ax/mistakes/` 캡처 → audit → 룰 승격 (코드 대신 환경 수정)

### SDD Workflow — Tier-aware + 두 가지 길

`spec-new`는 처음부터 9 파일을 다 만들지 않아요. triage size×risk로:

| Tier | 산출물 | 적용 |
|---|---|---|
| basic | spec.md + README.md (2) | S/M × L0~L1 |
| standard | + plan.md + tasks.md (4) | M × L2~L3 / L × L0~L2 |
| full | + research/data-model/contracts/quickstart/checklists (9) + ADR | L × L3 / XL |

- **빠른 길**: `/spec --tier full payment-refund`
- **점진 길**: `/spec --tier basic` → `/spec-plan` → `/spec-tasks` → `/spec-implement`
- 자연어 override: "스펙만" / "플랜까지" / "풀패키지"

## 설계 결정 — 거부된 대안 + 채택 이유

기록 보존 목적. 자세한 본문은 git history에. 각 결정의 *왜*만 한눈에.

### 4계층 모델 (v0.1)
- 채택: 4 Layer + 2 Cross-cut (Spirit, Mistake Loop)
- 거부 A: 단일 파일 (.cursorrules / CLAUDE.md만) — Triage·Sensors·Loop 부재, 같은 실수 반복 차단 불가
- 거부 B: PRD-first (specify→plan→tasks) — *비협상 룰*과 *행동 정체성* 미흡 → 부분 채택, spec-kit과 병행 가능

### `.claude/` ↔ `.ax/` 분리 (v0.1.2)
- 채택: `.claude/` = Claude Code 자동 로드 표준, `.ax/` = goax 자체 자산 (spirit, mistakes, hooks, config, docs/{adr,spec})
- 거부: 단일 트리 `.ax/` only — slash·자연어 트리거 자동 매칭 안 됨 (프로토타입 `ax-first`에서 검증)
- 거부: symlink 노출 — Windows·CI 호환 이슈

### Spirit Cross-cutting (v0.3)
- 채택: SPIRIT만 신규(`.ax/spirit/`), SOUL ≈ CLAUDE.md / BRAIN ≈ persona는 기존 자산 매핑
- 거부: SOUL/BRAIN/SPIRIT 3 파일 — 기존 자산과 중복
- 보류: 코사인 유사도 + EMA 정량 측정 — NumPy 의존, v0.6+

### 룰 토큰 컨벤션 (v0.2)
- 채택: `<scope>:<LEVEL>:<id>` (Constitution) + `SP-<CATEGORY>-<id>` (Spirit). 예: `AX:CRITICAL:001`, `SP-SEC-001`
- 거부: ID 없음 (정확도 ↓) / HTML 메타 코멘트 (사람 가독성 ↓)

### Plugin 배포 (v0.1.2)
- 채택: Hybrid — Plugin 진입점(skills, agents) + bash 잔존(`.ax/hooks/*.sh`만)
- 거부 A: Pure Plugin (Hook도 LLM) — pre-commit·CI는 LLM 없이 동작해야, 결정론 검사는 grep이 효율
- 거부 B: bash 유지 + plugin 보조 — 두 진입점 혼란
- 동기: bash 정규식 도메인 파싱 정확도 ↓, sed/grep cross-OS 차이, 사용자 자동 갱신 불가

### Slash Commands + HUD (v0.2.0)
- 채택: skill name이 곧 슬래시 (`/goax:install`, `/goax:doctor`, ...) + `/goax` 인덱스 alias 한 개. `.ax/state.json` (프로젝트별) + `.ax/hud/statusline.sh` (bash, jq, <100ms)
- 거부 A: 자연어 only — 명시적 호출 불가
- 거부 B: `/goax doctor` (space hierarchical) — Claude Code는 1단어 매칭이 정확
- 거부 C: 전역 `~/.ax/state.json` — 다중 프로젝트 충돌
- 명명 정정 (초기 `goax-` prefix → 제거): plugin namespace `/goax:`가 이미 disambiguation 역할. 공식 권장 따라 prefix 제거. commands.md는 *"merged into skills"* 공식 가이드 따라 폐기 (인덱스 `/goax` 한 개만 유지). 충돌 회피는 namespace로 충분.
- `.claude/settings.json` 자동 덮어쓰기 X (감지 → [b] 교체 / [c] 합치기 / [d] 취소)

## 핵심 원칙

- **결정론은 스크립트가, 판단은 LLM이** — SKILL.md는 thin wrapper
- **사용자 수정은 SSOT** — `_templates/`는 사용자 프로젝트 안 도메인 적응 가능, plugin 갱신 시 `.suggested`로 떨어트려 머지 결정 위임
- **HUD 우주 이모지** — `.ax/hud/statusline.sh`가 `.ax/state.json` 실측으로 4계층·Cross-cut 활성도를 별·행성(🪐/🌟/⭐/✦)로 표시. Claude Code statusline 공식 사양(stdin JSON, multi-line) 준수. 응답 자가 검증 X.
- **한국어 ~해요 체** — `tone.md` 강제, 안티패턴 명시
