## awk count snippet collapse 버그

SKILL.md Q2 카운트 검증의 awk 패턴 `awk '/^domain_risk:/,/^[^[:space:]]/'` 가 시작·종료 패턴이 *같은 라인*에서 매칭되는 함정에 걸림. `domain_risk:` 자체가 `^[^[:space:]]` 에도 매칭돼 첫 줄에서 즉시 종료, 결과 항상 0.

수정 (`skills/onboarding/SKILL.md` 3 곳):

```bash
# 옛 (collapse 버그):
awk '/^domain_risk:/,/^[^[:space:]]/' .ax/config.yml

# 새 (NR-guard, 정확 동작):
awk '/^domain_risk:/{found=1;next} found && /^[^[:space:]]/{exit} found' .ax/config.yml
```

검증: 옛=0 / 새=17 (실제값). grep 카운트도 정상.

## 신규 project hook 작성 4가지 가드

`SKILL.md` "절대 금지" 섹션에 신규 project hook 작성 시 따라야 할 4 가지 가드 추가:

### 1) 헤더 마커 (`# [project-specific]`)

shebang 다음 줄에 `# [project-specific] Generated by goax onboarding — not a shipped plugin artifact`. drift 감지가 출고본과 헷갈리지 않도록.

### 2) Annotation class 화이트리스트

Spring 테스트 검증류 hook 은 `*test/context/*` `*test/.../base/*` 같은 메타 어노테이션 정의 디렉토리를 `case "$f" in *test/context/*) continue ;; esac` 로 skip. 메타 어노테이션이 `@DataJpaTest` 등을 보유했다고 false-positive 발생 차단.

### 3) `import static` modifier 옵션

JUnit·assertion 류 검증은 `^import[[:space:]]+(static[[:space:]]+)?org\.junit\.jupiter\.` — `import static org.junit.jupiter.api.Assertions.*` 가장 흔한 형태도 catch.

### 4) `capture-mistake.sh` 호출

위반 발견 시 `[ -f "$CAPTURE" ] && bash "$CAPTURE" "$category" "$message" >/dev/null 2>&1 || true`. Mistake Loop violation 추적 가능. 호출 안 하면 hook 이 막아도 audit 이 추세 못 봄.

## CONVENTION 형식 통일

CLAUDE.md 본문에 `(`<scope>:CONVENTION:001`)` 형태로 body 인용된 케이스가 발생. `update-state.sh` 의 `^🔵 \*\*` 패턴은 body 인용 못 잡아 state.json 시그널 카운트 누락.

수정 (`SKILL.md` sub-Q "CONVENTION 처리 방식"):
- (a) **인라인 정의**: `🔵 **\`<scope>:CONVENTION:NNN\`** ...` root 박음
- (b) **@import 위임**: `.ax/spirit/rules/<category>.md` 에 SP-룰로, root 는 `@.ax/spirit/rules/...` 한 줄
- 두 형태 혼합 금지. body 인용 형태도 금지 — 정의는 한 자리에만.
