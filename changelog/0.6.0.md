# 0.6.0 — 룰의 `검출 패턴:` 마커를 실제로 집행 (grep 룰의 승격 = 집행)

> 두 룰 템플릿(`_templates/spirit/rule.md`, `_templates/module/rules.md`)은 오래전부터 룰마다
> `<!-- 검출 패턴: <regex> -->` 자리를 갖고 있었는데, 그 마커를 읽는 훅·스크립트가 하나도 없었어요.
> `audit` 은 승격 룰에 `- 검증: pre-commit grep …` 을 산문 bullet 로 쓰고, 출고 훅
> `critical-rule-grep.sh` 는 사람이 case 문을 손으로 채워야 하는 스캐폴드였어요. 그래서
> `mistake → audit → SP-XXX-NNN 승격` 이 끝나도 CI 는 안 빨개졌어요 — SP-CTR-001("약속은 문서가
> 아니라 테스트에")·I1("🔴 = 자동 차단 보장")에 goax 가 스스로 어긋나 있던 자리예요.

## 무엇이 바뀌었나

- **`common.sh`** — `goax_rule_patterns <file>` (마커 파서: `## SP-` 헤더 귀속 · ```·~~~ 코드펜스 무시 ·
  `<regex>`·`<ERE>` 같은 `<…>` 자리표시자 무시 · 한 룰에 여러 마커 = OR), `goax_rule_examples` (`❌`/`✅` 와
  `- 위반 예:`/`- 대안:` 추출), `goax_frontmatter_scalar`, `goax_glob_filter` (stdin 경로 목록을
  글롭으로 — python 을 룰당 1회만 띄워요). 파서는 이 하나예요 — 훅·프로브·doctor·rules-index 가
  전부 이걸 써요.
- **`hooks/pre-commit/critical-rule-grep.sh`** — 룰 패턴 섹션 신설. `spirit/rules/*.md` ·
  `modules/*/rules.md` 를 순회해 파일 frontmatter `paths:` 에 맞는 staged 파일만 검사하고,
  `severity: critical` 만 (mode=fail 에서) exit 2, mandatory/convention 은 경고. `.ax/**` 는 항상
  제외(룰 파일 자신의 ❌ 예시가 자기 패턴에 걸려요), 출력은 `file:line — 토큰` 만(본문 없음),
  깨진 ERE 는 경고 후 그 패턴만 생략. 스캐폴드 case 문은 "패턴 한 줄로 못 쓰는 검사만" 으로 축소.
- **`zero-probe.sh`** — 내장 프로브 `pattern-rules`. 프로브 파일이 없어도 돌아요. 룰마다 ❌ 예시는
  걸리고 ✅ 예시는 안 걸리는지 (hermetic — 워킹트리·인덱스 무변경). 예시 없는 룰은 skip.
- **`check-rule-enforcement.sh`** — I7: grep 류 파일(`enforced_kind: grep` 또는
  `critical-rule-grep.sh` 를 가리킴)의 마커 없는 룰 `i7_grep_without_pattern`, 패턴은 있는데
  `paths:` 빈 룰 `i7_pattern_without_paths`. `--strict` 에서 exit 1.
- **`check-sensor-liveness.sh`** — C1 은 "스캐폴드 미작성 **AND** 패턴 룰 0건" 일 때만. `pattern_rules: N`.
- **`rules-index.sh`** — 룰마다 `pattern: bool`, 텍스트 출력에 `⌕`.
- **`audit`** — 승격 후보마다 집행 사다리(① 구조 제거 → ② lint/CI → ③ grep 패턴 → ④ 산문)를
  옵션 앞에 물어요. §4.2 예시가 마커 형식이고, 시크릿 류 예시 값은 `"<plain-value>"`(룰 패턴엔
  걸리고 secrets 스캐너는 건너뜀). 완료 검증에 `zero-probe.sh --only pattern-rules` 통과 추가.
- **`mistake`** 템플릿 — "어떻게 막을 수 있나" 가 사다리 4줄. **`onboarding/signal-guide.md`** —
  JUnit5 전용 훅 40줄 예시 → `paths:` + 마커 2줄; 전용 훅은 "제외 경로·다중 파일 조건" 일 때만.
- **`doctor`** §3.9 I7 보고 + `[p] 검출 패턴 채우기`, §3.10 C1 문구. **`rule-enforcement.md`** —
  "검출 패턴 마커" 절 · severity×mode 표 · I7 · 시나리오 13~16 · 비목표.

## 검증

- smoke §45 신설 (21 검증): 파서(orphan·펜스·자리표시자·다중 마커·예시 추출·글롭 필터) ·
  훅(critical exit 2 + `file:line`, 본문 미출력, paths 밖 통과, mandatory 경고만, 룰 파일 자신 통과,
  깨진 ERE) · 프로브(ok/skip · ❌ 미검출 FAIL · ✅ 오탐 FAIL) · I7 두 배열 + `--strict` · C1 · rules-index.
- 하위 호환: 마커 없는 기존 룰 파일은 동작 변화 0 (§41 시크릿 13종 결과 불변). 마커가 있어도
  `paths:` 가 비면 안 돌아요.

## 기존 설치 주의

- onboarding 으로 `ops.md` 를 `.ax/spirit/rules/<project>-ops.md` 에 복사한 프로젝트는 SP-OPS-001 아래
  `<!-- 검출 패턴: 사용자 메시지에 "그냥 해줘" … -->` 산문 줄이 있어요. 출고본은 `적용 예외:` 로 바꿨는데,
  복사본은 그대로라 새 파서가 정규식으로 읽어요 — `zero-probe.sh` 가 `FAIL SP-OPS-001`, doctor I7 이
  `pattern_without_paths` 로 보고해요. 그 줄의 `검출 패턴:` 을 `적용 예외:` 로 바꾸면 끝이에요.

## 그 밖의 수정

- **`spirit-rules-inject.sh`** — 인라인 `paths: ["**/*.kt"]` 형식을 못 읽어 같은 룰을 grep 훅은 집행하는데
  주입은 안 되던 것 → `common.sh` 의 `goax_yaml_list`/`goax_glob_match` 를 우선 사용 (없으면 기존 fallback).
- **`critical-rule-grep.sh`** — `git -c core.quotePath=false` 로 staged 목록을 받아요. 기본값이면 한글 등
  비ASCII 파일명이 `"\355\225\234…"` 로 인용돼 `-f` 검사에서 빠졌어요 (secrets 검사도 같이 못 보던 것).
  `file:line` 은 파일명에 `:` 가 있어도 안 깨지게 직접 조합해요.
- **`evals/`** — `claude plugin eval` 현 스키마로 갱신. grader 의 `focus:` 가 산문이라 3케이스 전부 로드
  실패였고, `prompt.md` 에 `allowed_tools` 가 없어 읽기 도구·Skill 이 안 열려 `triage-first` 는 triage 를
  부를 수조차 없었어요. canary 의 regex grader(`target: files` — 경로 목록이라 내용을 못 봄)는 파일 내용
  LLM 판정으로, `tool_used: Skill(triage)` 지표 grader 추가, README 에 실행 명령·Bash grant 제약·baseline
  (triage-first 1.0/0 · doctor-i6 1.0/0 · critical-canary 1.0/1.0). `evals/results/` gitignore.
