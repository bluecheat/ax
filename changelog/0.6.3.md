# 0.6.3 — 0.6.2 의 두 자리: `--delta` 가 1 라운드에서 "전부 바뀜" 이라고 하던 것 · 긴 한글 placeholder 줄이 JSON 을 깨던 것

## 달라지는 것

> 둘 다 0.6.2 에서 들어간 코드의 결함이에요. 0.6.2 를 쓰는 사람만 해당해요.

- **`--delta` 가 리뷰 1 라운드에서 파일 전체를 "바뀐 줄" 로 세던 것.** 리뷰어가 본 본문이 아직 없으면 base 는
  `snapshot`(= 방금 찍은 본문)인데, 그 **이름표를 그대로 디렉토리 경로로** 써서 `.review-snapshot/snapshot` 과
  비교했어요. 없는 경로라 `/dev/null` 대비가 되고, 방금 찍어 한 글자도 안 바뀐 spec 이 "전부 바뀜" 으로 나왔어요.
  이름표와 디렉토리를 갈랐어요. diff 헤더도 base 에 맞게 붙어요 — `reviewed/` 가 아닌데 `reviewed/` 라고 쓰던 것.
- **긴 한글 placeholder 줄이 JSON 을 깨던 것.** `placeholder_lines` 를 만들 때 `cut -c1-120` 으로 잘랐는데,
  GNU coreutils 의 `-c` 는 바이트 단위예요 — ubuntu 에서 `C`·`C.UTF-8` 둘 다 한글을 반으로 갈랐어요(실측).
  깨진 바이트가 result JSON 문자열에 들어가면 `spec-validate` 의 `jq` 가 통째로 죽어요. macOS BSD `cut` 은
  문자 단위라 안 터지고, smoke 픽스처의 placeholder 줄도 짧아서 CI 도 못 잡던 자리예요 — §44 가 awk `substr` 에
  대해 이미 적어 둔 것과 같은 함정이에요. 공용 SSOT 인 `GOAX_AWK_CLIP` 의 `clip()`(낱말 경계)으로 바꿨어요.
- **`--fixup` 은 본문 사본이 없으면 `changed_lines` 를 `0` 이 아니라 `null` 로 줘요.** 모르는 걸 0 으로 말하면
  "안 바뀐 것" 으로 읽혀요.
- **`spec-validate` 는 재리뷰일 때만 delta 를 브리프에 붙여요** (`base=reviewed` 이고 바뀐 줄 > 0). 1 라운드에
  빈 diff 를 주면 리뷰어가 "볼 게 없다" 로 읽어요.

## 검증

- smoke 3건 추가 — `--delta` base=snapshot 이 0줄(이 버그 회귀 고정) · `--fixup` 사본 없음 → `null` ·
  긴 한글 placeholder 줄의 JSON 파싱 + UTF-8 유효성. 전부 통과.
- 리눅스 실측: ubuntu 24.04 에서 `cut -c1-120` 은 `C`·`C.UTF-8` 둘 다 BROKEN, `clip()` 은 mawk 에서 둘 다 VALID.
