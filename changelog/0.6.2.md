# 0.6.2 — spec 합의 리뷰가 덜 비싸요: 라운드는 본 만큼만, 리뷰어는 병렬·다른 눈, 오타는 리뷰 없이

## 달라지는 것

> 체감 범위를 먼저 적어요. 앞 다섯 항목은 size L/XL(또는 `--consensus`) spec 의 합의 리뷰에 해당해요 — L spec 하나에서
> 실측한 마찰(라운드 6 중 실제 리뷰 4 · `<패턴>` 오탐으로 라운드 1 소모 · 순차 기동 · 두 리뷰어가 같은 지적 ·
> 통과 뒤 오타 수정에 재리뷰)을 하나씩 뺐어요. 나머지는 모든 프로젝트에 해당하는 작은 보강이에요.

- **라운드는 리뷰어가 실제로 본 횟수만 세요.** `spec-review.sh --snapshot` 은 같은 sha 면 그대로고(reused), 직전
  스냅샷을 아무도 안 봤으면 그 자리를 바꿔 끼워요(replaced). 리뷰어를 띄우기 전에 고친 오타 한 줄로 상한 3 이
  타지 않아요.
- **architect 와 evaluator 를 한 메시지에 같이 띄워요.** 독립은 서로의 파일을 못 보는 데서 오지 순서에서 오지
  않아요 — 순차는 벽시계만 두 배였어요. 그리고 **검토 범위가 갈렸어요**: architect 는 반대안·트레이드오프·되돌리기
  비용·ADR 후보만, evaluator 는 AC 검증 가능성·코드 현실·누락 엣지·배포 전제·tasks 분해만. 각 agent 에
  "하지 않는 것" 절이 생겨 같은 지적이 두 번 오지 않아요. 둘 다 `## 비차단` 절이 생겼고 거기 적힌 건 verdict 에
  안 세요 — 비차단만으로 `보강 필요` 를 내지 않아요.
- **재리뷰는 바뀐 곳만 봐요.** `--delta` 가 리뷰어가 본 본문(`.review-snapshot/reviewed/`)과 지금 본문의 diff 를
  써 주고, 브리프엔 그게 재리뷰일 때만(`base=reviewed` 이고 바뀐 줄이 있을 때) 붙여요. 리뷰어는 이전 라운드에서
  진행으로 본 절을 다시 열지 않아요.
- **통과 뒤 오타는 `--fixup`.** 둘 다 `진행` 인 뒤 문구·링크를 고쳐 sha 가 어긋나면 리뷰어를 다시 띄우는 대신 지금
  본문을 "리뷰된 것과 같다" 고 원장에 적어요. 바뀐 줄 수와 diff 를 보여주니, 설계가 바뀐 거면 쓰지 말고
  `--snapshot` 으로 새 라운드예요.
- **tasks.md 가 생기면 `--stage tasks`.** sha 가 spec+tasks 합산이라 `/spec-tasks` 뒤엔 반드시 어긋나는데, 그건
  spec 을 다시 보는 게 아니라 분해만 보는 라운드예요. 단계가 바뀌면 라운드가 1 부터 다시 시작하고 상한은 2 예요.
  `--status` 가 `stage` 를 보고해요.
- **spec 단계 리뷰어는 grep·read 만 해요.** 빌드·테스트는 구현 리뷰(`tasks-gate.sh` G6)의 몫이에요 — 리뷰
  한 번이 구현 한 번만큼 비싸지던 걸 agent 와 skill 양쪽에 검증 예산으로 못 박았어요. 리뷰어는 돌아올 때 한 줄
  (verdict · 차단 N · 비차단 M · 파일 경로)만 — 파일에 쓴 걸 대화에 다시 풀지 않아요.
- **인라인 코드 안의 `<…>` 는 placeholder 가 아니에요.** `check-spec-clarity.sh` 가 `` `grep "<a|b>"` `` 같은
  코드 인용을 placeholder 로 잡아 통과한 spec 을 막고 리뷰 라운드를 태웠어요. 그리고 걸린 줄을
  `placeholder_lines` 에 "줄번호: 본문" 으로 보여줘요 — 몇 건인지만 알면 찾으러 다녀요.
- **"묻지 말고 쭉 해" 를 파일이 기억해요.** 사용자가 이 작업에서 얼마나 물을지를 자연어로 말하면 triage 가 의도를
  읽어 `update-task.sh --set friction=autopilot|phase_gate|per_task` 로 적고, `spec-implement` 가 config 의
  `confirmation.mode` 대신 그 값을 써요(정책 C0). 확신이 없으면 안 적고(안 적으면 더 묻는 쪽이라 안전), 적으면
  되묻지 않고 `friction` 한 줄로 되비춰요 — triage 출력에서 한 번, 다음 세션의 spec-implement 진입에서 한 번.
  Phase 경계마다 파일을 다시 읽어 도중에 바꾼 것도 먹어요. L3 override 는 여전히 이겨요. `reset-task.sh` 가 task 와
  함께 비워요.
- **새 워크트리에서 HUD 가 죽은 채로 남지 않아요.** `update-state.sh` 가 `state.json` 이 없으면(gitignore 라
  클론·워크트리엔 없어요) `hud/state.json.template` 로 만들고 진행해요. "installer 먼저" 로 죽으면 skill 의
  `|| true` 가 삼켜서 아무도 몰랐어요.
- **리뷰 원장이 PR diff 에 안 새요.** `.gitignore.template` 에 `.review-round` · `.review-snapshot/` ·
  `review-spec.architect.md` · `review-spec.evaluator.md` 를 넣었어요 — 합본 `review-spec.md` 만 커밋해요.
  `/up` 이 기존 `.gitignore` 에 빠진 줄만 붙여요.
- **tasks.md 템플릿 §1.5 가 짧아졌어요.** 단일 레인이면 비워 두는 절인데 표 예시·명령이 40줄이었어요. `/lane` 이
  채운다는 한 문단만 남겼어요.

## 메인테이너용

- `.review-round` 는 7 필드예요 — `라운드|스냅샷sha|시각|spec sha|tasks sha|단계|fixup sha`. 옛 5 필드 원장도 그대로
  읽어요 (단계 `spec` · fixup 없음). `.review-snapshot/{reviewed,current}/` 에 그때 본문 사본, `delta.diff` 는
  `--delta` 가 써요. `--dry-run` 은 셋 다 안 건드려요.
- `--status` 의 pass 는 `sha == 현재` 또는 `sha == 스냅샷 sha && fixup sha == 현재` 예요. `fixup` 객체와 `stage`,
  `snapshot_sha` 가 result 에 추가됐어요.
- confirmation 정책에 C0 (task 사전 승인) 추가 — 우선순위 C5 > C3 > C4 > C0 > C1 > C2.

  호환 · agent/skill 계약(검토 범위 분리·병렬·비차단·검증 예산·`--delta/--fixup/--stage` 배선) · `update-state` 자가 복구
  3종을 더했고, §39 의 라운드 상한 검사를 "본 라운드만 센다" 로 고쳤어요. clarity 에 인라인 코드 오탐·
  `placeholder_lines` 검사, update-task 에 `friction` enum·reset 검사, gitignore 4종 검사를 더했어요. 전부 통과.
