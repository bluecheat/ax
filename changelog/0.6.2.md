# 0.6.2 — 완료 마킹이 본문에 언급된 다른 task 까지 켜던 것 (spec-implement §5 인라인 sed → `mark-task.sh`)

## 달라지는 것

> 체감 범위: `spec-implement` 로 task 를 하나씩 끝내는 모든 프로젝트. tasks.md 본문이 다른 task 를 언급하는
> 게 권장 관행("T009 가 해소" · "T005 의 상수와 맞춤")이라, 그런 줄이 있는 spec 은 전부 해당해요.

- **완료 마킹이 그 task 한 줄만 켜요.** 전에는 §5 의 인라인 sed 가 `.*T013` 으로 줄 어디에든 ID 가 있으면
  매칭해서, 아직 시작도 안 한 task 의 본문에 `T013` 이 적혀 있으면 그 줄까지 `[x]` 로 뒤집혔어요. 실측 —
  T005·T007·T009 셋을 켜자 T008·T014·T058 이 검증 없이 완료가 됐고, `tasks-gate.sh` 는 그걸 정상으로
  읽었어요(코디네이터가 켠 체크박스는 원장 없이도 정상이라 구분이 없어요). 이제 `mark-task.sh` 가 **줄 앞**
  의 ID 만 보고(`- [ ] T013 ` · `**T013**` · `[T013]`), 코드 펜스 안은 건너뛰고, 쓰기 전후 `[x]` 개수가
  정확히 1 늘었는지 확인해요 — 어긋나면 error 로 멈춰요.
- **"다음 task" 가 템플릿 예시를 집지 않아요.** §1 의 `grep -m1 '^- \[ \]'` 는 tasks.md 템플릿의 "한 줄 형식"
  코드 펜스 안 예시(`- [ ] T001 [P] [AC2] <한 줄 설명>`)를 첫 미완료 task 로 돌려줬어요. `mark-task.sh --next`
  는 펜스 밖 줄만 봐요.
- **마킹이 락을 잡아요.** 인라인 sed 는 `tasks.md.lock` 을 안 잡아서 같은 파일을 쓰는 `lanes-dispatch.sh`·
  `tasks-gate.sh` 와 lost-update 가 날 수 있었어요. writer 계약(README §쓰기 규약)대로 같은 락 문자열을 써요.
- `spec-review.sh --merge --json` 이 합본 경로 `merged_file` 을 돌려줘요 (텍스트 모드만 찍던 것).

## 메인테이너용

- 결정론 경계 원칙(CLAUDE.md §Architecture 1) 위반이 하나 더 스크립트로 내려갔어요 — SKILL.md 에 남아 있던
  마지막 `tasks.md` 인라인 writer 예요.
- `mark-task.sh` 는 `--state '~'` 로 의도적 보류도 켜요(사유는 손으로). bash `case` 패턴의 맨 `~` 는 홈으로
  틸드 확장돼서 `"~"` 로 묶었어요.
