# 0.5.6 — 리눅스에서 placeholder 게이트가 조용히 꺼져 있던 것

> 0.5.5 의 CI 가 ubuntu 에서만 `check-spec-clarity — placeholder 를 못 잡음` 으로 실패했어요(macOS 는 통과).
> 새 smoke 가 한글 placeholder(`<이름>`)를 실제로 넣어 보면서 드러난 거라, 0.5.4 이전에도 리눅스에선 같은 상태였어요.

## 무엇이 바뀌었나

- `check-spec-clarity.sh` 의 placeholder 정규식이 한글 범위 `[가-힣A-Za-z0-9 …]` 대신 부정 클래스 `<[^<>="'()]+>` 를 써요.
  GNU grep 은 `C.UTF-8` 에서 `[가-힣]` 범위를 **"Invalid collation character"** 로 거부하는데, 스크립트가 `2>/dev/null` 로
  삼켜서 placeholder 가 항상 0건 — 게이트가 조용히 꺼져 있었어요. 부정 클래스는 로케일과 무관하고, 표 row · URL · 이메일 제외는 그대로예요.
  덤으로 `<기준 1 — Given/When/Then 또는 정량>` 처럼 em dash 가 든 템플릿 placeholder 도 이제 잡혀요.
- `scripts/bash/README.md` 쓰기 규약에 "문자 클래스에 한글 범위를 쓰지 않아요" 한 줄.

## 검증

- macOS `/bin/bash` 3.2: smoke 501 통과. ubuntu 24.04 컨테이너(GNU grep 3.11 · bash 5.2 · `LANG=C.UTF-8` · python3): smoke 전체 통과.
- 리포 안 `.sh` 에 남은 한글 범위 브래킷 0건.
