# 0.1.9 — rule-enforcement 스키마 + mistake/audit 분리 + CLAUDE.md no-append

> 0.1.8 큰 그림: 라벨↔메커니즘 invariant 검증 자동화. 0.1.9는 그 SSOT 를 수립하고, 캡처/심사 책임을 분리하고, CLAUDE.md 누적 회피 — 룰은 spirit/rules 가 SSOT, hook(path-scoped inject) 이 매 작업 자동 주입.

## 1) Rule Enforcement schema — 라벨↔메커니즘 invariant SSOT

기존: CLAUDE.md 4계층 인덱스에 룰 라벨 (CRITICAL/MANDATORY/CONVENTION) 만 있고 *어떻게 enforce 되는지* 명시 없음. CLAUDE.md 가 "shim 메커니즘 명시" 한 채로 실제 hook 으로 전환된 케이스(0.1.7→0.1.8) 같은 silent drift 가능.

수정:
- `docs/reference/rule-enforcement.md` 신설 (사용자 `.ax/docs/reference/` 로 cp) — I1~I5 invariant 정의
- `templates/.../scripts/bash/check-rule-enforcement.sh` — invariant 검증 SSOT (JSON 출력)
- `doctor §3.9` + §3 표 row 추가 — 위반 시 옵션 [r] (라벨↔메커니즘 자동 정합), [w] (warning fix), [d] (deferred 옵션 deadline 누락), [g] (grandfathered ADR 누락)
- `onboarding` deferred 옵션 — deadline 강제 + ADR checklist + MANDATORY 권장
- `CLAUDE.md.template` 4계층 인덱스에 `enforced_by` / `enforced_kind` 컬럼 + 형식 가이드
- `install §6.6` — `docs/reference` → 사용자 `.ax/docs/reference/` cp 추가

영향: 라벨만 있고 메커니즘 미설정 / 메커니즘만 있고 라벨 미설정 / deferred 옵션이 deadline 없는 채로 누적되는 패턴 모두 doctor 한 번으로 검출.

## 2) Spec slim — basic = `spec.md` 만

기존: spec 디렉토리 생성 시 9 파일 (spec/plan/tasks/checklists/contracts/data-model/research/quickstart/README) 한 번에 깔림 → 작은 작업도 무거운 산출물 강제.

수정:
- `init-spec-dir.sh` tier 재정의 — basic 1 (spec.md) / standard 3 (+ plan, tasks) / full 6 (+ data-model, research, quickstart)
- `_templates/spec/README.md` 폐기 (인덱스 문서 불필요)
- `checklists/contracts` 빈 dir 안 만듦 — 필요할 때 lazy 생성
- `add-spec-files.sh` tier 자동 승급 갱신 (basic→standard→full)
- `spec SKILL.md` tier 매트릭스 + lazy 안내

호환성: 기존 0.1.8 spec 인스턴스 그대로 동작 (tier 마커 frontmatter 호환).

## 3) Triage First META — 5번째 원칙

기존: META 4원칙 (Single Source of Truth / Empty State / Frontmatter Discipline / Rule of Three). triage 발동 시점이 모호해 Claude 가 EnterPlanMode 안에서 직접 분류 시도하는 경우 발생.

수정:
- META 4원칙 → 5원칙 — Triage First (EnterPlanMode 전·직후 1회 필수)
- `triage SKILL.md` description + 발동 시점 — "plan mode 가 triage 를 대체" anti-pattern 명시 차단
- `CLAUDE.md.template` META 섹션 갱신

## 4) Mistake/audit 책임 분리 — 캡처는 skill+LLM, 심사는 audit

기존: `capture-mistake.sh` 가 hook 시점에 자동 호출 → hook 시점은 LLM 부재라 본문 분석 불가, frontmatter 만 채운 빈 mistake 가 누적. audit 도 capture/review 가 한 SKILL 에 섞여 trigger 키워드 충돌.

수정:
- `skills/mistake/SKILL.md` 신설 — 사용자 명시 1건 capture (인터뷰 → init-mistake-file → LLM 본문 Edit)
- `init-mistake-file.sh` 신설 — template cp + frontmatter sed 치환 + idempotent (같은 DATE+CAT+SLUG → `## 이력` append) + JSON
- `_templates/mistakes/mistake.md` — frontmatter `{{...}}` placeholder + 5 Whys / 영향 / audit 액션 / 이력 섹션
- `capture-mistake.sh` **폐기** — 자동 capture 책임 분리
- hooks (block-destructive / check-protected-paths / critical-rule-grep) `CAPTURE` 변수 + 호출 모두 제거
- `common.sh` `goax_hook_report` / `goax_hook_exit` 의 capture 호출 제거
- `onboarding` hook 가이드의 Guard #4 (capture-mistake.sh 호출) 제거
- `audit SKILL` — review/promote 만, capture 분리. trigger 키워드 분리:
  - mistake (capture): '기록·캡처·남겨·박기·적어'
  - audit (review): '회고·심사·정리·점검·승격·패턴'
- 파일 ID 컨벤션 단일화 — `${DATE}-${EPOCH}-${RAND4}-${CAT}-${SLUG}.md` (15자 ID + 30자 SLUG cut, 한글 only → md5 hash 8자 fallback)

호환성: 옛 컨벤션 (`YYYY-MM-DD-NNN`, `EPOCH_MS-PID-RANDOM`) 그대로 매치 (idempotent glob).

## 5) CLAUDE.md auto-append 폐기 — 룰 SSOT 는 spirit/rules 만

기존: `promote-mistake.sh --apply` 가 CLAUDE.md 에 룰 본문 append + mistake 에 promoted_to 마킹. CLAUDE.md 가 무한 누적 → token cost + 가독성 저하 + spirit/rules 와 SSOT 충돌.

수정:
- `promote-mistake.sh --apply` — mistake `promoted_to:` 마킹만 수행
- `--rule-text` 옵션 폐기 — 룰 본문 작성은 LLM 책임
- `audit SKILL §3` — `[a]~[d]` 옵션의 "CLAUDE.md 시그널 섹션 추가" 제거
- `audit SKILL §4` — 두 단계 분리:
  1. `promote-mistake.sh --apply` (스크립트 — mistake 마킹)
  2. LLM 이 `.ax/spirit/rules/<project>-<category>.md` 직접 Edit (frontmatter `paths:` 권장 — path-scoped hook 매 작업 inject)
- plugin shipped 파일 (`security.md`, `ops.md` 등) 직접 append 금지 안내 유지 — project-specific 별도 파일로 (clobber 방지)

효과: CLAUDE.md = META + 핵심 가드만, spirit/rules = 룰 SSOT. path-scoped hook (`spirit-rules-inject.sh`) 이 frontmatter `paths:` 매칭으로 매 작업 자동 inject 하므로 CLAUDE.md 누적 불필요.
