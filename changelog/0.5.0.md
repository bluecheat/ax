# 0.5.0 — 0에서 1로 가는 길과, 가를 수 있는지부터 묻는 병렬

> 실사용 프로젝트 하나를 2주치(커밋 274 · ADR 34 · spec 13 · mistakes 20+) 통째로
> 뜯어보고 만들었어요. 관통하는 게 둘이에요 —
> **하네스가 정작 0→1 에서 마찰을 가장 적게 걸고 있었고**, 병렬은 갈래를 세는 일이
> 아니라 **가를 수 있는지 먼저 묻는 일**이었어요.

## 새 skill — `zero`

**0→1 진입점이 없었어요.** `up` 은 brownfield 면 1006줄짜리 `onboarding` 인터뷰로
넘기는데, greenfield 는 §6 이 "🥳 도입 완료" 를 출력하고 끝이었어요. 빈 리포는 판정
조건(CLAUDE.md·hooks·modules>1·external spec) 넷 다 없어서 **반드시 그쪽으로 떨어져요.**
그래서 `domain_risk` 실매핑·도입 ADR·모듈 룰 stub·룰 시그널화가 전부 미생성이었어요.

**더 나쁜 건 그다음이에요.** `triage-search.sh` 는 빈 리포에서 에러가 아니라 조용히
`status: ok` + 전부 빈 배열을 돌려줘요. 그러면 도메인 매칭이 출고 예시(`payment`·
`order`·`product`·`search`)에 걸리거나 `default_risk`(L0)로 떨어지고 → 게이팅 매트릭스가
**"S/M × L0 = 즉시 작업, spec 불필요"** 로 흘리고 → 역면접은 발동 조건(M×L2 이상)
미달로 **스킵**돼요. 결정 밀도가 가장 높은 구간에 마찰이 가장 적게 걸려 있었어요.

`zero` 는 그 자리를 메워요. 다만 순서가 메시지예요 — **제품·비즈니스가 앞이고 기술이
뒤예요.**

1. 문제와 대상 · 가치 가설 · **안 만들 것** · 단위 경제 · 성공/중단 기준 · 위험 가정
   순위 · 첫 사용자에게 닿는 경로 (역면접, `AskUserQuestion`)
2. PRD v0.1 — 파운더 원문을 요약하지 않고 **그대로 인용**해서 남겨요
3. **되돌리기 비싼 결정 → ADR.** 판정 기준은 "기술이냐 제품이냐"가 아니라
   **되돌리기 비용**이에요. 제품명·비주얼 방향처럼 제품 결정도 여기 들어와요
4. 시안 승인 게이트
5. `domain_risk` 최초 설정 — 안 하면 triage 가 영원히 L0 로 흘러요
6. 스캐폴드
7. **집행 배관 + 네거티브 프로브** — 건너뛸 수 없어요
8. 첫 배포 · STATUS 개설

### 첫날 팩 — `templates/zero/`

분석 대상 프로젝트의 정확도 장치는 **선제 3 : 사고후 22** 였어요. 그런데 사고후 22 중
**13개는 원리적으로 첫날에 깔 수 있는 것**이었어요 — 전부 "세는 대상과 무관한 규율"
이라서요. 그 16개가 이 팩이에요. 각 룰에 **"이게 실제로 무엇을 잡았는가"** 를 사례로
붙였어요. 추상적 원칙이 아니라 증거가 붙은 규율이어야 값이 있어요.

**다만 산문으로 다 밀어 넣지 않아요.** Claude Code 공식 문서가 이렇게 씁니다 —
*"Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"* ·
*"If Claude already does something correctly without the instruction, **delete it or
convert it to a hook**."* 정량 근거도 있어요 (Chroma *Context Rot* 2025-07, 프런티어
18모델 / IFScale arXiv 2507.11538, 지시 500개 밀도에서 최고 모델 68%).

그래서 팩은 세 갈래로 갈라요 — **기계가 판정할 수 있는 건 hook·스크립트·테스트로**
(hook 정의는 `settings.json` 에 있고 모델 컨텍스트에 안 들어가요), 판정 불가능하지만
꼭 필요한 것만 최소 산문으로, 모델이 이미 잘하는 건 **아예 빼요.**

그리고 **삭제 루틴**을 같이 넣었어요. 모델 세대가 바뀌면 룰을 끄고 무엇이 실제로
깨지는지 재보는 절차예요 — 첫날 팩이 영구 부채가 되지 않게 하는 유일한 장치예요.

**나중에 붙는 자리 9개**를 미리 파 뒀어요 (폐기 어휘 lint · eval 임계값 · 스냅샷
짝비교 · 말뭉치 지문 · 구조 증명 · 절간 정합 · 감사 스크립트 · 실기기 함정 목록 ·
회귀 기준선). 전부 **before 상태가 있어야** 만들 수 있어서 첫날엔 못 깔아요.

### 네거티브 프로브

**차단이 살아 있는지를 첫날에 증명하고 시작해요.** 분석 대상 프로젝트가 첫날 저녁에
스스로를 감사해 "자동 집행 0개" 를 발견하고, 그 자리에서 배관을 만들고 *"core 에
react import → exit 2 차단 검증 완료"* 까지 밟은 게 근거예요. 반대로 CI 가 설치
실패로 **한 번도 안 돌면서 초록으로 보이던** 사고도 같은 리포에 있어요.

policy-as-code 실무 정설이 이걸 뒷받침해요 — *"A rule that looks like it enforces a
control can silently evaluate to 'undefined' instead of 'false,' and undefined is not
the same as denied."* 그래서 프로브는 첫날 1회가 아니라 **CI 에서 상시로** 돌아요.

## 새 skill — `parallel`

`spec-tasks` 와 `spec-implement` 사이에 앉아요. 실행은 `spec-implement` 가 하고,
이 skill 은 **가르는 법과 정지 조건**을 담당해요.

**첫 관문이 "가를 수 있는 일인가?" 예요.** 병렬은 기본값이 아니에요 — Anthropic 이
직접 이렇게 씁니다: *"Most coding tasks involve fewer truly parallelizable tasks than
research… LLM agents are not yet great at coordinating and delegating to other agents
in real time."* 멀티에이전트는 챗의 **약 15배 토큰**이고요. 판정 4문항 중 하나라도
걸리면 **단일 레인**으로 답하고 끝내요. *"Subagents are a partitioning tool, not a
speed button."*

**두 축이에요** — 조사·검토는 **역할/도메인**으로, 실행은 **파일 소유권**으로.

> Phase 는 *논리적* 순서고, 병렬 실행의 단위는 **누가 어떤 파일을 쓰는가**예요.
> 같은 파일을 두 레인이 만지면 Phase 가 달라도 충돌해요.

**탐색이 먼저예요.** 게이트는 `files:` 대조로 성립하니 탐색 전엔 **빈 데이터를 검사하고
통과**시켜요. *"ask for the change plan, not the change."*

**핫 파일은 두 정책이에요.** 레인마다 서로 다른 판단을 하려 하면 **독점**, 같은 종류의
기계적 변경이면(배럴·인덱스·등록부·라우팅 테이블·i18n 카탈로그) **떼어내서 순차 큐**로.
독점만 있으면 배럴 하나 때문에 병렬이 통째로 사라져요.

**완료는 체크박스 그리고 통합 검증이에요.** "레인 idle"·"에이전트가 보고함"·"Phase
끝남"은 전부 완료가 아니에요 — 실제로 레인 8개가 idle 이 됐을 때 체크박스는 24/36
이었던 사고가 있어요. 그리고 **파일이 안 겹친다 ≠ 합쳐서 동작한다** 예요. worktree
정설이 그대로예요 — *"git worktrees prevent parallel sessions from overwriting one
another's files on disk, but they do not prevent logical conflicts."* 의미적 충돌
다섯 종(공유 전역 설정 · DB 스키마 · 싱글턴 · 공유 인터페이스 · **같은 개념에 다른
이름**)은 어떤 게이트도 못 봐요.

### 새 스크립트 — `lanes-hotfiles.sh`

`tasks-plan.sh` 에 사각지대가 둘 있었어요. (a) 지금 blocked 인 task 가 나중에 만들
충돌을 안 보고, (b) **`files:` 가 없는 task 는 아예 검사에서 빠지는데 출력은
`violations: 0`** 이에요 — 검사가 안 된 걸 통과로 읽게 돼요. `hot[]` 과
`tasks_missing_files[]` 로 그 둘을 메워요. `tasks-plan.sh` 는 안 건드렸어요.

`_templates/spec/tasks.md` 에 §1.5 핫 파일 표를 넣고, `files:` 를 **필수**로 격상하고,
`의존:` 표기가 `없음`·`none`·`-` 셋만 인정된다는 것도 적었어요.

## 새 에이전트

`agents/lane-scout.md`(조사 레인, 역할/도메인 축) · `agents/lane-worker.md`(실행 레인,
파일 소유권 축). 실행 레인 정의에는 소유 파일 목록·금지 목록·"커밋하지 않는다"·
"명령과 출력을 인용한다"가 기본으로 들어가요.

## `up` §6 — 안내에서 인계로

`up` 의 greenfield 분기가 이제 안내만 내고 끝나지 않고 **`zero` 로 넘겨요.** 왜 넘기는지도
그 자리에 적었어요 — 안내만 하면 `domain_risk` 가 출고 예시로 남고, triage 가 `default_risk`(L0)로
흘려서 "즉시 작업, spec 불필요"로 가고, 역면접도 스킵된다는 인과입니다.

`zero` 는 `/zero` 직접 호출과 "`.ax/` 는 있는데 ADR 0개 + 코드 없음" 조건으로도 스스로 발동해요.

## 이번에 안 한 것

- **`triage` 에 "분할 가능성" 축 추가.** 넣지 않기로 했어요 — triage 는 요청 직후 30초
  분류라 **그 시점엔 어떤 파일을 건드릴지 몰라요.** 추측으로 답하면 그 추측이
  `current-task.json` 에 적혀 이후 모든 실행자의 전제가 돼요. 분할 가능성은 탐색 후에
  `parallel` 이 답하는 게 맞아요.

## 대조 리뷰에서 나온 것 — 0.5.1 로 넘김

0.5.0 을 만든 뒤 Claude Code 공식 문서·최신 논문·외부 프레임워크와 맞대어 봤어요.
전문: https://claude.ai/code/artifact/633c198c-9d4f-4730-8e19-5ca0abb09f2f

**지지된 것.** 하네스가 1급 변수라는 건 정량으로 섭니다 — Harness-Bench(arXiv 2605.27922,
태스크 106 · 트라젝토리 5,194)가 **같은 모델에서 하네스만 바꿔 76.2% vs 52.4%, 23.8점**을
보고하고, 실패 1위가 **contract/format violation 36.4%** 예요. 그게 `--json` 계약이 겨냥하는
자리라, goax 는 **"산문형 하네스"가 아니라 "계약형 하네스"** 로 서야 두 근거를 동시에 만족해요.

**발명이 아닌 것 둘.** 결정론 경계는 Temporal(`workflow`/`activity`) · OpenAI Agents SDK ·
Anthropic Skills · Claude Code(`hook`/`CLAUDE.md`)가 각각 다른 이름으로 긋는 같은 선이에요.
파일 소유권 병렬도 2026년 관행이고(AgentRoom `room_claim()` · spec-kit `[P]` · `/batch` 등),
좁은 차별점은 **계획 시점 자동 대조** 하나예요.

**고쳐야 할 것 — 다음 판.**

1. **도달 범위 지도.** 계층이 높을수록 멀리 간다는 그림이 뒤집혀 있어요. 실측하면 L2·Spirit
   (`PreToolUse` 주입)이 가장 멀리 가고, L1 Constitution 은 **Explore/Plan 에 안 닿고**,
   L0 Triage 는 `UserPromptSubmit` 이라 **서브에이전트에 구조적으로 도달 불가**예요.
   공식 문서 원문: *"Explore and Plan are the only subagents that omit CLAUDE.md and git status.
   There is no frontmatter field or per-agent setting to change which agents skip them."*

2. **`SubagentStart` hook 등록.** Explore/Plan 에 룰을 닿게 하는 유일한 공식 레버이고
   matcher 에 두 에이전트가 명시돼 있어요(`"Explore|Plan"` 은 정규식이 아니라 정확 문자열 2개로
   평가돼요). ⚠️ **출력은 반드시 `hookSpecificOutput` 안에 nest 해야 해요** — 같은 그룹인
   `UserPromptSubmit` 문서가 *"if you place it at the top level of the JSON, Claude Code silently
   ignores it"* 라고 못 박습니다. `SubagentStart` 의 코드 예제는 문서에 없으니 **실측하고 넣어요.**

3. **`Stop` hook 으로 완료 판정을 자기보고에서 뗀다.** `tasks-gate.sh` 가 검사하는 체크박스를
   채우는 주체가 검사받는 주체와 같아요. 공식 게이트 사다리에 Stop hook(스크립트가 통과할 때까지
   턴 종료 차단)이 올라 있어요.

4. **`zero-ablation.sh` 에 주기 강제.** 스크립트가 있는 것과 도는 것은 달라요.

5. **`parallel` 게이트 우회 차단.** 계획을 안 거치면 방어가 0 이에요. LangGraph 는 런타임이
   거부하는데 goax 는 계획서가 권고해요.

**`doctor` 검사 후보 하나** — Claude Code 는 `AGENTS.md` 를 **직접 읽지 않아요**
(*"Claude Code reads `CLAUDE.md`, not `AGENTS.md`"*). `CLAUDE.md` 없이 `AGENTS.md` 만 둔
프로젝트는 Constitution 이 **메인 세션에도 도달하지 않고, 에러도 경고도 없어요.**
