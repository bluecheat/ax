# Phase 경계 리뷰와 리뷰 보고

## Phase 경계 리뷰 — 선택

§4 의 Phase 경계에서, 이 세션은 다음 Phase 로 넘어가기 전에 방금 끝난 Phase 를 evaluator 에게 따로 보일 수 있어요.

언제 띄우나:
- 사용자가 "Phase 마다 리뷰" 를 원할 때
- 끝난 Phase 에 입력을 거르는 task (파서, upsert, 조건부 갱신, 검증 로직)가 있을 때
- 끝난 Phase 의 산출물에 다음 Phase 가 의존할 때 (§4 박스의 ❗ 주의 줄)

어느 것도 아니면 띄우지 않아요. 이유: 완료 리뷰(§8.1)가 전체를 다시 봐요. Phase 리뷰는 결함이 다음 Phase 로 번지기 전에 잡으려는 것이에요.

띄우는 방법은 §8.1 과 같아요 (`goax:evaluator`, 새 컨텍스트, `agent-model.sh evaluator` 의 모델). 브리프는 이것뿐이에요.

- "Phase 모드" 라는 한 줄
- spec — `$SPEC_DIR/spec.md`, tasks — `$SPEC_DIR/tasks.md`
- 이 Phase 의 task ID 목록과 그 task 들의 diff 범위 (Phase 시작 커밋부터, 또는 워킹 트리)
- 산출물 — `$SPEC_DIR/review-phase-<Phase 이름>.md`, 첫 줄 `verdict:`, 둘째 줄 `model:`
- `모델: <넘긴 값 또는 에이전트 기본값>`

결과 처리:
- `진행` — 다음 Phase 로 가요.
- `보강 필요` — 지적마다 이 Phase 안에 task 를 하나씩 추가하고(`T0xx` 다음 번호), 고친 뒤 다음 Phase 로 가요.
- `재논의 필요` — §6 halt 와 같아요. 사용자 결정을 받아요.

`review-phase-*.md` 는 G6 이 읽지 않아요. 완료 게이트는 여전히 §8 의 `review.md` 예요.

## 리뷰 지적을 사용자에게 올릴 때

이 세션은 evaluator, rules-auditor 의 지적을 두 묶음으로 나눠 보여줘요.

- **직접 확인함** — 이 세션이 코드를 열거나 명령을 돌려 다시 확인한 지적. 확인한 `파일:줄` 이나 명령을 같이 적어요.
- **리뷰어 주장** — 아직 확인하지 않은 지적. 어느 리뷰어의 주장인지 붙여요.

설정값이나 정책(타임아웃, 재시도 횟수, 캐시 TTL, 배치 크기 …)을 권고할 때는 그 값이 적용되는 호출처(온라인 요청, 배치, 관리자 화면 …)를 같이 적어요.
이유: 확인하지 않은 주장이 사실처럼 보이면 사용자가 무엇을 믿을지 가릴 수 없어요. 호출처가 빠진 권고는 배치에 맞는 값을 온라인 요청에 넣게 만들어요.
