# 레인 규율이 나온 사고들 — 왜 이 다섯 줄인가

> SKILL.md §10 의 브리프 다섯 줄은 전부 실제 사고에서 나왔어요. 규율을 바꾸거나 빼려 할 때 읽어요.
> 매 발동마다 실릴 필요는 없어서 여기로 옮겼어요.

## 실제로 터진 사고 다섯

1. **두 세션이 한 산출물** — 파운더가 렌더 비교로 채택한 안을 다른 세션이 모른 채
   덮었어요. 커밋 메시지·ADR 은 새 안을 말하는데 바이트는 옛 안이었어요.
   근본 원인: *"산출물을 기준으로 소유자를 세지 않았어요. 파일이 아니라 작업 단위로만
   범위를 갈랐어요."* → 브리프 첫 줄 "소유 파일 — 이 목록 밖은 절대 건드리지 마세요".
2. **`git add -A` 가 다른 세션 파일 3개를 쓸어담음** — *"동시 세션 환경에서 '워킹
   트리는 내 것'이라는 단독 점유 가정."* → "커밋하지 않아요. `git add -A` 는 특히 금지".
   `zero-guard-bash.sh` 가 이제 pre-bash 에서 막아요.
3. **위임 산출물이 아예 도착 안 함** — 세 에이전트가 241·96·167줄을 완성해 놓고
   `SendMessage` 없이 idle. 근본 원인: *"완료 판정을 '에이전트가 idle 인가'로 했고
   '산출물을 받았는가'로 하지 않았다."* → "결과를 반드시 `SendMessage` 로 전송" + §11.
4. **레인 idle 을 완료로 오독** — 레인 8개가 전부 idle 이 되자 완료로 인식했는데 그
   시점 체크박스는 24/36 이었어요. *"Phase 와 레인을 1:1 로 착각했다."* → §12.1 은
   `tasks-gate.sh` 만 완료를 판정해요.
5. **번호 충돌** — 동시 세션이 ADR 번호를 겹치게 만들었어요.
   `next-spec-num.sh --reserve --slug <slug>` 의 `O_EXCL` 선점이 이걸 막아요. 레인이 문서를 새로
   만든다면 번호는 반드시 이 스크립트로 받으세요.

## 정량 주장은 문서에 적히는 순간 위험해요

계획에 이런 오차가 남았어요 — "소비처 6곳"이 실제 10곳, "사용처 0"이 실제로는 렌더
중, "import 함"이 실제로는 안 함. 셋 다 **브리프에 "삭제 전 grep 하고 결과를 보고에
포함하라"를 넣은 덕에** 실행 단계에서 걸렸어요.

> 정량 주장은 1인칭으로 말하는 시점이 아니라 **문서에 적히는 시점**에 이미 위험해요.
> spec 에 들어간 "N곳"·"사용처 0" 은 그 뒤 모든 실행자가 전제로 삼아요. 원 출처가
> 서브에이전트면 **근거 명령을 함께 적어** 재확인 가능하게 해요.

## 통합 검증이 따로 필요한 이유 — 파일이 안 겹쳤다고 합쳐서 도는 건 아니에요

**파일 소유권은 물리적 충돌만 막아요.**

> "git worktrees prevent parallel sessions from overwriting one another's files on
> disk, **but they do not prevent logical conflicts.**"

지배적 실패 모드는 덮어쓰기가 아니라 **레인들이 암묵적으로 상충하는 결정을 내리는 것**
이에요 — 공유 스펙이 없어서요. 파일 경계와 무관하게 나는 것들:

- 공유 전역 설정 · 환경변수 · feature flag
- DB 스키마 · 마이그레이션 순서
- 싱글턴 · 전역 레지스트리
- 공유 인터페이스 · props 계약
- **같은 개념에 서로 다른 이름을 붙이는 것** ← 제일 조용해요

실측: 한 레인이 `Pill` 의 축을 `tone` → `variant` 로 바꿨어요. 다른 레인이 그걸
모른 채 치환했으면 조용히 깨졌을 거예요 (레인 간 인수인계로 막았어요). 두 레인 다
자기 파일만 만졌는데도요. 그래서 바뀐 공유 이름은 인계 노트 `renamed`
에 코디네이터가 적고(`status-note.sh --add renamed`), 레인이 전부 끝난 뒤 전체 검증을 한 번 더 돌려요.

## 서브에이전트 보고가 잘리는 문제

오늘 세션에서 서브에이전트 보고가 6번 잘렸어요. "다시 보내주세요" 만 하면 앞부분이 또 오고
또 잘려요. **잘린 지점을 지목**해서 이어 보내달라고 해요 — "T3 섹션 3번째 항목부터 다시
보내주세요". 그리고 "다시 하지 말고 이미 만든 결과를 그대로 전송하세요" 가 없으면 레인이 전체
작업을 처음부터 반복해요.
