# design-spec 템플릿 — 표 0~7 로 쓰는 화면 명세

## 목차

빈 칸 규칙 · 파일 위치와 갱신 규칙 · 표 0 공통 토큰 · 표 1 화면 · 표 2 부품 · 표 3 숫자 표기 · 표 4 문구 · 표 5 레이어 · 표 6 예외 케이스 · 표 7 자기 검수 (G1~G20)

설계 모드의 산출물은 아래 표 일곱 개를 **이 순서, 이 열 그대로** 채운 문서예요. 산문 설명은 표 앞뒤에 짧게 붙여도 되지만, 값은 표에만 있어요. 이유: 산문으로 쓰면 "상태를 안 적었다"·"단위 굵기를 안 나눴다"가 안 보여요. 표는 빈 칸이 보여요.

**빈 칸 규칙**: 빈 칸은 두 가지만 허용돼요. 값을 적거나, `해당 없음(이유)` 를 적거나. `—`·`TBD`·공란은 미완성이에요. 값이 다른 행과 같아도 "위와 같음"이라 쓰지 않고 값을 다시 적어요(구현자는 행 하나만 보고 만들어요).

**파일 위치와 갱신 규칙**
- 기본 경로는 `docs/design/design-spec.md` 예요. 프로젝트에 `design-system/` 디렉터리가 이미 있으면 `design-system/design-spec.md`. `design-caps.sh --json` 의 `result.spec` 이 지금 있는 파일을 알려 줘요.
- 파일이 있으면 **바뀐 행만** 추가·수정해요. 표를 통째로 다시 쓰면 다른 화면의 결정이 사라져요.
- 표 0 은 코드의 토큰 파일과 **이름·값이 일치**해야 해요. 다르면 둘 중 하나가 거짓말이에요 — 코드가 진실이면 표를, 표가 진실이면 코드를 고쳐요. 기존 토큰 값을 바꾸면 다른 화면이 깨질 수 있어서 그건 "결정 필요" 로 올려요.
- 표는 스크린샷보다 먼저 채워요. 화면을 그리고 나서 표를 맞추면 표가 화면의 결함을 그대로 베껴요.

## 표 0. 공통 토큰

프로젝트에 디자인 시스템이 있으면 이 표 대신 그 토큰 이름을 쓰고, 없을 때만 여기서 정해요. 없을 때의 출발점은 `color-type.md` 의 기본 팔레트·타입 램프·간격 스케일과 `component-systems.md` §12 예요.

| 토큰 | 값 |
|---|---|
| 본문 글자 | 예: 16 Regular, 행간 150% |
| 화면 타이틀 | 예: 28 Bold (= 본문 × 1.75) |
| 핵심 숫자 | 예: 32 Bold |
| 캡션 | 예: 13 Regular |
| 간격 스케일 | 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 |
| 화면 좌우 마진 | 예: 20 |
| 포인트 컬러 | 하나. 예: #2563EB — 주 CTA 와 선택 상태에만 |
| 무채색 | 배경 / 면 / 선 / 보조 글자 / 본문 글자 |
| 상태색(의미) | 성공 / 경고 / 오류 — 색만으로 구분하지 않고 아이콘·기호·텍스트를 붙임 |
| 라운드 | 예: 버튼 12 · 카드 16 · 칩 100% |
| 선 | 1px, 10~20% |
| 그림자 | 안 씀 / 쓰면 Y 4 · 블러 12 · 6% (자리 명시) |
| 아이콘 | 24, 굵기 2px, 정방형 가이드 박스 |

## 표 1. 화면 — 한 화면에 한 행

| 화면 | 핵심 정보(가장 먼저 보여야 할 것) | 가장 큰 글자 ÷ 본문 (실제 나눗셈) | 정보 순서 (위 → 아래) | 레이아웃 폭·마진 |
|---|---|---|---|---|
| 예: 출조 일정 목록 | 오늘 이후 가장 가까운 출조의 잔여 인원 | 28 ÷ 16 = 1.75 | 헤더 → 필터 진입 → 일정 행 목록 → 끝 안내 | 375, 좌우 20 |

비율이 1.75 미만이면 이 행에서 멈추고 큰 글자를 올려요. 시트·모달·팝업도 화면이에요 — 각각 한 행.

## 표 2. 부품 — 화면에 놓이는 부품마다 한 행

**탭·클릭할 수 있는 것은 전부 행이 있어야 해요**(행·칩·체크박스·스테퍼 +/−·캘린더 셀·X·링크·토글). 하나라도 빠지면 터치 영역과 상태를 안 적은 거예요.

| 화면 | 부품 | 크기 (높이 × 너비) | 터치 영역 | 패딩 / 간격 | 라운드 · 선 | 글자 (크기 / 굵기 / 색) | 상태: 기본 | 상태: 선택·포커스·눌림 | 상태: 비활성·마감 |
|---|---|---|---|---|---|---|---|---|---|
| 예: 일정 목록 | 일정 행 | 72 × 전체 | 72 × 전체 (행 전체 탭) | 상하 16 / 좌우 20 | 라운드 0 · 하단 1px 10% | 제목 16 Semi-bold #111 | 흰 배경 | 눌림: 배경 4% 그레이 | 마감: 글자 40% + "정원 마감" 뱃지 |
| 예: 예약하기 | 인원 스테퍼 − | 44 × 44 | 44 × 44 | 안 12 | 100% · 1px 20% | 아이콘 20 | 선 20% | 눌림: 배경 8% | 최소 1명: 아이콘 30%, 탭 무반응 |
| 예: 예약하기 | 장비 체크박스 행 | 56 × 전체 | 56 × 전체 (행 전체 탭) | 상하 16 / 좌우 20 | 체크 22, 라운드 4 | 라벨 16 Regular | 빈 체크 1px 30% | 선택: 포인트색 채움 + 체크 아이콘 | 재고 0: 라벨 40% + "대여 마감" |

상태 세 열은 **모든 행에 값이 있어야** 해요 (`principles.md` B1 의 상태 행렬). 정적 텍스트·구분선처럼 상호작용이 없는 부품만 `해당 없음(정적)`.

## 표 3. 숫자 표기 — 숫자가 나오는 자리마다 한 행

| 자리 | 숫자 (크기 / 굵기) | 단위·기호 (크기 / 굵기 / 색) | 예시 | 큰 값 처리 |
|---|---|---|---|---|
| 예: 일정 행 잔여 인원 | 16 Bold | 명 14 Regular Gray | **3** 명 | 두 자리까지 폭 확보 |
| 예: 일정 행 1인 요금 | 16 Bold | 원 14 Regular | **150,000** 원 | 천 단위 콤마, 7자리까지 |
| 예: 일정 행 출항 시각 | 16 Semi-bold | 오전/오후 13 Regular Gray | 오전 **04:30** | 24시간제 대신 오전/오후 + 새벽 배지 |
| 예: 결제 요약 합계 | 24 Bold | 원 16 Regular | **320,000** 원 | |

숫자와 단위를 한 글자 스타일로 적으면(예: "150,000원 16 Bold") 이 표를 안 채운 거예요.

## 표 4. 문구 — 사용자에게 보이는 글자마다 한 행

| 화면 | 자리 | 유형 | 문장 (그대로) | 상황 | 다음 행동 | 근거(정보 축) |
|---|---|---|---|---|---|---|
| 예: 예약하기 | 주 버튼 | 버튼 | 320,000원 결제하기 | 요약을 확인한 뒤 | 결제로 이동 | 기대 결과(금액)가 라벨에 |
| 예: 예약하기 | 인원 초과 | 오류(입력 검증) | 남은 자리가 2명이에요. 인원을 줄여 주세요 | 잔여보다 많이 선택 | 스테퍼를 줄임 | 상황 + 행동, 금지어 없음 |
| 예: 결제 | 결제 오류 | 오류(행동 실패) | 결제가 진행되지 않았어요. 카드를 바꾸거나 잠시 후 다시 시도해 주세요 | 결제 승인 거절 | 재시도·카드 변경 | 상황 + 행동 |
| 예: 내 예약 | 완료 | 완료 | 9월 21일(일) 04:30 해왕호 2명 예약됐어요 | 결제 성공 | 내 예약으로 이동 | 대상·수량·시각 셋 |
| 예: 내 예약 | 목록 0건 | 빈 상태 | 아직 예약한 출조가 없어요. 이번 주 일정을 둘러보세요 | 첫 방문 | 일정 목록으로 | 상황 + 행동 |

**반드시 있어야 하는 행**: 화면마다 주 버튼 1행 · **실패할 수 있는 행동마다 오류 1행**(결제·전송·저장·불러오기·**입력 검증 초과**·오프라인) · 완료 1행 · 목록이 있으면 빈 상태 1행 · 취소·삭제가 있으면 확인 대화상자 1행(버튼 둘 다 결과가 드러나는 라벨).

**금지어 검색**: 표를 다 채운 뒤 **"문장" 열만** 골라 `실패`·`불가`·`유효하지`·단독 `확인`·단독 `완료`·`오류가 발생`을 찾아 건수를 표 아래에 적어요 — 명령은 `ux-writing.md` §12 그대로 (파일 전체를 grep 하면 "유형" 열의 `완료` 가 걸려요). 다른 언어는 §12 의 같은 역할 낱말. 0건이라야 해요. 버튼 라벨은 행동 동사형만(명사형 "초기화"·"필터"는 "필터 지우기"·"선박 고르기"로).

## 표 5. 레이어 — 바텀시트·모달·팝업·드로어마다 한 행

| 레이어 | 여는 곳 | 스크롤 소유 | 닫는 법 ① | 닫는 법 ② | 닫는 법 ③ | 딤 | 높이·라운드 |
|---|---|---|---|---|---|---|---|
| 예: 선박 필터 시트 | 목록 상단 필터 버튼 | 시트 내부 독립, 뒤 화면 고정 | 인디케이터·헤더 아래로 드래그 | 바깥 딤 탭 | 우상단 X (터치 44) + 하단 "적용하기" | 30% | 최대 80%, 라운드 20 |

셋 중 하나를 라이브러리 이름으로 대신 적으면 안 채운 거예요.

## 표 7. 자기 검수 — 게이트마다 명세 값

행은 SKILL.md "## 6. 게이트" 의 G1~G20 과 **같은 수 · 같은 순서**예요. 행을 빼거나 합치지 않아요 — 해당이 없으면 `해당 없음(이유)` 를 적어요.

| 게이트 | 명세 값 | 통과 |
|---|---|---|
| G1 화면 · 시트마다 핵심 정보 한 줄 | 표 1 행 수 = 화면 수 (N/N) | ✅ / ❌ |
| G2 가장 큰 글자 ÷ 본문 ≥ 1.75 | 표 1 각 행의 나눗셈 | |
| G3 간격 값이 전부 스케일 안 | 표 2 패딩/간격 열에서 스케일 밖 값: 0건 | |
| G4 주 버튼 · 인풋 높이 ≥ 44, 화면을 넘어 같은 값 | 표 2 주 버튼·인풋 행의 높이 — 같은 부품 이름끼리 다른 값 0건 | |
| G5 화면 좌우 마진 · 카드 안쪽 여백이 화면을 넘어 같은 값 | 표 0 화면 좌우 마진 + 표 1 마진 열 + 표 2 카드 패딩 — 다른 값 0건 | |
| G6 포인트 컬러 1개, 상태색은 아이콘 · 기호와 함께 | 표 0 포인트 · 상태색 + 표 2 포인트가 쓰인 행 | |
| G7 탭 가능한 부품마다 터치 영역 ≥ 44 | 표 2 터치 영역 열, 빈 칸 0 · 44 미만 0 | |
| G8 선택형 부품마다 선택 / 비선택 / 비활성 세 상태 | 표 2 상태 세 열, 빈 칸 0 | |
| G9 레이어마다 스크롤 소유 + 닫는 법 셋 | 표 5 빈 칸 0 | |
| G10 버튼 라벨 행동 동사형, 상태어 없음 | 표 4 유형=버튼 행 전수 | |
| G11 금지어 0건 | 표 4 문장 열 검색 건수 (`ux-writing.md` §12 명령) | |
| G12 실패할 수 있는 행동마다 오류 문구 | 표 4 유형=오류 행 수 = 행동 수 | |
| G13 완료 문구가 대상 · 수량 · 시각 중 둘 이상 | 표 4 유형=완료 행 | |
| G14 숫자 + 단위는 크기 또는 굵기를 분리 | 표 3 빈 칸 0 | |
| G15 같은 라벨 · 같은 행동 버튼이 한 화면에 하나 | 표 4 유형=버튼 행을 화면별로 묶어 중복 0건 | |
| G16 하단 고정 CTA 가 있으면 뒤 배경 페이드 + 스크롤 하단 여백 | 표 2 CTA 행 + 표 6 | |
| G17 다크 테마면 배경 · 카드 · 보조 버튼 · 비활성 면이 눈으로 갈림 | 표 0 레이어 표면 값 (명도 단계) | |
| G18 사용자 상태를 말하는 문구는 보여 주는 순간 참 | 표 4 해당 행의 "상황" 열 | |
| G19 긴 문자열 · 큰 숫자 · 320 처리 | 표 6 | |
| G20 글자 대비 — 본문 4.5:1, 큰 글자 · 아이콘 3:1 | 표 0 글자색 · 포인트 대비 값 (`color-type.md` §6) | |

통과 열은 ✅ 또는 ❌ 만 써요. **명세 값 열이 비어 있으면 그 행은 ❌ 예요** — 숫자 없이 ✅ 를 치지 않아요. `해당 없음(이유)` 는 이유가 구체적일 때만 통과로 쳐요 ("화면 하나 — 교차 비교 대상 없음" · "다크 테마 없음"). ❌ 가 하나라도 있으면 산출물을 넘기지 않고 그 표로 돌아가요.

표 7 은 **명세 단계의 자기 검수**예요. 화면을 만든 뒤의 실측 게이트는 screen-designer 리포트의 게이트 표가 같은 G1~G20 으로 맡아요 — 표 7 의 숫자는 "명세에 적힌 값", 리포트의 숫자는 "화면에서 잰 값(출처 포함)" 이에요. 둘이 다르면 구현이 명세를 안 따른 거예요. 명세에 적었다는 것만으로 리포트의 동작 게이트(G9 · G12 · G16 · G18 · G19)가 ✅ 가 되지는 않아요.
