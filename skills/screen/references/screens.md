# 화면 유형별 가이드 — 18종

화면마다 **핵심 정보(primary content) → 위에서 아래 정보 순서 → 레이아웃 → 흔한 실수 → 전/후** 순서예요. 부품 수치는 `components.md`, 문구는 `ux-writing.md`. "이 가이드에 없음" 은 지어내지 않은 자리예요.

- 수치는 1배수 논리 단위(pt · dp · CSS px)예요. 웹 폭은 1080·1280·1440, 모바일은 375 기준이에요.
- 핵심 정보는 `spec-template.md` 표 1 의 둘째 열에 그대로 옮겨요. 시트·모달도 화면이에요 — 각각 한 줄.
- 여기 없는 유형은 SKILL.md 의 "화면이 하는 일 → 가져올 유형" 표로 가장 가까운 유형에 붙여요. 도메인 이름(농장·정비소·학원)으로 찾지 않아요.
- 랜딩·포트폴리오는 파격 허용 화면이에요 — 이 파일의 전/후와 함께 `bold-mode.md` 를 읽어요.

- **레이아웃**: 375×812/894 **첫 화면 안에 전부 노출**, 스크롤 없음.
- **실수**: 상단 여백·로고·인풋이 커서 회원가입 문구가 화면 밖, 상단 그레이 박스·이펙트, 포커스 선·X·눈 아이콘 없음, 소셜 버튼과 일반 버튼 라운드 불일치, 약관 동의 화면에 거대 그래픽이 중앙을 차지, 체크박스 12px.

## 3. 상품 목록 · 카테고리 · 필터

- **핵심 정보**: 썸네일과 가격·할인율.
- **순서**: 경로 → 상단 필터·정렬·상품 수 → 카드 그리드(이미지 → 브랜드 → 상품명 → 가격 → 별점) → 페이지네이션·무한 스크롤.
- **레이아웃**: 썸네일 1:1 통일. 웹은 좌측 필터 + 우측 그리드 또는 상단 필터 + 풀배열.
- **실수**: 비율 혼용, 딤 필터 레이어에 독립 스크롤·적용 버튼 없음, 선택 상태 불명, 카테고리 탭 **최대 글자 수** 미고려, 선택 칩 초기화 버튼 없음.
- **전/후**: → 1:1, 브랜드 14 / 상품명 15 / 가격 16~20 Bold / 별점 12~14, 적용하기 고정, 체크마크, 10글자 이상 여백 확보, 칩이 2줄로 늘면 아래가 밀리는 구조, 전체 삭제 버튼.

## 4. 상품 상세

- **핵심 정보**: 대표 이미지와 가격·혜택·구매 버튼.
- **순서**: 대형 이미지·360° → 브랜드·상품명 → 가격·할인율·쿠폰 → 배송 정보(배송비·일자·도서산간) → 옵션 칩 → 하단 고정 CTA → 상세·리뷰 탭.
- **레이아웃**: 웹 5:5(좌 1:1 이미지 / 우 정보 패널). 모바일 상단 1:1 → 수직 → 하단 고정 바.
- **실수**: 배송 정보 누락, 이미지 위 배경 카드 오버랩, 옵션 선택 피드백 불명, 구매 버튼이 과대하고 대비가 강해 이미지를 압도, 상단에 뜬금없는 커뮤니티·공지 배너, 상품명이 가격보다 큼(40px+), 이중 할인가 없음.
- **전/후**: → 1:1 대형 이미지, 360°·컬러칩을 상품 아래로, 상품명 20~24 (웹 32), 가격 24~32 (웹 40~44) Bold, 취소선 정가 옆 배치, 칩 24/34 + 체크, 구매 48~56, 구매·찜·공유를 하단 탭바(독바) 하나로.

## 5. 장바구니 · 주문 · 결제

- **핵심 정보**: 총 결제금액과 결제하기.
- **순서**: 배송지(수령인·연락처·주소·변경·직접 입력) → 상품 목록(작은 썸네일·수량·가격) → 쿠폰·포인트 입력(+모두 사용) → 결제 수단 → **영수증 그룹**(총 상품금액 → 할인 −(위험 역할 색) → 최종 결제금액 대형 Bold → 적립 +) → 하단 고정 결제하기.
- **레이아웃**: 흰 바탕 영수증 세로 스택.
- **실수**: 연락처·직접 입력 누락, 썸네일이 주문서에서 거대(이미 본 것), 최종 금액과 적립을 묶고 할인을 따로 떼는 **개념 오류**, 할인에 − 없음, 카드 2~3중, 브랜드 파란색 난발.
- **전/후**: → 연락처·직접 입력 추가, 썸네일 축소, 영수증 통합(최종 24+ Bold / − / +), 카드·그레이 삭제 후 1px, 결제 48~56.

## 6. 요금제 · 플랜 비교

- **핵심 정보**: 가격 수치와 시그니처 플랜의 선택 버튼.
- **순서**: 제목 → 결제 주기 탭 → 플랜 컬럼(플랜명 → 가격 → 기능 목록 → CTA).
- **레이아웃**: 세로 3~4컬럼 병렬, 1080/1280.
- **실수**: 가격이 구석에 작게, 속성을 가로로 배치해 비교 불가, 무료·현재·상위 플랜 버튼이 전부 같은 원색, 기능을 아코디언으로 접어 비교 불가.

## 10. 랜딩 · 브랜드 소개

- **핵심 정보**: 슬로건 타이틀과 비주얼 퍼포먼스.
- **순서**: GNB → 대형 히어로·슬로건 → 핵심 가치·스토리 → 컬렉션·프로덕트 → 동영상 → 푸터.
- **레이아웃**: 풀배열, 비대칭. 1080 세로 한 화면 안에 타이틀 + 키비주얼 + CTA 가 한눈에.
- **실수**: 일반 UI 처럼 타이틀·여백이 좁아 퍼포먼스 약함, 형광·원색 도배, 이미지와 타이틀 평면 배치, 3D·오버랩·지그재그 남발, 이미지를 늘려 찌그러뜨림.

## 11. 포트폴리오 (목차 · 프로필 · 프로젝트)

- **핵심 정보**: 직무 정체성과 프로젝트별 UX 문제 해결 과정·Before/After.
- **순서**: 인트로·프로필(직무 하나 명시 + 이력) → 목차 → 타임라인·기여도 칩 → 문제 정의·리서치 → IA → UI 개선(Before vs After) → 디자인 시스템(폰트·컬러) → 연락처.
- **실수**: "디자이너/퍼블리셔" 모호 표기, 퍼블리싱 기교(스크롤·글래스)는 화려한데 UX 근거가 비어 있음, 그레이 박스 중복, 목차를 지그재그 타임라인으로, 프로필에 그라디언트 도형·대형 인물 사진으로 학력·경력이 안 읽힘, 프로젝트 페이지에 의미 없는 강조색·박스.
- **전/후**: → 주 직무 하나("퍼블리싱이 가능한 UI/UX 디자이너"), 기교 삭제(필요하면 PDF), 화이트 바탕, 문제 정의 → 리서치 → IA → 개선 기재, 목차는 일렬 + 넘버링(01, 02), 프로필은 사진 축소·텍스트 중심, '빼는' 원칙.

상품이 없는 서비스(일기장·메모·헬스케어·핀테크·커뮤니티·B2B 도구)는 아래 피드·에디터·캘린더·빈 상태·온보딩·설정·통계 유형부터 봐요. 도메인 특유의 규제·접근성 기준은 별도로 검사해요.

## 12. 피드 · 타임라인 (일기·게시글·알림·활동)

- **핵심 정보**: 가장 최근 항목 하나. 화면을 열면 "새 것이 있나"가 먼저 읽혀야 해요.
- **순서**: 헤더(제목 또는 날짜) → 작성 진입(있으면 상단 고정 또는 플로팅) → 항목 리스트(최신순) → 끝 안내(더 없음 / 더 불러오기).
- **레이아웃**: 항목은 리스트 행 또는 단일 카드. **카드 안 카드 금지**, 항목 사이 구획은 여백(16~24) 또는 1px 선. 항목 안 순서: 날짜·시간(13~14 Gray) → 제목(16~18 Semi-bold) → 본문 요약 2~3줄(15~16, 행간 150%) → 보조(태그·사진 수·감정 아이콘 12~14).
- **흔한 실수**: 항목마다 그림자 있는 카드로 감싸 피드가 무거움, 날짜가 제목보다 큼, 본문 요약이 잘리지 않고 끝까지 펼쳐져 한 화면에 한 항목만 보임, 작성 버튼이 스크롤에 밀려 사라짐.
- **규격**: 항목 상하 패딩 16~20, 좌우 마진 16~20. 플로팅 작성 버튼 56 원형, 우하단 마진 16~24, 탭바 위 16. 요약은 3줄 말줄임.
- **빈 상태**: 항목 0개면 리스트 자리에 상황 한 줄 + 행동 버튼 하나("첫 일기를 써 보세요" 같은 기대 결과형). 일러스트는 선택, 있어도 화면 1/3 이하.
- **예외**: 하루에 여러 항목이면 날짜 헤더로 묶고(섹션 헤더 14 Semi-bold Gray, 위 24 / 아래 8), 사진이 많은 항목은 첫 장만 1:1 또는 4:3 썸네일 + "+N".

## 13. 글쓰기 · 에디터 (긴 글 입력)

- **핵심 정보**: 본문 입력 영역. 화면의 70% 이상을 본문에 줘요.
- **순서**: 헤더(닫기 X · 날짜 또는 제목 · 저장 버튼) → 제목 필드 → 메타(감정·태그·날짜 선택 칩) → 본문 → 키보드 위 액션 바(사진·태그·글자 서식).
- **레이아웃**: 제목 필드는 테두리 없는 큰 글자(22~24 Semi-bold, 높이 44~48, 플레이스홀더 Gray). 본문은 16~17 Regular, **행간 160~170%**(읽고 쓰는 긴 글은 UI 본문보다 넓게), 좌우 마진 20~24, 한 줄 30~40자. 키보드 위 액션 바 높이 44~48, 아이콘 24 굵기 2px, 배경 화이트 + 상단 1px 선.
- **저장**: 자동 저장이면 헤더에 "저장됨 · 방금" 같은 상태 텍스트(13, Gray)를 두고 버튼은 "완료"가 아니라 "닫기" 또는 "쓰기 마치기". 수동 저장이면 주 버튼 하나(포인트 컬러), 비활성 조건(본문 0자)을 명시.
- **흔한 실수**: 제목·본문·메타가 전부 같은 크기, 본문 행간이 UI 본문 그대로(130%)라 빽빽, 툴바 아이콘이 열 개 넘게 나열, 저장 버튼이 키보드에 가림, 사진을 본문 위 큰 영역에 고정해 본문이 아래로 밀림.
- **예외**: 긴 제목은 2줄까지 늘고 그 이상 말줄임 없이 스크롤. 사진 여러 장은 본문 아래 가로 스크롤 썸네일(64~80, 간격 8). 320 은 액션 바 아이콘을 5개 이하로 줄이고 나머지는 더보기.
- **문구**: 저장 못 했을 때 "저장하지 못했어요. 연결을 확인하고 다시 시도해 주세요" 처럼 상황 + 행동. 나가기 확인은 "쓰던 글을 저장할까요?" + "저장하고 나가기 / 저장 안 하고 나가기".

## 15. 빈 상태 (Empty State)

- **핵심 정보**: 왜 비었는지 한 줄과 다음 행동 하나.
