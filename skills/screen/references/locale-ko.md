# 한국어 UI 프로필 — 국내 앱 관례 · 문체 · 줄바꿈 · 표기

한국어 화면을 만들 때만 읽어요. 국내 앱 화면 약 350장을 직접 읽고 뽑은 공통 패턴이에요 — 생활 기록·운세·건강 측정·부동산 진단 같은 **라이프스타일 앱**과 금융·간편결제·증권·중고거래 같은 **메이저 앱**을 함께 봤어요. 수치는 화면에서 추정한 값이라 범위로 읽고, 프로젝트 토큰이 있으면 그쪽이 이겨요. 벤치마킹 원칙(`process.md` §6)대로 겉모습이 아니라 **왜 그렇게 했는지**를 가져와요.

## 1. 메이저 앱과 라이프스타일 앱 — 먼저 어느 결인지 정해요

| | 메이저 (국내 금융·간편결제·증권 앱) | 라이프스타일 (국내 기록·운세·진단 앱) |
|---|---|---|
| 위계를 세우는 수단 | 흰(검은) 바탕 + 글자·숫자 크기만 | 카드·색 면·캐릭터·일러스트 |
| 포인트 컬러 | CTA 하나에만 | 칩·그래프에 여러 색 |
| 구획 | 여백과 1px 구분선 | 카드·색 띠 |
| 감정 | 싣지 않음 (사실만) | 캐릭터·이모지로 실음 |

업무·금융·결과를 보여 주는 화면이면 메이저 결이 기본값이에요. 라이프스타일 쪽 장치는 명분(감정을 실어야 하는 화면)이 있을 때만 빌려요. 어느 결을 따를지는 사용자가 정할 몫이라 "결정 필요" 에 후보로 올려요.

## 2. 부품 공통 패턴 8

### 2-1. 결과 화면 = 결론 한 줄 앵커 + 근거 행

- 관찰: 부동산 안전 진단 앱의 "모두 안전하다는 것을 확인했어요" 한 줄 아래로 항목(가처분 · 가압류 …)이 한 행씩, 행 우측에 짧은 상태 태그("해당 내역이 없어요"). 주기 기록 앱의 "최근 주기가 모두 정상 범위예요" 바로 밑에 막대그래프.
- 왜: 1초 안에 결론이 읽히고, 의심하는 사람만 내려가 근거를 확인해요. 앵커 하나 + 근거는 행.
- 규격: 결론 28 급 (본문 대비 1.75배 이상), 근거 행은 `좌 항목명 / 가운데 한 줄 설명 / 우 상태 태그`, 카드 없이 구분선.

### 2-2. 리포트 섹션 = 굵은 제목 + 회색 부제 한 줄 + 시각화

- 관찰: 감정 기록 앱 "자주 기록한 감정 / 가장 많이 등장했던 감정들만 모아봤어요", 부동산 진단 앱 "이 집의 위험요소 / 지금 이 집에 걸려있는 정말 위험한 주의사항만 가져왔어요".
- 왜: 제목은 무엇, 부제는 왜 봐야 하는지. 부제가 있어야 시각화가 해석돼요.
- 규격: 섹션 사이 여백 40 급 (또는 8 높이 회색 띠). 섹션마다 카드를 두르지 않아요.

### 2-3. 큰 숫자 + 작은 단위

- 관찰: "375일", "83%", "48.75kg", "$14.70" (화면 폭 절반 크기), "1,000원".
- 왜: 숫자가 앵커예요. 단위가 같은 크기면 숫자가 안 튀어요.
- 규격: 숫자 32~48 / 단위 15 급, 굵기도 숫자만 Bold. `spec-template.md` 표 3 이 이걸 강제해요.

### 2-4. 주 버튼은 하단 전폭 하나, 보조는 1:2 회색

- 관찰: 증권 앱 "취소 | 이체하기" (약 1:2), 간편결제 앱 "카드 추가" (전폭), 운세 앱 "다시 선택 | 결과 보기", 감정 기록 앱 "예시 구경하기 | 홈으로 가기".
- 왜: 엄지 자리 + 다음 행동이 하나라는 신호.
- 규격: 높이 48~52, 보조는 좁은 회색 또는 텍스트 버튼. 색은 주 버튼에만. 국내 모바일 앱 주 CTA 는 52 가 가장 흔해요.

### 2-5. 리스트 행 = 좌 아이콘 + 제목 + 회색 보조 줄 + 우 값/꺾쇠

- 관찰: 간편결제 앱 포인트 행 (우측 알약 칩), 은행 앱 설정 행 ("사용하기 >"), 지갑 앱 거래 행 (우측 금액), 중고거래 앱 매물 행. 전부 카드 없이 여백·구분선.
- 규격: 아이콘 32~40, 행 높이 56~72, 구분선 1px 10~20%. 좌우 여백 16 이 가장 흔해요.

### 2-6. 칩은 선택 하나만 채움

- 관찰: 부동산 진단 앱 "위험요소 · 내 순서 확인 · 원본문서", 은행 앱 금액 칩 "100만 500만 1천만", 건강 측정 앱 "개별 기록 · 일 누적 · 주 누적".
- 규격: 선택 = 검정(다크면 흰) 채움 + Bold, 비선택 = 연회색 알약. 포인트 컬러를 칩 선택에 쓰지 않아요.

### 2-7. 촬영 화면 = 검정 배경 + 점선 윤곽 가이드 + 안내 한 줄 + 조건 칩

- 관찰 (운세 앱 얼굴 촬영): "가이드에 얼굴을 정확히 맞춰주세요." + [밝은 조명] [정면사진] [무표정] 칩. 촬영 전 바텀시트 "얼굴 촬영 가이드" (좋은 예 / 나쁜 예 + 불릿), 분석 중 진행 표시, 완료 "이제 결과를 볼 수 있어요.", 첫 화면 하단 회색 "사진은 서버에 저장되지 않고…". 세탁 앱도 "세탁물 1개 전체가 보이도록 촬영해주세요" + 옷 윤곽 점선.
- 왜: 실패 원인(어두움 · 측면 · 표정)을 찍기 전에 없애야 결과 품질이 서요.
- 주의: 진행률은 실제 단계에 맞춰요. 시간으로 흘러가는 가짜 % 는 신뢰를 깎아요.

### 2-8. 완료 화면 (메이저) = 큰 숫자 → 회색 두 줄 → 상세 행 → 전폭 확인 버튼

- 관찰: 증권 앱 "○○님에게 이체 완료 / 1,000원" + 거래시간 행 + 하단 버튼, 지갑 앱 "$14.70 / 장소 / 시각".
- 위험 행동만 위험 역할 색: 간편결제 앱 "카드를 삭제하시겠습니까 / 취소 | 삭제(빨강)".
- 이 skill 에선 완료 문구에 대상·수량·시각 중 둘을 담고, 하단 버튼은 단독 "확인" 대신 다음 행동("내 예약 보기")으로 써요.

## 3. 문형 — 푸시 · 결과 헤드라인

### 3-1. 푸시 — 제목 = 무슨 일(명사), 본문 = 그래서 이제 할 수 있는 것

- "대출 결과 / 최저금리와 최대한도를 확인할 수 있어요."
- "등록 완료 / 이제 간편결제로 3% 적립 받을 수 있어요."
- "포인트 도착 / 2원 받았어요" — 이모지를 쓴다면 보상 알림에만.
- "11월 가계부가 도착했어요!", "결과 나왔어요 / 내 점수, 합격선 넘었는지 체크!"
- "한밤중 선선한 바람이 찾아올 운세예요", "공복 상태에서 측정해보세요 / 상쾌한 아침, 지금이 측정하기 딱 좋아요"
- 길이: 제목 2~8자 명사구, 본문 한 문장 20~35자.
- 후킹 장치 넷: 구체 숫자("20원" · "3%") · 결과 도착형("결과 나왔어요" · "…가 도착했어요") · 장면·시각("상쾌한 아침") · 이름 부르기("○○님").
- **로컬 예약 푸시는 보내는 순간 참인 말만.** 예약 시점엔 사용자가 그날 앱을 열었는지, 보상을 받았는지 몰라요. "7일째 기록 중" · "배지를 받아요" 같은 상태 약속은 서버가 그 순간 상태를 보고 보낼 때만. 로컬이면 어느 시각·요일에도 참인 질문형이 안전해요.

### 3-2. 결과·리포트 헤드라인 — 시간 범위 + 관찰한 사실 + ~했어요/~예요

- "주로 새벽에 답답한 감정을 느꼈어요", "지난 달보다 평균이 1.8점 내려갔어요", "운동을 기록할 때는 기분이 좋았어요"
- "최근 주기가 모두 정상 범위예요", "물 8잔 마시기 시작한 지 375일 됐어요!"
- 판정어(좋다 · 나쁘다)보다 사실을 서술해요. 사실이 판정을 대신하니 거부감이 적어요.
- 권유형 서비스(운세 · 코칭)는 "사실 + 오늘 할 일" 을 한 줄에 묶어요. 헤드라인을 요일 · "오늘은" 같은 여는 말로 시작하면 누구에게나 맞는 말이 돼요 — 첫 어절은 할 일의 대상(답장 · 장바구니 · 점심 약속).

## 4. 문체 (~해요)

- 국내 앱 대부분 — 메이저·라이프스타일·리포트 모두 — 해요체("~했어요" · "~예요")가 기본이에요. 합쇼체("~습니다")는 공지·약관·주의가 필요한 자동 메시지에만 (`principles.md` D8).
- 반말 앱("안녕! 오늘은 어떤 감정이야?")은 친구형 캐릭터 앱의 선택이지 기본값이 아니에요.
- 한 서비스 안에서 문체를 섞지 않아요. 버튼 라벨은 문체와 상관없이 동사형 명사구("결제하기" · "다시 시도하기").
- 겹높임 줄이기: "-하실 수 있어요" → "-할 수 있어요". 이름을 부를 때만 "님" (`principles.md` D3).
- 한자어보다 일상어: "불가능합니다" → "할 수 없어요", "유효하지 않습니다" → 무엇이 틀렸는지.

## 5. 금지어와 대체

`ux-writing.md` §12 의 한국어 목록이 게이트예요. 사용자에게 보이는 문구 전체에서 아래를 검색해 **0건**이어야 해요.

| 금지 | 대체 방향 | 예 |
|---|---|---|
| 실패 | 상황 + 다음 행동 | "결제가 진행되지 않았어요. 카드를 바꾸거나 잠시 후 다시 시도해 주세요" |
| 불가 | 지금 안 되는 이유 + 언제·어떻게 | "지금은 주문할 수 없어요. 오후 5시에 다시 열어요" |
| 유효하지 않 | 무엇을 어떻게 고치나 | "휴대폰 번호 11자리를 입력해 주세요" |
| 단독 "확인" | 결과 동사 | "320,000원 결제하기" · "내 예약 보기" |
| 단독 "완료" | 대상·수량·시각 중 둘 | "9월 21일(일) 04:30 해왕호 2명 예약됐어요" |
| 오류가 발생 | 원인 + 행동 | "연결이 끊겼어요. 연결되면 자동으로 다시 보낼게요" |

맥락에 따라 예외: 환불처럼 예민한 정책 안내는 "환불이 불가해요" 처럼 단호한 말이 오해를 줄일 때가 있어요 — 쓴다면 리포트에 근거를 적어요.

## 6. 어절 줄바꿈

좁은 칼럼에서 "…쉴까\n요?" 처럼 한 음절만 떨어지면 읽기가 끊겨요. 한국어는 **어절(띄어쓰기) 단위**로만 줄을 바꿔요.

| 스택 | 설정 |
|---|---|
| 웹 | `word-break: keep-all;` + 긴 URL·영문 대비 `overflow-wrap: anywhere;` |
| React Native (iOS) | `<Text lineBreakStrategyIOS="hangul-word">` |
| React Native (Android) | `textBreakStrategy="simple"` 로는 부족할 때가 있어요 — 칼럼 폭을 넓히거나 문장을 짧게 |
| Flutter | 기본 줄바꿈이 음절 단위라, 필요한 자리에 줄바꿈을 직접 넣거나 어절 사이 공백을 줄바꿈 가능 지점으로 남겨요 |
| SwiftUI · UIKit | `lineBreakStrategy = .hangulWordPriority` (UIKit), SwiftUI 는 UIKit 브리지 또는 직접 줄바꿈 |
| Android (View) | `android:lineBreakWordStyle="phrase"` (API 33+) — 한국어에 적용되는 범위는 OS 버전마다 달라요. 스크린샷으로 확인해요 |

그래도 남으면 칼럼을 넓히거나 한 단으로 바꾸거나 문장을 줄여요. 스크린샷에서 한 음절 줄을 찾는 건 `measure.md` §4 체크리스트 항목이에요.

**자간**: 한글 글꼴의 타이틀 · 본문은 기본 자간이 넓어 −2 ~ −3% 로 좁혀요 (큰 글자일수록 좁게, 캡션 13 이하는 0 ~ −1%). 라틴 글꼴만 쓰는 화면엔 이 값을 옮기지 않아요 — 그 글꼴의 기본 자간을 써요.

## 7. 숫자 · 날짜 · 단위 표기

- 금액은 천 단위 쉼표 + 단위 "원" 을 숫자 뒤에 작게: **150,000** 원. 큰 금액은 "1억 2,000만 원" 처럼 만·억 단위로 끊어 읽히게.
- 시각은 "오전 10시 33분" · "오전 04:30" 처럼 오전/오후. 새벽 시각엔 "새벽" 배지를 따로 두면 오독이 줄어요.
- 날짜 축약은 `2026. 3. 31.` 처럼 마지막 점까지. 요일은 괄호: "9월 21일(일)".
- 구간은 하나로 통일 — "3~5일" 또는 "3-5일" 중 하나.
- 수량 단위(명 · 장 · 회 · 개)는 화면마다 하나로 잡고 섞지 않아요.

## 8. 레퍼런스를 볼 곳

|---|---|---|
| 국내 앱 화면 갤러리 서비스 | 국내 앱 화면을 UI 패턴(푸시 · 통계 · 리포트 · 촬영 · 메인) × 카테고리(일상 · 금융 …) 로 필터, 이미지 속 글자 검색 | 무료 범위가 좁은 곳이 많아요. MCP 로 붙어 있으면 `capabilities.md` 의 reference 슬롯 |

| 해외 화면 갤러리 서비스 | 해외 중심 플로우 | 대개 유료 |
| 직접 써 보기 | 같은 업종 상위 앱 3곳을 설치해 같은 과업을 끝까지 | 가장 확실해요 (`process.md` §6) |
