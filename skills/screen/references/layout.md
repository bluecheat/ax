## 1. 기본기의 정의

감각이 아니라 **기준**으로 디자인하는 능력. 구성 요소는 다섯:

1. **글자 크기와 계층** — 타이틀·서브·본문의 강·중·약을 크기와 굵기로. 모바일 본문 최소 13~14.
2. **자간·행간** — 행간은 어간(띄어쓰기)보다 무조건 넓게(140~150%). 자간은 −2~−3% 로 타이트하게.
3. **여백의 체계화** — 요소·코너 사이를 20~24 이상, 일정하게.
4. **부품 규격 기준치** — 터치·버튼 40~56 등 가이드 수치 준수.
5. **공통 UI 규칙** — 페이지마다 인풋·셀렉트·버튼을 다르게 그리지 않고 하나로.

기본은 폰트가 먼저 잡혀야 해요. 이게 안 잡히면 뭘 해도 어색해요. 필요 없는 것, 의미 없는 것은 넣지 않아요.

**느낌으로 디자인** = 컨셉보드의 예쁨만 모방해 최소 크기 미달의 글자·버튼·어긋난 정렬을 감각으로 배치, 페이지마다 다르게. **기준을 가지고 디자인** = 페이지마다 다르게 그리지 않고 공통 요소는 공통 규격으로 맞추는 개념 + 디폴트/호버/선택/입력 완료 상태까지 설계.

## 2. 레이아웃 잡는 순서

1. **텍스트 계층·가독성 100% 먼저** — 박스·그래픽을 그리기 전에 전달할 내용의 중요도(1~4순위)와 글자 크기·계층부터. 그래픽이 없어도 텍스트만 보고 뜻이 다 통해야 함.
2. **장식 제거(decluttering) & 레이아웃 구조(layout structure)** — 중복 카드·그레이·이펙트를 지우고 흰 바탕에서 텍스트와 여백만으로 첫 구도.
3. **최상단 키비주얼 볼륨** — 접속 시 시선을 잡는 빌보드의 시각적 무게(visual weight)를 넓은 여백으로 먼저 확보. 첫 화면부터 바둑판식으로 쪼개지 않아요.
4. **대표 모듈의 디폴트 규격** — 반복되는 대표 부품(상품 카드·영수증 모듈)의 표준 형태를 먼저 확정.
5. **그리드 & 수직 정렬** — 웹 12(또는 16)컬럼, 모든 요소의 좌측 시작선을 일치. 오토레이아웃 마진 통일.
6. **계층·여백 확장** — 타이틀-본문-캡션 위계, 섹션 사이 위 40 / 아래 80~100.
7. **마감** — 1px 선(10~20%), 은은한 그림자, 포인트색 1개.

## 4. 정렬

- **좌측** 기본. 본문·라벨·리스트·상품 정보·카테고리·주문서. 좌측 기준선이 있어야 시선이 안정되게 내려가요.
- **우측** 제한적. 카드에서 좌측 상품명·옵션과 마주 보는 가격·할인율·수량·화살표.
- **중앙** 한정. 히어로 타이틀, 텍스트 적은 단일 비주얼 배너, 팝업·모달 헤더, 로고, 알림 칩. 본문·긴 글에 중앙 정렬은 시선을 지그재그로 만들어요.
- 한 카드·섹션 안에서 정렬을 섞지 않아요.

## 5. 그룹핑(grouping, 근접성 원칙 proximity) — 여백 · 선 · 면의 순서

1순위 **여백 차이**: 연관 요소는 타이트(4·8·12·16), 다른 그룹 사이는 넓게(32~100). **안 여백 < 바깥 여백**을 지켜요. 안이 바깥보다 넓어지면 요소가 퍼져 그룹핑이 깨져요.
2순위 **선**: 여백만으로 불투명한 리스트·아코디언·테이블 경계에 1px 10~20%.
3순위 **면·카드**: 박스 전체가 클릭 타겟일 때만. 면 + 카드 2중 금지, 1개로 모듈 단위로 넘어가게.

그룹핑을 어디서부터 가져갈지가 중요해요. 요소가 따로따로 보이면 안 되고, 이렇게 묶여 보이고 저렇게 묶여 보여야 해요.

**여백은 처음부터 확 벌려 놓고(60 이상) 나중에 줄여요** — 좁게 시작하면 여백 부족이 굳어요.

## 6. 시선 흐름과 정보 순서

- 위 → 아래, 좌 → 우. 지그재그·사선 오버랩은 시선 흐름을 깨는 흔한 실수.
- **배너 정보 4순위**: 1 핵심 혜택(가장 큼) → 2 대상·상품명(중간, 포인트색) → 3 조건·기간(작게, 그레이) → 4 로고(우상단 소형 — 이미 알고 들어온다).
- **상품 카드**: 이미지 → 브랜드 → 상품명 → 가격 → 할인율 → 별점.
- **영수증**: 상품·배송지 → 총 상품금액 → 할인(−) → 최종 결제금액(대형) → 적립(+).

## 7. 웹 ↔ 모바일

- 웹에서 정한 글자 크기·색·기본 패딩을 모바일에도 공통 적용되게 세팅하면 브레이크포인트 작업이 쉬워져요.
- 웹: 2분할(좌 메뉴·필터 + 우 본문) 또는 1 : 0.5 : 0.5. 모바일: 1컬럼 수직 스택, 메뉴는 햄버거·하단 탭바(독바).
- 모바일 첫 화면(375×812): 로그인·주요 CTA 가 **스크롤 없이** 보이게 상단 패딩·높이를 계산.
- 3D·강한 비주얼의 대비가 강할수록 레이아웃을 쪼개지 말고 여백을 넓혀 상쇄.

## 8. 색은 줄이고 레이아웃은 한눈에

- 고채도 주조색·원색·다중 그라디언트를 제거하고 무채색·화이트 바탕으로.
- 1080 세로 한 화면 안에 타이틀·키비주얼·차트가 들어오도록 코너 간 거리를 컴팩트하게.
- 오버랩·두꺼운 선·그레이 박스·그림자를 지우고 은은한 면 분할·그리드 선으로.

## 9. 예외 케이스와 확장성 (시니어가 먼저 보는 것)

- **가변 데이터**: 가격이 천만 단위로, 카테고리가 10글자 이상으로, 모듈이 5~6단으로 늘 때 터지지 않게. 최대 글자 수를 하나 정하고 말줄임을 설계. 5단까지 대응, 6단부터 분기.
- **상태값**: 디폴트·호버·선택·입력 완료를 화면마다 같은 규격으로.
- **320px**: 최소 해상도에서 깨지지 않게.
- **리듬**: 같은 모듈 반복 사이에 강한 면 코너·띠배너 1~2개.
- **시안 방향성**: 색만 바꾼 a-1·a-2 는 방향이 아니에요. 운영 공수·프레임 구조가 다른 A/B/C.

## 11. 컨셉 · 심플 · 따라하기

- **글래스 스타일 따라하기**: 글래스·블러를 4중으로 쌓아 글자·아이콘이 묻힘, 스플래시 딤 60%+. → 이펙트 1개(이너 섀도우 1~2)로도 글래스 느낌은 나요. 딤 낮추고 하단만 그라디언트. 확대해야 예쁜 해외 아이콘은 2배수에서 깨져요 — 2px 정방형 박스 안에서 직접 그려요.
- **컨셉보드 복사**: 최소 크기 미달 글자·버튼·어긋난 마진·상태값 없음. 예쁘다고 무작정 그대로 그리지 않아요. → 가이드 사이즈(본문 14+, 버튼 40~56, 디폴트/완료 분기, 좌측 정렬).
- **컨셉 벤치마킹 3단계**: ① 사용성 먼저, 컨셉은 그 위에 모방 연습 ② 가독성이 주, 컨셉은 부(주객전도 금지) ③ 화면을 찌르는 진한 라인·파란 버튼은 연한 스트로크로, 브랜드색은 호버·활성에만.
- **커머스 벤치마킹 3단계**: ① 아트워크 습관을 버리고 상위 커머스 상세페이지의 썸네일 폭·정보 구도를 스캔 ② 1:1 썸네일과 1~4순위 텍스트 계층 선작업 ③ 가격·배송·혜택·옵션·구매·찜을 상단/우측에 집약.
- **진짜 심플**: 요소를 다 지운 빈껍데기가 아니라, 최대 글자 수·초기화·계층·그리드 같은 실무 구조를 다 갖춘 상태에서 수식만 뺀 것. 미니멀 브랜드 웹을 따라 할 때도 라인·오버랩·어지러운 이미지를 제거해야 완성.
- **호버 오버레이 실수**: 상품 위에 어두운 오버레이 + 아이콘 띄우기 → 상품 4개밖에 못 놓고 마우스가 가면 항상 1개는 가려짐. 가격·찜·장바구니를 카드 아래 밖으로.


## 12. 대시보드·관리자 화면의 추가 규칙

이미지가 없어 기본기 결함이 그대로 드러나는 화면이에요. 위 규칙에 더해:

- **좌측 내비(LNB)는 공중에 띄우지 않아요.** 모듈 카드처럼 떠 있으면 본문과 이질감이 생겨요. 좌측 벽면에 밀착한 2분할 수직 패널(240~250) 하나로.
- **보조 아이콘·위젯의 색면을 제거해요.** 아이콘 뒤 알록달록한 원형 배경, 위젯마다 다른 면색은 전부 연한 무채색으로. 시선은 차트 숫자에 가야 해요.
- **차트는 슬림하게, 강조는 점 하나로.** 막대 16 이하, 선 2px, 최고·최저 지점에만 원형 도트 + 말풍선 칩. 차트 배경 박스는 비워요.
- **웹 콘텐츠 폭은 1200 으로 가둬요.** 화면 끝까지 퍼지면 저해상도에서 가독성이 깨져요. 1200 중앙 컨테이너 안에서 정렬하고, GNB·배경만 풀와이드.
- **영문 폰트는 하나.** 타이틀과 본문에서 영문 패밀리가 다르면 한 서비스로 안 보여요.

## 13. 피드백을 받을 때

- 피드백을 전부 반영하는 게 아니라 **기준에 비춰 거르는** 게 디자이너의 일이에요. 반영할 땐 "이 피드백이 어느 원칙(위계·여백·그룹핑·직관성)을 살리는가"를 한 줄로 적고, 어느 원칙도 안 살리면 반영하지 않아요.
- 여러 사람의 한마디씩을 다 넣은 화면은 반드시 선·박스·프레임이 겹쳐요. 그 화면은 고치지 말고 흰 바탕에서 다시 세워요.

## 14. 플랫폼별 레이아웃 메모

| 스택 | 폭·여백을 정하는 곳 | 놓치기 쉬운 것 |
|---|---|---|
| 웹 (React·Vue·Svelte 등) | 컨테이너 `max-width` + 좌우 `padding-inline`, 간격은 `gap` | 375·390·430·1280 네 폭에서 모두 봐요. `100vh` 대신 `100dvh` (모바일 주소창) |
| React Native · Expo | 화면 루트의 `paddingHorizontal` 하나를 상수로, `useSafeAreaInsets` 로 하단 CTA | 화면마다 여백 상수를 따로 두지 않아요. 터치 확장은 `hitSlop` |
| Lynx | 루트 view 의 padding 과 safe area 변수 | 웹과 RN 관례가 섞이기 쉬워요 — 한 화면 안에서 단위를 하나로 |
| Flutter | `Padding`/`EdgeInsets` 상수, `SafeArea`, `MediaQuery.textScaler` | 큰 글씨 배율에서 고정 높이 위젯이 잘려요 |
