# 리뷰 절차 · 판별 기준 · 용어 · 벤치마킹 · 사용성과 운영

## 1. 화면을 열자마자 보는 것 (1~2초)

1. **시각적 앵커(visual anchor)** — 상단이나 메인 인트로에 시선을 붙잡아 주는 타이틀·메인 비주얼이 있는가.
2. **볼륨과 여백(white space)** — 폰트·부품이 해상도 대비 커서 화면을 막거나 아래로 잘리지 않는가.
3. **방해 요소** — 글래스·짙은 그림자·고채도 과다(oversaturation) 배경이 핵심 상품·이미지를 가리지 않는가.

## 2. 리뷰어가 스스로 던지는 질문

- 시각적 앵커가 되는 타이틀이 있나? 타이틀에 대비(contrast)·강조(emphasis)가 있나?
- 화면에서 무엇이 제일 중요한가? 제일 먼저 보여 줘야 할 것이 무엇인가?
- 모든 걸 다 강조하면 강조된 게 하나라도 있나?
- 카드를 2중 3중 중첩하고(nested containers) 그레이 배경을 깐 이유가 있나?
- 실무·커머스에서 상품이 수천~수만 개일 때 이 구조를 유지보수할 수 있나?
- 사용자가 실제로 클릭하고 스크롤할 때 진심으로 편한가?

## 3. 실제 수정 순서 (디자인 도구에서든 코드에서든)

| 단계 | 하는 일 | 구체 |
|---|---|---|
| 1 장식 제거(decluttering) | 장식 요소 제거 | 중복 카드 frame·그레이 배경·글래스·짙은 섀도우 삭제 → 흰 바탕 |
| 2 레이아웃 구조(layout structure) | 정렬 재배치 | 지그재그·오버랩 해제, 1080 풀배열 또는 좌측 정렬, 1 : 0.5 : 0.5 |
| 3 위계 | 폰트 등급화 | 타이틀 48/64(매거진 160~300), 본문 15~16, 캡션·단위 ≤14 |
| 4 여백 | 8pt 체계 | 요소 16, 섹션 40 / 80~100, 버튼 패딩 12/20 |
| 5 색 | 배경 톤 다운(tone down) + 포인트 1 | 주변은 무채색·그레이로 후퇴시키고 CTA 하나에만 브랜드색 |
| 6 마감 | 부품 디테일 | 버튼 44px·라운드 12, 1px 선 10~20%, 이너 섀도우 1px, 그림자 6~15% |

## 4. 완성도 판별 기준

**완성도가 높은 화면**
- 흰 바탕에서 텍스트와 여백만으로 위계를 세워요.
- 강조할 것이 하나 있고 나머지는 강조를 낮춰요(de-emphasize) — 강약 조절과 절제.
- 주변에 방해 요소 없이 보여 주려는 이미지·상품이 가장 먼저 보여요.
- 레이아웃 구조와 위계가 잡혀 있고 유지보수와 사용성을 고려해요.

**완성도가 낮은 화면**
- 크기가 다 비슷해 위계가 없고(flat hierarchy) 볼륨감이 애매해 어디를 봐야 할지 몰라요.
- 모든 걸 다 강조해서 결국 밸런스가 깨져요.
- 카드 박스를 2중 3중 중첩하고 그레이 배경을 깔아요 — 위계·여백 규칙이 없을 때 나오는 가장 쉬운 연출이에요.
- 이펙트에 치우쳐 실제로 사용하기 어려워요.
- 지그재그로 배치해 시선 흐름을 깨요.
- 색다르게 하려고 오버랩하고 복잡하게 꼬아서 아무도 사용하지 못하게 만들어요.

## 5. 용어

| 용어 | 뜻 |
|---|---|
| 시각적 앵커(visual anchor) / 시각적 무게(visual weight) | 상단·중심에서 시선을 안정적으로 잡아 주는 타이틀·대형 비주얼의 시각적 비중. 앵커가 없으면 화면이 비어 보여요 |
| 대비(contrast) · 강조(emphasis) | 두께(Bold)와 크기 대비로 우선순위를 세우는 것. 강조가 부족하면 얇거나 작아 존재감이 없어요 |
| 강조 낮추기(de-emphasize) | 메인이 돋보이도록 보조 정보의 크기·불투명도·톤을 낮추는 것 |
| 시각적 노이즈(visual noise) / 명도 대비 저하 | 짙은 그림자·중복 그레이 박스·원색 범벅으로 화면이 어둡고 지저분한 상태 |
| 여백 부족 · 밀도 과다(high density) / 빈 공간 과다 | 폰트·부품이 커서 여백이 부족한 상태 / 시각적 앵커가 없어 비어 보이는 상태 |
| 컨테이너 중첩(nested containers) / 카드 중첩 | 여백·폰트로 못 나누고 카드·그레이 박스로 2중 3중 테두리를 두르는 것 |
| 그룹핑(grouping) · 근접성 원칙(proximity) | 연관 요소는 가깝게, 다른 그룹은 멀게 두어 여백만으로 묶는 것. 안 여백 < 바깥 여백 |
| 시각적 충돌(competing emphasis) | 강한 요소 둘 이상(거대 타이틀·강렬한 동영상·원색 칩)이 한 화면에서 서로 튀려고 다투는 상태 |
| 고채도 과다(oversaturation) / 원색 남용 | 절제 없이 고채도 원색을 사방에 도배해 눈이 피로한 상태 |
| 장식 제거(decluttering) | 글래스·그레이 배경·카드·섀도우를 삭제해 흰 바탕으로 되돌리는 작업 |
| 레이아웃 구조(layout structure) | 흰 바탕·폰트 위계·넓은 여백·정렬·그리드로 이루어진 화면의 기초 |
| 배경 톤 다운(tone down) / 배경으로 후퇴 | 떠 보이는 카드·팝업·부품을 흰 바탕이나 무채색 평면에 안착시키고, 주변을 저채도로 낮춰 포인트 하나가 보이게 하는 것 |
| 위계 없음(flat hierarchy) | 크기·굵기 차이가 없어 어디를 먼저 봐야 할지 모르는 상태 |
| 간격 스케일(spacing scale) | 4·8·12·16·20·24·32·40·48·64·80 처럼 정해 둔 간격 값의 집합 |

**핵심 지침**: 디자인을 꾸미거나 이펙트를 더하려 하지 말고, 레이아웃 구조(흰 바탕, 폰트 위계, 넓은 여백)부터 세운 뒤 절제하는 것이 실무 기준이에요.

## 6. 벤치마킹 — 왜 · 무엇을 · 어떻게

레퍼런스 도구(레퍼런스 갤러리 MCP · Figma · 웹 검색)가 있든 없든 원칙은 같아요. 도구가 있으면 같은 업종 화면 3~5개를 찾아 보고, 없으면 사용자가 준 스크린샷이나 이 skill 의 `screens.md` 정보 순서를 기준으로 삼아요 (`capabilities.md` reference 슬롯). **옮기는 건 "왜 그 자리에 두었나" 뿐이에요** — 색·라운드·그림자 같은 겉모습은 옮기지 않아요.

### 왜 하나

- UI/UX 의 목적은 꾸밈이 아니라 **사용성**. 잘 만든 레퍼런스가 문제를 어떻게 풀었는지 보고 내 서비스에 옮기기 위해.
- 기초(흰 바탕·위계·여백)가 없는 상태에서 "색다른 것"(오버랩·지그재그)만 시도하다 사용성을 망치는 실수를 막기 위해.

### 무엇을 참고하나

같은 업종의 상위 서비스 3곳을 직접 눌러 보며 타이틀·가격·필터·버튼이 왜 그 자리에 있는지 이유를 읽어요. 이름을 모으는 게 아니라 구조를 읽는 거예요. 브랜딩 웹은 대형 이미지·타이틀 배치와 좌우 밸런스를, 커머스는 필터 위치와 레이어가 열릴 때의 딤·스크롤 처리를, 요금제는 가격을 타이틀급으로 세우는 방식을 봐요. 무드·스타일용 컨셉보드 모음은 실무 사용성 참고가 아니에요.

### 레퍼런스를 볼 때 뜯어볼 것

1. **직접 눌러 보고 써 보기** — 어디서 스크롤이 멈추고 적용 버튼이 어디 뜨는지 동작 원리.
2. **정보 계층과 수치** — 타이틀·가격·본문 크기 차이를 얼마나 벌렸는지.
3. **스크롤·레이어 구조** — 바텀시트·필터가 박스 안에서 도는지, 전체가 움직이는지, 상단이 요약되는지.
4. **여백·그리드** — 컨테이너 폭(1080 등)과 8pt 배분.

### 베끼기 vs 벤치마킹

- **베끼기(낮은 완성도)**: 화려한 이펙트(글래스·뉴모피즘·카드 겹침·지그재그)를 맥락·사용성·유지보수 고려 없이 겉모습만 복사.
- **벤치마킹(실무 기준)**: "왜 그 자리에 타이틀·가격·필터·버튼을 뒀는지" 이유와 구조를 파악한 뒤 내 서비스 목적에 맞게 변형.
- 벤치마킹은 우리 서비스에 어떻게 적용할지 고민하는 일이에요. 색다르게만 하려고 오버랩하고 꼬아 놓으면 아무도 사용하지 못하는 디자인이 돼요.

### 서비스 종류별

| 종류 | 우선순위 | 따를 것 |
|---|---|---|
| 커머스 | 유지보수·상품 가독성 | 1:1 썸네일 통일, 상단 필터 또는 좌측 필터로 상품과 옵션 동시 노출 |
| 패션·매거진 브랜딩 웹 | 비주얼 퍼포먼스·타이포 파격 | 대형 폰트 120~400, 대형 동영상·이미지 풀배열, 세로 썸네일 허용 |
| 컨셉보드·포트폴리오 | 스타일 표현(JPG 한 장) | 실무 공부엔 사용성이 동반된 앱·웹 UI 를 벤치마킹 |

## 7. 사용성 · 정보 구조 · 운영 관점 지적 12건

시각 꾸밈이 아니라 "쓸 때 편한가 · 무엇이 먼저 보여야 하나 · 운영이 되나"의 지적이에요.

| # | 항목 | 증상 | 근거 | 고침 |
|---|---|---|---|---|
| 1 | 상단 띠배너 닫기 없음 | X 가 없어 계속 차지하고 서브 페이지까지 따라다님 | 못 끄면 콘텐츠·GNB 를 계속 가림 | 우측 X(터치 44px), 닫으면 아래 콘텐츠가 올라옴 |
| 2 | 아코디언 토글 아이콘 이탈 | + 누르면 − 가 우측 끝 등 다른 자리에 뜸 | 같은 자리를 다시 눌러 닫을 것으로 기대 | +/− 같은 자리에서 토글 |
| 3 | 썸네일 비율 혼용 (운영) | 위는 정사각, 아래 코너는 세로 | 수천~수만 상품에서 왜곡·가공 비용 2배, 운영 불가 | 1:1 전면 통일 |
| 4 | 바텀시트 박스 안 갇힌 스크롤 | 작은 박스 안에서만 좁게 스크롤 | 조작 영역이 좁고, 길어지면 레이어 전체가 움직여야 | 스크롤을 밖으로, 상단 핵심 정보는 얇게 요약 고정 |
| 5 | 필터 딤 레이어 스크롤·적용 버튼 없음 | 딤으로 막아 놓고 메인 스크롤 시도, 적용 없음 | 딤이면 내부 독립 스크롤 필수, 선택 후 적용→닫힘→갱신 플로우 | 내부 독립 스크롤 + 하단 고정 '적용하기' |
| 6 | 선택 상태 피드백 결함 | 어떤 옵션이 선택됐는지 구분 안 됨 | 즉각 인지 못 하면 잘못된 조작 반복 | 체크 아이콘 + 대비 강한 색/스트로크 + 볼드 |
| 7 | 요금제 가격 강조 미흡 (IA) | 가격이 구석에 작게, 불필요한 문구가 강조 | 요금제에서 핵심 정보(primary content)는 가격 | 가격을 타이틀급으로, 상위 플랜에 포인트 스트로크 |
| 8 | 터치 영역 미달 | 버튼·아이콘·닫기가 20~30px | 오타율↑, 손가락 접근성 훼손 | 최소 44~48px |
| 9 | CTA 성격 구분 모호 | 카드·필터·버튼이 똑같은 글래스/그레이 | 진입 즉시 CTA 가 보여야 과업 달성 | 주변 이펙트를 제거하고 CTA 만 48px·선명한 채움·라운드 12/원형 |
| 10 | 지그재그 시선 흐름 파괴 | 코너가 좌-우-좌-우 | 단조로움을 피하려다 시선 흐름을 깨는 흔한 실수, 탐색 효율↓ | 좌 텍스트 + 우 이미지 일관 세로 스크롤 |
| 11 | 바텀시트 인디케이터·닫기 없음 | 끌어내리거나 닫을 구조 없음 | 레이어임을 인지시키는 바가 필수 | 4×48 라운드 100% 바 + 바깥 딤 터치로 닫힘 |
| 12 | 메인 기능 위 오버랩 (IA) | 360° 뷰어·배너 위에 배경 카드 | 핵심 정보는 상품 자체 | 카드를 제거하고 360° 아이콘·컬러칩을 상품 아래로 |

### 설계 모드에서 미리 잡는 법

- 화면마다 **핵심 정보 하나**를 명세 첫 줄에 적어요. 요금제면 가격, 상품이면 상품 이미지, 업무 앱이면 다음 행동.
- 레이어(바텀시트·필터·팝업)를 그릴 땐 **스크롤 소유자**(레이어 전체 / 내부 독립 / 메인)와 **닫히는 방법**(적용 버튼 / 바깥 터치 / 드래그)을 같이 적어요. 안 적으면 12번 패턴이 나와요.
- 커머스는 썸네일 비율을 화면이 아니라 **서비스 단위로 하나** 정해요.
- 토글·탭·아코디언은 **상태가 바뀌어도 자리는 그대로**.
