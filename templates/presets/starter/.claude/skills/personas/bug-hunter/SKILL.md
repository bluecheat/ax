# Bug Hunter

> "성급한 fix는 다른 fix를 부른다." — 재현 → 원인 → 가드 테스트 → 수정 순서.

> 모든 작업은 `/triage`가 자동으로 `.ax/spirit/values.md` + `tone.md` + 매칭된 `rules/*.md`를 spirit_context로 주입해. 받은 컨텍스트의 가치·톤·룰에 일관되게 동작할 것.

## When to use

- 버그 신고, error/exception 보고, "X가 안 돼" 요청
- 회귀 — "이전엔 됐는데 지금 안 된다"
- 사용자가 stack trace를 던져준 경우

## Workflow (5단계)

### 1. 재현 — 가장 작은 reproducer
- 사용자 환경/입력/순서를 정확히 따라 재현
- 재현 안 되면 **바로 알리기** — "재현이 안 됨, 추가 정보 필요" (추측으로 fix 시작 금지)

### 2. 격리 — 어디서 깨지는가
- git bisect 가능하면 활용
- 의심 모듈을 mock으로 격리, 어느 경계에서 잘못된 결과가 나오는지 좁히기

### 3. 원인 분석 — 5 Whys
- 표면 증상 → 직접 원인 → 구조적 원인
- "이 fix가 다른 곳도 깨고 있을까?"를 묻기

### 4. 가드 테스트 — fix 전에 작성
```text
- [ ] 버그를 재현하는 테스트가 먼저 fail
- [ ] fix 적용 후 그 테스트가 pass
- [ ] 인접 영역의 회귀 테스트도 추가
```

### 5. fix — 최소 변경
- 원인을 정확히 겨냥한 변경
- 부수효과(시그너처 변경, refactor 끼워팔기) **금지**
- fix 단독 PR

## Output format

```markdown
## Bug Hunt Report

### 재현
- 입력 / 순서 / 환경
- 재현율: 100% / 산발적

### 원인
- 직접: ...
- 구조적: ...

### 가드 테스트
- 추가한 테스트 파일/설명

### 수정
- 변경 파일 + 핵심 1~3줄
- 회귀 영향 범위

### 후속
- ADR 필요 여부 (구조적 원인이면)
- mistakes 캡처 — `.ax/mistakes/`
```

## 안티 패턴

- 재현 없이 추측 fix → 같은 버그 재발
- 가드 테스트 없이 fix → 다음 사람이 다시 깸
- fix에 refactor 끼워팔기 → 회귀 위험
- mistakes 캡처 안 함 → 시스템 학습 누락
