# 삭제 루틴 (ablation) — 룰이 아직 필요한지 재는 법

> 첫날에 깐 룰은 **영구 자산이 아니에요.** 모델 세대가 바뀌면 "없으면 틀리던 것" 의 절반은
> 지시 없이도 맞습니다. 그런데 룰은 스스로 사라지지 않아요 — 아무도 안 지우면 컨텍스트를
> 먹는 부채로 남고, 지시가 늘수록 준수율이 떨어져요.
>
> **주기: 6개월마다, 또는 주 모델 세대가 바뀔 때 (둘 중 먼저).**
> 다음 예정일을 `.ax/docs/STATUS.md` 의 "다음" 에 체크박스로 적어 두세요 —
> 날짜가 어디에도 없으면 이 절차는 영영 안 돌아요.

## 절차

### 1. 끄기

```bash
bash .ax/scripts/bash/zero-ablation.sh --status --json     # 지금 상태
bash .ax/scripts/bash/zero-ablation.sh --off --json        # 전부 끄기 (파일은 보존)
```

`.md` → `.md.ablated` 로 이름만 바꿔요. 주입 훅도 doctor 도 `.md` 만 보기 때문에,
내용을 지우지 않고도 "없는 셈" 이 됩니다.

### 2. 재기 — 실제 작업으로

끈 상태로 **평소 작업 5회 이상**을 돌려요. 인위적인 테스트 말고 진짜 작업이어야 해요.

각 작업이 끝날 때마다 아래 표에 한 줄씩 적어요. **깨진 것만** 적어요.

| 날짜 | 작업 | 무엇이 깨졌나 | 어느 룰이 막았을 것 |
|---|---|---|---|
| | | | |

기준: "이 룰이 있었으면 안 일어났을 일" 만 세요. 그냥 마음에 안 드는 결과는 아니에요.

### 3. 되돌리고 정리

```bash
bash .ax/scripts/bash/zero-ablation.sh --on --json
```

그리고 표를 보고 가릅니다.

- **한 번이라도 걸린 룰** → 유지. 다만 **기계로 옮길 수 있는지** 다시 물어요
  (`.ax/_templates/zero/checks.md` 의 판정 3단계)
- **한 번도 안 걸린 룰** → **지웁니다.** 파일에서 삭제하고, 이 문서에 지운 날짜와 이유를
  한 줄 남겨요. 다시 필요해지면 그때 다시 씁니다 — git 에 남아 있어요
- **애매한 룰** → 다음 회차까지 유지하되 표에 "관찰 중" 으로 표시

### 4. 기록

```
## ablation 기록

- YYYY-MM-DD (모델: <이름>) — 5개 중 2개 삭제(SP-XXX-001·SP-YYY-002: 5회 작업에서 0회 발동),
  1개를 hook 으로 승격(SP-ZZZ-001 → .ax/hooks/pre-bash/...), 2개 유지
```

## 왜 "끄고 재기" 인가

룰을 **읽어 보고** 필요 없다고 판단하는 건 안 돼요. 읽으면 전부 그럴듯해 보여요.
실제로 없이 돌려 봐야 무엇이 깨지는지 알아요 — 그게 유일하게 정직한 신호예요.

같은 이유로 **한 번에 하나씩 끄지 않아요.** 전부 끄고 재야 "합쳐서 얼마나 기여하는가" 가
보입니다. 개별 기여도가 아니라 팩 전체의 값어치를 재는 거예요.

## 주의

- ablation 중에는 **집행 장치(hook·CI·테스트)를 끄지 않아요.** 여기서 끄는 건 산문 룰뿐이에요.
  계약은 애초에 컨텍스트를 안 쓰기 때문에 부채가 아니에요
- 팀이 있으면 ablation 기간을 공지해요. 모르는 사람이 "룰이 사라졌다" 고 놀랍니다
