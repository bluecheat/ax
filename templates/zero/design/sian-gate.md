# 시안 승인 게이트

> 구현 전에 **보고 정하는** 자리를 만들어요. 이 게이트가 없어서 실제로 일어난 일:
> 잘못된 버튼 모양으로 승인이 날 뻔했고, 파운더가 "시안 파이프라인 안 써?" 라고 물어서야
> 절차가 있다는 걸 알았어요 ([SP-PRC-005]). 승인은 말이 아니라 **아티팩트**에 해요.

## 불변 4개

1. **승인 대상은 아티팩트 하나** — 링크 하나, 파일 하나. 채팅에 흩어진 이미지 여러 장은
   승인 대상이 아니에요. 승인 시점의 바이트를 나중에 다시 열 수 있어야 해요
2. **소유자 하나** ([SP-PRC-004]) — 그 아티팩트를 갱신하는 사람·스크립트는 하나예요.
   둘이면 승인된 안이 조용히 덮여요
3. **실기기와 같은 단위로 렌더** — 아래 렌더 체크리스트 참조. 단위가 다르면 승인한 것과
   구현된 것이 다른 물건이에요
4. **승인 후 바이트 대조** — 구현이 끝나면 승인 아티팩트와 실제 화면을 나란히 놓고 봐요.
   "반영했습니다" 는 대조가 아니에요 ([SP-VFY-001])

## 렌더 체크리스트 (시안을 만들 때)

- [ ] **크기 단위가 목표 기기와 같음** — 웹 px 로 그린 모바일 시안은 실기기에서 다른 크기예요.
      목표 기기의 논리 해상도·안전 영역·상태바 높이를 넣고 그려요
- [ ] **글꼴이 실제로 쓸 글꼴** — 대체 글꼴로 그린 시안은 줄바꿈이 달라요
- [ ] **가장 긴 문구로 그림** — 한국어·영어 중 긴 쪽, 그리고 실제 데이터의 최대 길이
- [ ] **상태 전부** — 기본·로딩·비었음·에러·비활성·포커스 ([SP-ENF-003])
- [ ] **두 테마** — 밝게/어둡게를 쓸 거면 둘 다. 나중에 붙이면 색 결정을 다시 해요
- [ ] **대비·터치 타깃 수치를 시안에 표기** — 승인 시점에 숫자로 남겨요
- [ ] **애니메이션은 정지 프레임 2장 이상** (시작·끝) 또는 짧은 캡처

## 승인 기록 형식

시안 아티팩트 옆에 이 표를 둬요.

| 필드 | 값 |
|---|---|
| 아티팩트 | <경로 또는 링크> |
| 소유자 | <이름 — 갱신 권한 하나> |
| 승인자 | <이름> |
| 승인일 | YYYY-MM-DD |
| 승인 범위 | <이 시안이 정하는 것 — 예: 레이아웃·간격. 색은 별도> |
| 승인 안 한 것 | <명시. 나중 "그건 안 정했잖아" 를 막아요> |
| 관련 ADR | <ADR-NNNN> |

## 구현 후 대조

- [ ] 승인 아티팩트와 실제 화면 캡처를 같은 배율로 나란히 봄
- [ ] 어긋난 항목을 목록으로 적음 (0건이면 "0건" 이라고 적음)
- [ ] 어긋남이 의도적이면 그 이유를 시안 아티팩트에 반영 (구현이 정본이 되지 않게)
